# CoReTA 局部贡献协议 v1：实现交接包

日期：2026-10-21。状态：详细设计及独立实现已完成62项离线测试，见[实现入口](../../../engineering/handoff-v1/README.md)。未调用新模型或执行候选程序；手工轨迹和预设响应测试不是能力实验结果。

本包将“通常求解路径＋按需局部处理”具体化。保留任务相关专长利用的主命题；以局部贡献和实际应用为对象，不要求三类固定专家或每次消息都审计。

## 阅读顺序

1. [执行规格与流程图](SPEC.md)：六项决策、状态、调度、预算、失败和实现边界。
2. [完整提示词](PROMPTS.md)：四种调用模板及输入组装要求。
3. [消息结构](message.schema.json)与[原型参数](runtime.defaults.json)：候选格式及运行约束，均尚未接入执行器。
4. [真实公开题面](example.public.json)与[手工逐步轨迹](WALKTHROUGH.md)：正常、缺口、争议和失败分支。
5. [同状态方法动作对照](COMPARISON.md)：实际借鉴、风格适配与差异，允许所有方法成功。

## 本次确定的实现取向

- 首轮三个独立DeepSeek上下文；成员数可配置，规划/应用者按任务位置轮换。
- 四类模型输出：贡献、应用、定向回复、核查；探测是一次定向请求的用途，不增加新角色。
- 正常路径：各成员贡献→应用/整合→原题核查。计划选择和简单自查并入应用调用。
- 每次应用最多提出一项当前重要请求；回复后须实际使用或给出具体不采用理由。
- 贡献原文不可变；新信息追加为新引用，当前应用记录采用/排除的具体部分。不给旧字段赋“已证真”的全局状态。
- 首版没有在线执行、浏览或隐藏评测反馈；Docker评分仍在最终交付后独立进行。工具条件未来单独设计。
