# CoReTA：专长利用的动作级设计稿

日期：2026-10-20。状态：研究设计草案，供审查；没有实现、模型调用或新增实验结果。

本文承接 research/expertise-architecture-20261020/POST_RESEARCH_REVIEW_20261020.md。核心命题保持不变：当成员存在相关专长差异时，怎样可靠利用差异，减少无依据折中和有效知识流失，同时保留纠错与局部组合能力。

## 1. 本次作出的决定

1. 将“有效知识已经出现，但没有正确进入后续求解”作为首个机制设计对象；信息未披露、信息本身错误仍分别处理。
2. A_TEST_HANDOFF：区分性检验交接。保留为比较候选和可借用操作；不以双边预测、外部验证、证书或账本作为单独创新。
3. B_APPLICATION_HANDOFF：接收者应用交接。将此前“专家表达转为接收者盲做任务”具体化为：提供者交付针对当前解法的局部修改，接收者在看不到提供者完整答案的分支中应用，随后审核实际应用及其适用条件。
4. B是本稿展开的候选，不代表已证明优于A，也没有认定新颖性充分。其最接近的强比较是AgentAsk的定向能力澄清及SAT的建设性修复。若二者得到相同信息后已做同样操作，不能靠改名或强制多一步声称独立创新。
5. 固定整合者不是知识权威；提供者/接收者/复核者随局部问题分配，三成员即可承载。

命名对齐：本稿A/B对应主REPORT的两个候选。NEAREST_METHODS.md中的“候选B：依赖图”是另一命名，本文只将其归入来源与版本管理设施，避免混作第四种研究候选。

## 2. 真实依据与诊断边界

### 2.1 公开锚点：NASA讨论中的无依据折中

[Multi-Agent Teams Hold Experts Back，图4，PDF第8页](https://arxiv.org/pdf/2602.01011v4#page=8)的公开片段中，专家就加热设备提出月面光照侧、宇航服温控等任务相关理由，非专家仍建议将其升至第7或第8位，以平衡意见。可以确认：理由已出现，但后续修改没有在片段中给出相应的新任务依据。

本稿把它归为“已有依据与折中提议之间缺少应用说明”的设计动机。不能从该片段推出专家整份排名正确、最佳位置是多少，或断言缺乏理解是唯一原因。完整上下文与逐项反事实后果并未在此重建。附录J.5属于编码提示中的示例，不能冒充独立原始运行。

这决定一个最低要求：提出修改的人须说明它改变哪条任务判断、增加什么依据；“其他人也觉得有道理”不足以支持数值折中。但该要求本身已有建设性辩论近邻，不能单独包装创新。

### 2.2 本项目真实反例：数学140

见 ../../engineering/CONVERGED_FLOW_REPORT_20261020.md。流程已出现正确的系数约束，后续基却与其不一致；检查者仍认可。公开点(1,1)代入所提g1得到3/2，而不是所需的0。

### 2.3 四类失败不能混用

| 可观察状态 | 优先问题 | 本稿应做的动作 |
|---|---|---|
| 相关原始资料没有进入消息 | 披露失败 | 按资料目录索取，或全披露控制；不先强加应用教学 |
| 资料与正确局部规则已可见，但下一步仍误用 | 应用失败 | B：定位接收者具体步骤并试用局部修改 |
| 修改仅因票数或平衡意见，缺少新增依据 | 无依据折中 | 要求给出任务后果与修改理由，保留原分支供比较 |
| 提供者规则或条件本身错误 | 合理纠错需要 | A或其他实证/逻辑检查；不得以保护专家为由阻断 |

“正确”在设计分析中可由我们核对；实际运行时协议看不到这枚真值标签。

## 4. 共同完整案例：信息已公开仍可能用错

以下是**自构设计案例**，其初答与分支行为是人为指定的，不是任何模型或论文的实际输出。不作为正式任务集或效果证据。

### 4.1 任务与完整世界

选择费用最低且误差方差不超过5的测量方案P/Q/R。每个方案取两个测量的等权平均；两个测量都无偏、各自误差方差为9。费用依次为1、2、3。除相关性外不存在其他约束。

实际配置记录：P的两项误差相关系数为1，Q为0，R为1/2。配置记录是输入事实，不是隐藏答案；协议可读取这些记录。题目金标准与“哪个成员正确”的标签不供协议使用。

推导：

    Var((X+Y)/2) = [Var(X)+Var(Y)+2Cov(X,Y)]/4
                  = 4.5(1+rho)

故P/Q/R方差分别为9、4.5、6.75，只有Q可行，最终选择Q。

### 4.2 私有资料与初答

| 成员 | 原始专有资料/本例指定的有效贡献 | 指定的错误整答 |
|---|---|---|
| A0 | 误差传播推导，正确写出含协方差项的公式；没有配置表 | 猜错Q/R对应关系，算成9/6.75/4.5，选R |
| A1 | 带方案标识的真实相关性配置记录 | 忽略相关性，一律用9/2，选最便宜的P |
| A2 | 公共任务和费用；承担本例整合提交 | 无依据地报告方差9/6/4，选R |

三个整答P/R/R都错，但公式与配置记录的并集足以产生Q。不是在三份初始答案中挑一个正确答案。提供配置只建立信息优势，不自动建立一般统计推理专长。

所有方法先得到相同公开池：三份初答、A0的公式与推导、A1的配置原文、公共要求。A0的完整答案R在池中已公开；B的应用分支不再展示它，属于对既有可见信息的主动遮蔽，不得描述为所有条件拥有完全相同的上下文。

### 4.3 同一状态下的逐动作对照

下表是依据原方法操作构造的**机制风格适配**，不是原论文在本例上的运行，更不是复现。VideoHV原任务是视频，不能原样声称适用；若未来实现对照，须冻结真实适配提示和权限。各方法均可以成功，不能预设基线必败。

| 方法 | 输入与执行者 | 接下来明确允许/要求的动作 | 可能成功路径与真实区别 |
|---|---|---|---|
| 普通讨论 | 三人看公开池 | 自由讨论并整合 | 直接组合公式和配置即可选Q；也可能折中保留R，均不能预言 |
| 强制全披露 | 同上，资料已全部披露 | 直接重新求解 | 本状态无新增资料；若选Q，说明无需更复杂交接 |
| SAT式修复/证书审计 | 三人看相同池 | 指出A0配置错、A1公式错，保留正确部分，再综合 | 可以完整获得Q；本稿不主张SAT不能重组 |
| AgentAsk式澄清 | 控制者看A0→A2交接及任务 | 向A0问公式怎样用于本题，或向A1问配置归属 | 问对问题可以取得Q；B更强的要求是接收者先提交应用结果，供反馈针对实际错误，而非仅接收解释 |
| VideoHV式主动取证/工具critic | 同样公开池和工具 | 将P/R可行性转成方差检查，读配置并计算 | 正确计算即可发现Q；无需专长身份判断，可能已足够 |
| A_TEST_HANDOFF | 同池，保存当前两种算法 | A1的独立公式预测P方差4.5；A0公式及真实配置预测9；通过公开关系/推导检查 | 可以排除忽略相关性的规则；通过后仍需将正确公式用于各方案，不能把局部pass当最终答案 |
| B_APPLICATION_HANDOFF | 协调者确定“相关性→方差”交接；A0提供公式，A1提供标识记录，A2执行 | A2在不展示完整答案R/P的分支中填rho、计算三项方差、应用阈值，再按费用选择；第三人检查来源绑定和公式应用 | 若A2报告9/4.5/6.75并选Q，才记录本次应用完成；仅复述公式不算。该路径是预期行为，尚无模型实证 |

本案例证明的是这些操作可以被具体定义，不证明B会比SAT、AgentAsk或直接重算更好。尤其本例极小、全资料已公开，强单体很可能已足够；不能将它直接扩成论文主实验。

### 4.4 B的完整纸面轨迹

1. A2当前工作表将R方差写为4，未连接A0的公式；这是可观察触发，不需要正确性oracle。
2. A0交付局部修改：“用含协方差的式子替换方差计算行；前提是等权、每项方差9；rho必须来自相应方案记录。”不得把“选择R”带入该修改。
3. A1交付原文带标识的P=1、Q=0、R=1/2；它可以同时承认或不承认自身公式错误，不以其自我认错为成功前提。
4. A2在隔离分支读取公共任务、局部修改、配置和需要替换的步骤，独立写出替换后的计算与选择。这里“盲”仅指不展示提供者完整答案和自报权威，不是统计独立，也不防止内容泄漏答案。
5. 纸面理想输出为P=9、Q=4.5、R=6.75，选Q。A1可核配置身份，A0可核公式应用；这两人分别可能偏向自己的贡献，因此并非独立真实性证明。
6. 程序只保存两份原始来源、替换位置、实际新计算和复核理由。确定性算术若启用，所有对照获得同样算术权限；程序不预装本题完整求解器。
7. A2把新工作表写回并重新执行阈值/费用选择。最终提交前需检查最终文本与工作表一致；单独组件正确不计完整成功。

## 5. B的最小架构与职责

### 5.1 四个功能，仍然三个成员

| 功能 | 输入→输出 | 谁做 | 程序能保证什么 |
|---|---|---|---|
| 记录贡献与当前使用位置 | 原始资料/局部规则/当前工作→来源句柄与关联步骤 | 成员声明，程序保留 | 原文、版本、引用存在性；不能保证关联完整或正确 |
| 提供局部应用修改 | 接收者出错/缺失步骤→替换操作、条件、预期改变 | 相关资料/技能持有者 | 限制请求范围；不能证明修改正确 |
| 接收者实际应用 | 最小分支输入→新中间结果、后续选择及理由 | 当前需要使用该知识的成员 | 新上下文中遮蔽提供者完整答案；不能证明没有猜测或潜在共同错误 |
| 审核与合并 | 原状态、新结果、原任务约束→采用/修订/未决及理由 | 第三成员；必要时原来源持有者核对 | 保存前后版本及已声明影响范围；不等于形式化蕴含检查 |

它们是一个交接循环的职责划分，不是四个独立“创新模块”。核心候选是第三行与前后环节形成的闭环：依据接收者实际应用错误调整交付，而不是只看解释是否有说服力。

### 5.2 分工规则

- 协调提交者只按轮换规则任命，首例可以A2；不据此赋予事实权威。
- 提供者按原始资料目录/独立能力校准/当前可见贡献选择。目录只说明访问范围；校准不能使用测试题答案。没有合适提供者时询问或继续独立推理，不自动认定知识缺口已解决。
- 接收者是后续步骤实际依赖该知识的人；不总是固定A0。
- 第三成员审核当前应用。若第三成员也缺乏判定能力，保留模型判断的不确定性，允许A的事实/计算检查，不用“第三人认可”充当真值。
- 角色在下一个子问题可以交换。独立贡献阶段仍保留三份初始解，不以专业头衔代替差异建立。

### 5.3 最小信息结构（概念接口，不冻结JSON schema）

程序维护原文/ID/版本；模型不复制历史记录或维护数组索引。

    Contribution = 局部内容 + 来源句柄 + 适用条件
    UseRequest   = 当前任务/步骤 + 所需贡献句柄 + 待完成操作
    Patch        = 替换哪一步 + 替换操作 + 条件 + 预期任务后果
    Application  = 新中间结果 + 如何影响后续解 + 仍缺什么
    Review       = 当前观察/计算依据 + 采用或修订理由

字段服务具体动作；不加入专长分数、可靠性标签或未经校准的数值置信。出错先修职责/信息视图，不继续叠加枚举和关闭状态。

### 5.4 触发、循环和停止

触发依据：当前步骤缺少参数/操作；当前解与已给条件冲突；提供者指出某步未应用其规则；或最终检查发现公开任务条件不满足。成员提出的关联可能错，触发只启动试用，不代表判其正确。

每次固定一个局部步骤。草案流程：一次交付→一次接收者应用→一次复核；失败时允许一次针对实际结果的修订应用。之后仍不明则停止该局部循环，保留原/新分支及未决原因，回到整体求解；不无限重试直到出现喜欢的结果。数目是让流程可推演的暂定上限，不是经验证最优预算。

采用要求是能陈述原题相关性、适用条件及实际应用结果；其判定仍可能依赖模型。没有可靠判定时，不标“已验证正确”。最终仍输出任务要求的最佳努力答案并评分；未决/少答不自动算收益。

结构化工作表可只写入指定单元并重算显式依赖；自由文本只能记录声明过的依赖并再审查，不能保证自动找到全部受影响结论。分支回退也不代表原答案正确。

## 6. A与B各自的区分案例和反例

### 6.1 A何时可能比只澄清有效

双方对误差相关性的作用持相反规则，却都能解释得流畅。重复澄清不增加判别依据；A要求对同一等权、完全相关情形给预测，得到9与4.5，再直接用Var((X+X)/2)=Var(X)作可复算检查。这改变证据供给，可能打破僵局。

但VideoHV式查证、工具critic或善于提问的AgentAsk同样可做；本稿**没有找到A对这些近邻必然新增的能力**，故A不作主创新。

### 6.2 A可能更差

原任务只要求读取已明确给出的配置值，专家原文已经足够。强制双方先登记预测、寻找额外检验可能引入错误的解释步骤；若没有可取得的独立结果，协议还可能延迟使用有效信息。此时直接引用和应用更合适。

### 6.3 B何时可能比只验证主张有效

接收者已同意A0公式正确，仍在自己的方案表中将Q/R配置抄反。再证明公式不会修复错误。B以接收者的三行实际应用为输出，能暴露来源标识的错配，反馈针对这一行而非要求专家写更长解释。

区别来自可见的接收者应用轨迹和针对其错误的反馈，不来自公式更正确。AgentAsk/SAT若已经要求并利用同样轨迹，就没有此区别；必须未来通过具体适配与消融检验，而非预设其做不到。

### 6.4 B可能更差

- **共同错误：** 将任务改为均方误差限制，且传感器有偏。提供者给方差规则，接收者计算与复核都无误，却忽略偏差平方；“会用”仍错。只有回到原目标检查MSE=Var+bias²才会发现。
- **弱接收者：** 它无法可靠执行有效的局部修改，B可能反复保留旧错误。若专家本来能直接给正确结果，额外转交可能使表现下降。
- **局部不可分：** 修改一个引理改变整个证明假设，不能用局部表格假定影响封闭。需要扩展审查范围，可能退化为重做整题。
- **泄漏/顺从：** 修改中暗含“选择Q”，接收者可抄答案而不理解；即使完整答对也不能据此称教学或应用能力提升。

## 7. 六类边界逐项推演

| 情形 | 机制应执行 | 不能据此宣布 |
|---|---|---|
| 正确专家少数、两人无依据反对 | 提出实际使用任务；修改者须连接新依据与后果 | 少数必对；禁止专家受到反驳 |
| 专家局部规则对、完整答错 | 交付局部操作，隔离其完整答案；参数来自相应原始记录 | 原专家整份解获得权威 |
| 全员整答错、不同局部有用 | 重组规则与参数，允许产生初始候选之外的新解 | 新解一定正确，或已有实证恢复 |
| 全员同意同一错误 | 最终检查仍回到公开任务目标；有冲突才启动局部修订 | 共识是充分的停止条件 |
| 接收者不会查 | 尝试更小操作或可用执行通道；保留未决与交付结果 | 接收者不会就说明专家错 |
| 来源冲突/任务含糊 | 展示冲突，查版本或额外信息；条件化作答 | 通过更多讨论自动消除真实矛盾 |

## 8. 新颖性审查：本稿找到什么、还没有找到什么

已经形成明确的行为对象：在“知识已出现却没有被实际用好”的状态下，改变下一轮输入，使接收者提交局部应用而非观点；反馈依其实际操作，接入依据和接入完整答案分开。

这使设计可实施、可反驳，但**尚不足以声称明显创新**。最强质疑是：这只是AgentAsk式能力澄清加SAT式局部修复，或已有机器教学/软件补丁流程的适配。严格盲做本身也可能仅改变信息量与答案锚定。无相关性验证信号时，B仍可能只是另一种自纠错提示。

可能产生实质差异的可检验假设：在有效依据已经可见、接收者仍有应用错误的子集上，“按实际应用反馈”的交接比“按解释质量反馈”更能减少有效知识流失；且不同比例增加错误依据的采纳。两者须使用相同候选、资料与执行权限，并另外分离额外推理和上下文遮蔽的影响。

这里没有需要训练的新router，没有关于自动识别真专家或可靠验证的黑箱假设。若只有更多算术或更强判定器带来改善，应按这些原因解释。

## 9. 后续设计顺序及退出条件

请求级对照已随本稿完成，见 HANDOFF_REQUEST_EXAMPLES_20261020.md。它把B与AgentAsk能力澄清、SAT建设性修复各自写成实际请求/响应样例，保持同一任务、成员资料和检查权限。对照显示：强AgentAsk同样可要求接收者提交实际应用；SAT同样可保留规则与参数并重组。B尚未显示足够独立的新能力，不能据此宣布创新通过。

因此不将A/B作为已确定主方法冻结实现，目前不恢复MuSiQue批量计划或旧付费试跑。B可以保留为应用交接的比较版本，不能直接取得主创新地位。接下来的研究决策只聚焦“接收者不懂且提供者也可能错时，何时辅助应用、何时质疑原知识”的可观察控制依据；不能继续靠字段和模块数量支撑新意。

未来验证需分开：披露成功、资料提取正确、接收者实际应用正确、正确贡献保留、错误贡献接入、最终完整任务表现，以及全员整答错子集的恢复。更好的过程可解释性不代替最终结果。
