## 实际控制差异

1. Q由程序挂到具体U；指定旧版本target的请求会映射到本次新版本，无需模型预知新ID。
2. 回复只生成新C，不修改原U的missing。接受回复需更新其原应用并绑定回复；拒绝或退休也有明确记录。
3. APPLY先在注册表副本检查，再提交。结构错误恢复不会留下半个U更新。
4. 替换/退休U使显式后继stale，保留原C。最终核查前优先调度相关应用更新；剩余预算不足或未取得进展则保留未决。
5. 候选不能静默丢掉原应用关联；依据变更即使保留答案文本，也生成新W，旧核查不自动覆盖新依据。
6. 候选及其登记依赖未完成时，不能获得reviewed_no_defect状态。

每次至多更新一个U，至多一个显式missing活动交接。没有缺项时仍可直接求解，不强制发请求。上游状态传播只覆盖显式bindings。
