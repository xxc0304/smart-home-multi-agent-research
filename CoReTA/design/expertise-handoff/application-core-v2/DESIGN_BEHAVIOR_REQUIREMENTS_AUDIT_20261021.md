## 结论

同时存在表达遗漏、已有职责未有效执行、以及设计本就不提供语义保证三种情况。不能统称为程序没按架构运行，也不能再笼统增加“认真检查”。目前不足以确定初始错误由结构要求导致。

## 有效提示核实

源码：`application_v2/prompts.py`中APPLY分支直接返回COMMON+自定义APPLY+packet，未经过`HandoffPrompts.render("APPLY", ...)`。因此旧设计文件中存在要求，不代表v2模型已收到。

已核对真实`requests.jsonl`：CoReTA逻辑调用5的instructions没有“Preserve supported relations”或“A source can contain useful and mistaken parts”，但包含“Neither member identity nor source ownership proves a comparison”。调用8 REVIEW确实包含“Your own earlier contribution is not authoritative”以及“Check the concrete use, input binding and result”。这不是只凭设计文档的推断。

## 对后续修改的判断

1. **引用容量：明确应修的工程项。** 当前先登记，不在本轮实施。
2. **有效知识保留措辞：有依据提出提示一致性修复。** 应恢复设计语义并控制篇幅；不能把恢复文字当作新机制或承诺修复本次结果。本轮未改。
3. **内容纠错：不宜马上加字段、角色或重复要求。** 核对具体结果和不盲信自身贡献已写入提示却失败。还需隔离初始生成与后续协调的影响。
4. **停止规则：暂不修改。** 本次正确保留未决，预算停止本身不是实现错误。
