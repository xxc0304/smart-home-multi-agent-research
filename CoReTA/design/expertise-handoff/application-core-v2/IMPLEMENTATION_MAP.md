## 1. 落地顺序

### 先实现一条完整接续链

明确的当前使用位置→必要缺项→Q绑定U→相关成员交付C→接收者对原U重新应用→得到新U与完整候选。先实现这一主干，不同时扩建多任务平台、工具系统或复杂图检索。

### 再补同一主干的失败与更新行为

无法帮助、部分解决、拒绝建议、已有关系保留、显式后继stale与重新应用、预算耗尽后如实交付。原语义失败不改记格式失败。

这些功能必须接入实际调度；只写字段或本地记录类不能算完成核心重构。首版开发阶段不与已经完成的v1结果混用。

## 3. 验收需要看什么

本文件定义未来验收，不代表已运行或要求本轮添加测试。

| 情形 | 程序应保证的可观察行为 | 不能因此声称 |
|---|---|---|
| 有真实必要缺项 | Q与当前U关联，等待/暂定状态保留 | 已找出全部隐含缺项 |
| 收到回复 | 记录新C，不自动把U改为完成 | 回复是真实且有用的 |
| 接受回复 | 原步骤更新、引用与具体结果可追踪 | “使用过”就代表正确应用 |
| 只部分解决 | missing与最终未决保留 | 所有未决均已准确登记 |
| 回复无关/错误 | 允许拒绝，不为显示协作强制改答案 | 拒绝本身正确 |
| 条件变动 | 修改具体应用，原C关系保留，显式后继stale | 来源仍真或自由文本依赖图完备 |
| 推导被推翻 | 可以修订或退休应用，不以无完整替代而拒绝反例 | 新路径已经正确 |
| 资料已足够 | 可无请求直接完成 | 无请求说明架构没工作或全题无缺口 |
| 无法判别新旧排序偏好 | 保留未决，不把另一人的赞同当证明 | 程序能自动裁定这种偏好 |

## 4. 用已有真实轨迹核对适用性

以下仅解释设计边界，不是让旧Agent演出新成功过程。

- 集中C4已有完整正确候选：并不存在一定要找别人补齐的事实。新规格不能凭它已知正确而强制采用，也不能靠强制Q保证成功。该失效属于采用判断，仍需保留在评估中。
- 分散V1声称没有星图材料：现有C7指向S05，相关资料由A3持有。若接收者把“星图资料究竟支持什么”登记为当前比较步骤的关键缺项，才有具体核实对象；A3可交付实际材料含义，而不是再投一票。材料仍不必然决定星图对食物的精确次序。
- 集中V1提出奶粉高于推进用途物品：现有用途材料本身没有唯一比较规则。如果不能说明哪项可获得检查会区分新旧排序，就不应制造请求；最佳努力与未决仍是合法结局，新对象不会凭空产生正确比较。

据此，v2不能把“有求助”“U从waiting变成applied_declared”作为机制成功。要核对它是否确实增加可使用的依据/操作、接收者是否实际应用，以及最终表现是否改善。任务适配应选具有可观察交接的真实问题；改变任务也不能替代这些实现要求。
