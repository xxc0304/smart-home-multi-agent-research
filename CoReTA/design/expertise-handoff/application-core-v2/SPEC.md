## 1. 此次重构的目标

原核心是：成员提供有用的局部知识，接收者在实际使用时暴露缺项或错误，相关成员补充可使用的内容，接收者重新应用，保留未受影响的知识。

当前实现中，applications只是refs+result的文字说明，不能稳定区分“引用了贡献”“正在等待其必要输入”“回复已收到”“原应用已更新”。本候选补的是这条执行链，不增加固定讨论轮次，不把零求助视为协议失败，不要求所有贡献都必须被应用。

第一版只跟踪涉及跨成员交接或具体争议的一项关键应用及其显式后继，不将整题每个思维步骤登记成图。

## 2. 增加的唯一核心对象：具体应用U

保留C/W/Q/V；新增U1、U2…表示一次具体知识使用，U与成员A1等身份分离。程序分配ID，模型只引用当前可见已有ID。C保存知识原文，U保存这份知识在当前任务中的使用结果，W仍为完整交付候选。

模型每次最多提出一条需要跟踪的应用更新，内容是：

| 字段 | 类型及作用 |
|---|---|
| target | 已有U引用或null；null表示新应用，已有U表示修订同一使用位置 |
| task_step | 正在完成的具体计算、推导、记录绑定或决策；不是“解决整题” |
| bindings | ref+use列表；说明实际使用哪个可见C/S/T/U及其输入、关系或操作用途 |
| result | 具体中间结果/操作结果/局部决策文本，或null；只写“已采用”不构成语义成功 |
| missing | 一项影响本步骤的必要待补内容，或null；普通宽泛不确定性留在unresolved，不自动激活求助 |

target、binding refs的合法性可以程序检查；task_step是否具体、use是否忠实、缺项是否必要、结果是否正确仍是模型判断，离线内容核验必须保留。

实现补充：bindings也可引用可见W/Q/V表达对话上下文；程序依赖传播只跟踪直接列在bindings中的U，不从C/W/Q/V内容自动推断间接U依赖。需要跟踪的应用输入应直接列U。

原贡献C的conditions/needs仍可以存在，不将所有自报needs提升为强制任务。只有接收者在具体使用步骤中主动确认相关性后，才登记到U.missing。

## 3. 只改一处模型接口，复用其他调用

候选APPLY保留完整artifact、excluded、unresolved与request；原applications字段改为零或一条上述应用更新。新增artifact_uses，列出候选实际依赖的当前U引用。若本次刚建立U，程序将其关联到本次候选，模型不提前编造新ID；其余依赖只能引用先前已存在的U。

再新增retire_applications：已有U引用+reason列表，仅用于明确放弃应用路径；程序不从excluded的自由文本猜测是否退休。excluded仍可表达不采用某条C或某条核查的具体部分，二者不混同。运行时对数组数量、可见枚举与预算设上限，首版每次最多退休一项跟踪应用；其显式后继由程序处理。

单次APPLY的字段清单因而是artifact、applications（0或1）、artifact_uses、retire_applications、excluded、unresolved、request。绑定项为ref+use，退休项为ref+reason；所有ID由当前引用枚举约束。这里给出接口字段，不声称已形成或验证服务端JSON schema。

CONTRIBUTE与REPLY继续使用现有Item，不要求新角色专用结构。REVIEW仍可指出事实/关系/应用问题；动态Ref枚举增加可见U，允许精确指向应用位置，而不只指向整个W。

request沿用ask/check/probe、recipient、target_refs、question、impact。Q记录由程序补入application_ref：如本次新建U则关联新U，否则关联指定的现有活动U。第一版一次只有一个正在等待交接的U，不增加模型生成的请求ID或多个并发计划。

若request是对任务本身的普通澄清，也必须说明它影响哪项具体使用；本轮不设计与应用无关的新规划接口。完整候选可不变，可为null；模型没有义务为了表明处理了意见而改答案。

## 4. 程序管理的状态与事件

### 4.1 U状态不是正确性标签

| 状态 | 程序依据 | 含义 |
|---|---|---|
| waiting | missing非空且result为空 | 一项必要内容尚未取得，不能标为已完成应用 |
| provisional | result非空且missing非空 | 已有暂定结果，仍依赖未解决内容 |
| applied_declared | result非空且missing为空 | 模型已提交应用结果；不意味着外部验证正确 |
| stale | 其显式依赖U被替换 | 原结果需要重查/更新，不能继续当作当前已支持结果 |
| superseded | 同一使用位置已有替代U | 保留原记录，不再作为该位置当前版本 |
| retired | 模型明确放弃该使用路径并给理由 | 不再使用该应用；原始C不被删除或判错 |

result与missing同时为空不形成有效U；可不提出应用更新，继续普通求解或明确交付未决。

### 4.2 回复收到与缺项解决分开

1. driver登记U及必要missing，提出有任务后果的请求。
2. 程序将Q关联到U并路由。权限不相符的成员可正常说明不能帮助，不转成格式错误。
3. REPLY生成新C，程序只标记Q已回复，U原missing不会自动清空。
4. 下一次APPLY必须对同一U进行处理：
   - 接受回复：新U的bindings使用相应回复C，给出重新应用结果，并说明missing如何处理；
   - 部分接受：保留仍缺内容，状态仍waiting/provisional；
   - 回复无用/错误：在excluded中明确部分与理由，U保持待补或改派；
   - 放弃该路径：明确退休U并说明新路径，不把原C整体删除。
5. 单纯把回复引用写进任意applications不再算目标U已处理；必须关联原使用位置或明确退休它。

明确退休原请求U本身即可处理该交接，不要求同时把回复C判错。对同一C部分采用、部分排除时，仍须遵守原应用目标约束。核查若明确指向唯一当前U，接受V时同样必须更新或退休该U；拒绝V可保留原U。指向整体W或多个U时仍由模型定位。

若明确拒绝回复C且保持原U待补，允许只有excluded处理记录、不生成新的U；程序通过pending Q中的application_ref知道拒绝作用于哪个使用位置。仅在同一位置有实际应用更新时才生成新版本，不能因“收到无法帮助”便使所有后继失效。

清空missing需要对应的回复、可见资料、具体推导/重算结果或“该前提对当前步骤并不必要”的理由。这里的充分性仍由模型判断；程序不能认证自由文本解释是真的。现有知识重新推导也可解决问题，不要求凭空增加新资料。

### 4.3 修订与显式依赖更新

更新U产生新版本，旧U标superseded，不覆盖。只对声明依赖旧U的其他U做stale传播，W若引用这些U也标记待更新。不得因一项应用错误，将它引用的全部C一起判错。

新应用不能以已过期U为当前依据；修订U时，也不能把将随之失效的后继当作新版本的支持。历史U仍可作为比较对象显示，但不能同时充当当前有效输入。结构校验拒绝自依赖、未来ID和这种显式无效绑定，不从自然语言自动发现隐含循环。

后继重新应用时须绑定当前版本，而非把旧结果无解释地继续算作有效依据。每次最多更新一个跟踪U，避免模型提前引用同响应中新ID。只有交接或争议相关的关键步骤登记U，普通自主推理无需逐句登记。

这是对显式依赖的管理，不是自动语义依赖图。遗漏的依赖仍可能存在，旧U之外的实际错误仍需原题核查。若替换后连带步骤在预算内无法更新，结果保留未决，不静默称为完成。

## 5. 下一动作由什么决定

1. U已具备必要输入/操作：直接应用；不得为了显示协作制造请求。
2. U缺少可获得的资料或可执行的局部检查：发一次有对象、交付和后果的ask/check；按目录或已有贡献选择成员，不按头衔判真。
3. 仅怀疑隐含前提，且有不改变题面事实的合法对比：可用原probe；无法构造则不编造分支。
4. 没有可以判别的检查：保留未决和最佳努力候选。有人再次赞成不是新增支持。
5. 对整体候选的建议若将改变具体应用：定位到U，再按同一规则处理；不能仅因reviewer提出意见便默认替代成立。

模型仍负责发现缺口。程序不能保证所有真实缺项都会登记，不能用“没有活动U”推断团队没有隐含错误。

## 6. 最终交付与不允许的捷径

保留现有完整排序数组和确定性渲染；不借本候选修改NASA评分或硬编码物品次序。

W所声明使用的U有waiting/provisional/stale时，最终只能为最佳努力/未决，不能标reviewed_no_defect或称其全部应用已完成。仍然允许交付完整候选，不因缺少完备证明而无限停机。

模型不得通过省略artifact_uses静默删除仍活动且与当前解关联的U；改变关联需明确退休/排除及理由。程序检查显式对象的状态一致性，但不能检测所有隐藏推理依赖或确认“已不需要”的理由属实。

原来源记录C保持不可变不等于强制采用C；合法依赖链不等于正确答案；新U不等于有实质改善；核查认可不等于外部证明。所有结果继续离线评分，不回传金标准。

## 7. 复杂度和预算

成员数按N处理，首版仍可3个独立DeepSeek上下文。继续CONTRIBUTE/APPLY/REPLY/REVIEW四类调用，driver按原序号选择，不新增专职规划或裁判。

单显式缺项上限按所有未退役/未替换的U统计；仅从候选excluded一个仍有missing的U不会释放名额，需要解决或退役该路径。

完整任务沿用最多3次定向干预、2次最终核查、20次含恢复尝试。没有争议/缺项时无需请求，也不强迫所有C建立U。U跟踪可能增加更新调用；只记录关键交接，预算不足就明确未决，不能宣称新增状态管理无成本或必有净收益。

## 8. 本规格仍需承认的能力风险

- 模型可能漏登记缺口、把错误内容写成事实、给出不忠实的binding、清空未解决missing或错误退休路径。结构约束不能消除这些语义失败。
- 新对象如果只使输出更长、没有影响下一动作及实际使用，重构就没有兑现目标，不能以字段填写率当成功。
- 本次NASA用途事实不能唯一推出精确全序；该任务没有因此获得更好的判别规则，不能承诺本重构会使其正确。
- 本候选不直接解决普通讨论为何本次成功，也不证明其反复参与机制多余。原完整讨论基线仍需保留。

因此此处先固定可实现差异：目标应用与请求关联、回复不自动解决缺项、版本变动使显式后继失效、候选不能静默越过已登记未决。内容正确性和整体收益另行测量。
