# 局部判断候选的分阶段验证计划

状态：计划，未冻结数据、请求预算及manifest，不可联网执行。旧70次授权已用完。

## 1. 先检验什么

先检验H1：自主提出局部问题再求解，是否比同预算的普通两次评议形成更正确且有用的局部结果。先不以完整团队准确率为主指标，不以人工给定正确局部问题检验自主能力，不同时引入新整合流程。

011/023仅用于规格和接口开发。正式样本尚未选择；需覆盖不同关系而非只围绕道路/场馆挑题，也保留无效贡献和合理不改。不得按新方法输出挑出有利样本。任务是否反映局部能力优势需有独立校准证据，未校准时限定为信息不对称诊断。

## 2. H1的两组对照

| 阶段 | 普通两次评议 | 自主局部问题后求解 |
|---|---|---|
| 第一次 | 任务、自己原件、公共资料、同一W0；给普通贡献 | 相同资料；自主选问题与定位，不交完整改答 |
| 第二次 | 新请求，任务、自己原件、公共资料及第一次贡献；进一步形成局部结果 | 新请求，相同原件、公共资料及自己提出的问题；完成局部结果 |
| W0曝光 | 第一次可见；第二次不直接附W0或旧选项 | 相同 |
| 最终输出接口 | 结论、证据、范围、缺条件、pass理由 | 相同 |

控制成员、资料权限、独立调用数上限和输出上限；记录真实tokens及延迟，不能称严格等实际算力。方法第二次不携带选题理由中的预判答案。普通组自己的贡献可能包含旧判断，方法的问题也可能含偏向；这属于交付表示的干预结果，不据此单独声称消除锚定。

普通组允许自己提出问题、计算、具体修订或不改，不能人为禁止有效策略以拉开差距。两组同一pass规则；需报告pass后的实际调用差别。

这里检验的是自主选题与再求解的组合，不是纯粹question字段的收益。若只有人工指定问题才能改善，应转为辅助诊断结论，不宣称已实现自主机制。

## 3. H1的评分与决策

分别记录：

1. 问题/贡献是否与任务相关，是否有原件或可复查能力依据；遗漏只在预先标注的审查范围内统计，不声称列尽所有可能贡献。
2. 局部结论是否受证据支持，是否保留对象、时间、条件与不确定性；正确部分与错误扩张分开。
3. 对任务有何实际作用，例如撤销不成立的排除、补足必要关系、提供有效反例；不要求推荐最终选项。
4. 原件误读、无依据推断、无效pass与额外成本。

评判员应看任务和评判所需原件，不看方法标签；开发中的同一助手分析不冒充独立盲标。不同输出涉及不同局部问题，不能只数被提出问题中的正确率；应报告每个尝试交付有效贡献的比例及遗漏/覆盖，避免挑容易问题。

若没有可重复的有效贡献增量、错误扩张抵消收益或普通组同样好，则停止该候选，不用增加整合层挽救。少量样本仅支持筛查，不能用一个配对优势称稳定改善。具体题数、重复数和判定阈值须在选择正式样本后、运行前冻结；当前没有编造功效或运行次数。

## 4. 只有H1有收益才检验H2

冻结同一批自然产生的局部贡献（包括好、坏及有条件结果），两组使用相同贡献、原文和权限：

- 强基线：普通处理贡献后再求解，给相同调用/输出预算，并允许纠错。
- 候选：先逐项处理局部结果、物化处理后的工作依据，再在新请求中生成答案。

两组均匹配旧稿可见性，均保留原始引文；不能只给候选组原文或去掉其错误旧稿。若添加IMP或Re-Ex对照，按真实机制与预算公开实现差别，不把简化版冒充完整复现。

主结果是最终质量及错误介入损害；过程结果区分正确局部结论是否形成、是否被正确处理、是否真正影响受影响的步骤，以及更新是否同步到最后答案。引用、use标记、改选率均不代替语义效果。

H2若无收益，报告局部能力改善未转为团队收益，不再把两者合称架构成功。完整自然协作、跨任务和不同模型是更后阶段，本计划不授权自动进入。
