# CoReTA：围绕共同解答发现并应用成员知识（设计草案 r0）

日期：2026-10-22。状态：待独立设计审查；尚未实现或验证。

## 1. 不变的问题锚点

- 核心问题：怎样让多 Agent 团队更好地利用成员专长，使不同成员的知识共同提高解题能力。
- 必须面对的瓶颈：使用者可能不知道自己缺什么；提供者即使持有相关知识，也可能发现不了贡献机会，或无法使正确知识在实际解答中得到正确应用。
- 研究范围：探索围绕中间解答的主动贡献与实际应用反馈，是否改善上述知识利用过程。允许完整解答、局部知识、反例和无法判断；不预设成员意见一定正确。
- 约束：优先沿用现有 DeepSeek 接口与权限隔离；成员数可变，三个成员只是最小开发配置；设计阶段不调用解题模型、不运行实验、不改旧运行器。
- 成功条件：在真实存在信息或能力差异的任务上，与获得相同资料和相近计算机会的普通讨论等强对照相比，改善最终质量，并能把改善关联到被发现且正确应用的成员知识；同时报告错误介入的损害和不生效的条件。
- 非目标：不要求所有题目或所有轮次单调改善；不以角色名称证明专长，不把引用、认可或一致当作正确，不要求全部基础思想前所未有。

## 2. 研究判断与已有证据

主线保持“利用专长”。候选解释是：当前解答暴露具体推理位置，使持有者有机会识别自己能贡献什么；实际试用暴露条件和结果，使双方有机会发现误用。两者均是假设，不是现有结果。

旧版不是完全没有协作：请求获得了事实，检查也曾推动局部改善；但正确分值与错误排序可以并存，检查者还会重复同一矛盾。现有受控错误输入两对中，两法均未完全修好，不能归因于 CoReTA 独有的失败；其他端到端案例确有普通讨论更好。旧版已明文要求检查实际结果，缺口不能只靠补一句提示解释。

证据索引：`../../../REVIEW_MISS_DIAGNOSIS_20261021.md`、`../../../ARCHITECTURE_AND_EXPERIMENT_REVIEW_20261021.md`、`../../sbp-diagnostic-v1/CONTROLLED_COORDINATION_PARTIAL_20261021.md`。这些是开发诊断，不是方法优劣的总体估计。

## 3. 从黑板和中间解答借鉴什么

### 3.1 黑板的可复用部分

[Salemi 等的黑板论文 §3](https://arxiv.org/html/2510.01285v2)：主成员广播请求，熟悉各自文件分区的助手自行决定响应；响应板与请求板分开，助手之间看不到当轮回复，主成员执行分析并观察结果。

直接借鉴三点：知识持有者自选响应；同一快照下独立提交；以真实任务产物和执行反馈承接交流。它解决了部分“找谁帮助”的问题，但仍以主成员提出需求为主要触发方式。

本方案增加的候选交互是：没有请求也展示正在形成的解答，成员据此提出具体贡献；接收者把知识用于实际产物，再把使用过程和结果交回提供者检查。只是增加共享文档或给黑板换名，不构成贡献。

### 3.2 中间解答是什么

它是任务原生的工作对象：代码及相关运行输出、数学解答中的式子与推导、问答中的证据与当前结论、决策中的事实表与候选方案。可以完整，也可以未完成。它不等于聊天历史，不要求公布隐藏思维链，不要求先转为庞大的知识图谱。

现有 v2 的 U 已保存应用文字，因此“第一次共享中间结果”不是我们的差异。需要改变的是：成员能在需求尚未被表述时围绕实际工作主动介入，并通过试用后的具体反馈继续纠正应用。

### 3.3 来源边界

[LMAD §3](https://arxiv.org/html/2608.01463v1) 已有局部推理定位和修订，本方案不把局部修订本身称为新；它的启动依赖答案分歧，而我们拟检验知识持有者能否在无显式请求、甚至答案暂时一致时发现帮助机会。两者都可能漏掉共同错误。

[TeamSTEPPS](https://www.ahrq.gov/sites/default/files/wysiwyg/teamstepps-program/teamstepps-pocket-guide.pdf) 的 check-back 启发我们核对“实际怎样使用”，不把复述和认可当真值检验。[Carlile 的边界对象研究](https://people.bu.edu/carlile/docs/Pragmatic%20View%20of%20Knowledge%20(Carlile).pdf) 启发共同工作对象如何使不同知识被具体关联到任务。它们均不证明 LLM 会因此改善。

## 4. 只保留三个功能组件

1. **共同解答板**：存任务原生当前产物、支持材料与版本；版本由程序管理。
2. **主动贡献入口**：成员看到同一快照与自己的资料，选择提供帮助或跳过；不以整合者先判断“有缺口”为门槛。
3. **试用与反馈闭环**：在副本中实际使用贡献，展示改动和后果，提供者检查适用性，另一成员检查后果，编辑者选择保留哪个现成版本。

这些是逻辑职责，不新增三个专职 Agent。模型能否识别关联、正确应用与核查仍是研究问题。程序只保障版本、权限、定位与调度。

## 5. 成员、权限和初始化

N 可配置；开发首例可用三人，已有四成员任务保持四人。N=2 时提供者兼查后果，不能称为独立复核；N=1 是单成员消融。

资料或工具权限形成信息差异，不把提供者、编辑者、检查者等同领域专家。成员私有资料不自动向全队公开；贡献可带任务允许公开的摘录，原件仍受权限控制。资料优势需用独立作答校准，不能由分配方式直接认定。

所有成员先按通常解题方式独立给出尽力解答，可以包含局部成果；不强迫先生成 C/U 贡献表。模型仅输出普通解答与任务所需交付物，程序再给可定位段落/行范围加标识，不另用模型重写解答。

编辑者以 task_ordinal % N 预先平衡指定，在本次任务内保持不变；W0 使用其初稿。选择不依赖金标准、事后正确性或“已知专家”。其他初稿保留在审计记录中，不自动全部灌入 W0；普通讨论基线也做相同独立初答，但按其原生方式交流。固定编辑者是简化假设，可能形成瓶颈，要单独报告，不宣称已解决权威问题。

## 6. 最小消息与程序状态

采用短文本字段，固定枚举只控制动作；不要求模型维护依赖图、专家分数、未来引用编号或多层 JSON。

| 对象 | 最小内容 | 谁维护 |
|---|---|---|
| Work | version；任务产物 artifact；简短依据/目前未完成处 notes | 程序分配版本，成员写原生内容 |
| Offer | target；knowledge；support；proposed_use | 成员，允许 pass |
| Trial | base_version；实际新 artifact；use_record | 编辑者；程序记录 diff 与来源 |
| Check | observation；finding；scope | 提供者/另一成员 |
| Decision | keep_old / keep_trial；基于观察的理由 | 编辑者；程序切换版本指针 |

Offer 的 target 可为现有段落/行或 whole_goal。不能精确定位的约束或替代方案仍可提出；可靠反例不必给出完整修复。support 可为可见资料引用或明确标为推导的依据，禁止把模型自称“独立核算”当工具证据。proposed_use 可要求尝试某操作/反例/澄清，不必完整替代答案。

use_record 只解释此次怎样使用：适用对象和条件、实际局部结果、影响到的结论。程序另外保存真实前后产物；不以 use_record 自述成功判成功。Check.finding 为 issue / no_issue_found / unable，不存在 verified_true。

状态只需 task、权限、当前版本、历史版本、当前一条 offer、trial、两份 check、预算和停止原因。无全局知识真值库、自动语义依赖网或声誉学习。

## 7. 一次协作周期如何执行

### A. 看当前解答，独立决定能否帮助

全部 N-1 个非编辑者读取同一冻结 Wt、任务、自己的私有资料及上一周期未解决观察，各交 0 或 1 条 offer。当轮看不到彼此的新 offer，避免先跟随第一条意见；pass 合法，不强制挑错。

不问“你同不同意”，而问“你掌握的材料是否能改变某一步的适用性、操作或结论；如能，指向该处并提供依据”。这仍可能判断失败，不能因措辞就视为已实现能力。

### B. 有限试用，不先要求编辑者知道贡献正确

有多条 offer 时按预置轮转顺序选一个提供者，非按自报信心排名。其余 offer 存档，下周期成员可结合新快照重新提交，旧定位不静默沿用。首版不引入有用性预测器。

编辑者在 Wt 副本中尝试该贡献，生成 trial 的真实产物和 use_record；允许给出无法应用的具体原因。主版本仍保留。试用不等于采纳，不能为了互动强制修改。错误或不相关的贡献可能浪费这轮预算，这是明确风险。

### C. 反馈给知识持有者，分开观察应用和后果

提供者获得原 offer、原任务、相关前后产物、实际 use_record 及自己原本有权看到的材料，检查对象/条件/操作是否匹配，允许撤回或说明“不适用”。

N≥3 时，由另一位非编辑、非提供者成员按轮转规则检查实际产物的后果。它获得任务、相关公开材料、贡献中的公开依据和 trial 真实产物；先不提供编辑者对自己改动正确性的说明，也不提供提供者本轮 verdict。要求从可见原始依据重建一个关键后果或构造反例。其能看到的原始依据不足时明确 unable；不能假装拥有完整私有证据。

两份反馈独立形成再交编辑者。前者侧重“用对没有”，后者侧重“后果是否一致”。同一基础模型的两个判断仍可能一起出错；不同输入不等于统计独立。

若有现成、任务允许的执行器，可把程序运行/公开约束检查结果提供给全部方法；不得把离线答案或专为当前题手写的正确性判定器引入方法。

### D. 选择现成版本，或留下未解决问题

编辑者读两份观察后选择 keep_old 或 keep_trial，并指出依据。不能在这个选择调用里悄悄写第三版。如果需要修复，记录 issue，下一周期作为可见观察；成员仍可主动指出别的问题。没有“多数认可即通过”规则，也没有把所有人说没问题升级成正确。

程序原样保存所选产物。编辑者仍可能选错，这是不能由协议消除的剩余瓶颈。保留旧版提供回退机会，不保证无损。

## 8. 停止、未完成、冲突与复杂度

开发假设上限两周期，非经验最优值。全部 pass 后停止；重复同一 offer 且无新依据，程序按相同 target+文本哈希只标记重复，不声称识别语义重复。矛盾无法解决时保留现有尽力版本并记录未决，不延长到“直到同意”。

若最后 artifact 未满足任务要求的交付形状，使用预留收尾预算：编辑者形成完整尽力候选，再由一位相关提供者和另一成员分别按 C 检查，最后仅选现有版本。收尾允许产出仍然错误的答案，不自动算成功；无完整可交付版本时按任务规则记交付失败，不能事后补写。

默认不为已完整的版本再写新终稿，最终输出由程序选择版本并按任务 adapter 原样渲染。这个工程规则避免“检查的是一个版本，提交又改出新错”，不解决版本内部的语义错误。

N≥3 时每周期调用为 (N-1) 次观察 +1 试用 +2 检查 +1 选择，即 N+3。N 次初答、两周期最多 3N+6；如需收尾最多另4次，三人19次、四人22次。每调用 token 上限及总预算在实施计划冻结；本设计不沿用旧长 JSON 容量假设。该开销不小，普通讨论需给足相同量级有效推理机会，不能只对比少轮弱基线。

## 9. 具体例子：分清可机械保障与待检验能力

以下均为构造示例，不是已运行结果。

**排名矛盾**：当前列出 D=2,C=1,A=0,B=-1，却交付 D>C>B>A。持有者指向排序产物，以 A>B 为反例；试用重排真实数组。后果检查者只从实际分值和 trial 数组重建相邻关系，未先看到“排序已修好”的解释；最终选该数组而不另写。若它仍说 B>A，协议不会神奇知道错；只有可用的通用排序/约束工具或其他有效判断才能提供更强证据。

**代码接口**：一位成员知道时间戳单位为毫秒；当前实现按秒计算。它指向 parse_event 的除法，给接口资料并建议输入1000的局部试验。编辑者修改真实代码，提供者可发现误把另一字段也除1000，后果检查者运行已有测试或构造输入检查。不为该任务硬编码“毫秒专家”，工具权限在基线相同。

**数学条件**：成员看到当前把相关变量当独立，提出协方差项；有效公式可保留，原先假定的独立条件撤回。提供者检查联合分布是否满足使用条件，另一成员重建特殊情形结果。没人知道协方差时可以保留参数化结论；不能把提出公式直接记为解题成功。

**错误介入**：公开资料已说明某字段在当前版本改为秒，但持有者引用旧版本毫秒规则。反馈应允许指出版本不符并选择旧产物。若全员接受旧规则则会退步，必须计入损害，而不是删除案例。

## 10. 相比旧版改变什么，复用什么

| 维度 | 旧版主要方式 | 本候选改变 |
|---|---|---|
| 初始内容 | 先输出贡献结构，可能抑制完整解题 | 正常独立解题，结构由程序附加 |
| 贡献机会 | 整合者发现缺失后点名请求 | 周期性展示实际解答，成员可无请求主动介入 |
| 使用 | 中央整合者合并贡献 | 具体试用副本与可见前后产物；可以不适用 |
| 检查 | 指定检查者读 U 并指出问题 | 提供者查实际适用性，另一成员先重建后果；不先灌入编辑者正确性声明 |
| 提交 | 持续改写候选 | 最后选择已有产物并原样渲染 |

复用原有 transport、日志、用量统计、权限输入、任务适配。新建独立实验方法模块，旧 v2 和结果冻结；不在原实现里连续补丁然后混称同一方法。

首版不建知识图谱、不加训练、不加声誉、不加额外专职 Agent。代码工作主要是短消息接口、快照/分支状态与调度，以及任务产物定位；不作未经估算的行数承诺。数学或问答没有执行器时，语义检验难度仍在模型上。

## 11. 创新与路线选择

一项主贡献候选：围绕当前任务产物组织“主动发现贡献机会—实际试用—应用反馈”的交互，把知识持有者与使用者共同纳入知识利用过程。暂不声称每个组件新，也不声称已优于最新相近方法。

最小技术路线为推理时协议，无新训练模块。另一条可考虑的路线是学习何时介入/如何选择贡献，但目前缺可信的局部收益监督和稳定交互数据，先引入训练会增加独立问题；不能把最终答对直接归功于某一次贡献。

关键反驳必须正面检验：这可能只是更多轮讨论；也可能把使用者识别需求的困难转移给提供者；双检查仍可能重复同样错误。若按同等机会比较没有增益，不能靠模块名称把它包装成创新成果。

## 12. 最小验证轮廓（只设计，三块）

1. **端到端知识利用**：先确认资料条件确实改变独立表现，再比较普通讨论、请求式黑板适配、本候选；信息、模型、工具与有效计算机会匹配。覆盖集中、分散及低差异条件。看最终质量、初答正确被改坏、同次全员初错后恢复；现有小样本不足以预设团队拖专家后腿一定出现。
2. **机会发现**：持有相同私有材料，比较看不到当前产物、看到原样产物、同内容普通聊天呈现。离线判断是否存在可用帮助及是否提出。主实验不能向方法提供人工标注的缺口；此块是诊断，不用泄漏的机会标签决定调度。检验中间解答是实际线索还是装饰。
3. **实际应用反馈**：在相同自然产生或清楚标注的受控输入上，比较普通评论、提供者实际用法反馈、再加独立后果重建。调用机会补齐，检查“具体知识是否用对”及错误介入损害。固定输入回放只支持条件性结论，不代替端到端优势。

以上最多支持两个主张：总体知识利用带来的任务收益；主动发现与实际反馈对收益的机制证据。引用/采纳率仅为过程指标，必须连同使用正确性和最终影响判断。论文贡献强弱取决于这些结果，不由设计审查评分决定。
