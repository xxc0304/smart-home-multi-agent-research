**GAP：** 当前设计已经建立“看见产物—提出贡献—实际试用—观察后果”的路径，但还没有保证团队现成的完整解答能够低损耗地进入这条路径，也没有完全定义最后一次生成、检查和提交之间的候选集合。与此同时，固定编辑者仍控制试用和采纳，两周期轮转只能处理有限成员的意见。因此，方案可能改善发现，却把收益消耗在候选压缩、排队和编辑者误用上。需要用最小接口修订使这些失败可定位，并让强普通讨论对照能够区分交互机制与额外计算的作用。

**关于真实改变与既有工作的关系**

我不接受“黑板、局部修订和反馈都存在，因此方案完全被覆盖”的判断。所核对的黑板方案由主成员提出请求、助手自行决定响应，主成员执行行动并使用结果；r0 则允许提供者依据当前任务产物发现尚未被编辑者表述的需求，再回看知识的实际使用。这是可检验的交互差异。[黑板论文 §3](https://arxiv.org/html/2510.01285v2)

LMAD 从答案分歧启动局部冲突处理，答案一致时停止。r0 没有这个门槛，因而能够检验“表面一致但存在可用私有知识”的情形。这项区别成立；局部定位、自然初答和局部修订本身应继续归为借鉴。[LMAD §3](https://arxiv.org/html/2608.01463v1)

不过，“主动”在这里应准确解释为**没有编辑者提出具体需求时，成员在定期观察中自行识别贡献内容**。调度仍由程序触发。普通讨论也可能实现这种行为，所以主贡献应落在主动发现与实际应用反馈如何相互配合，而不是把无点名发言本身称为独有能力。

**必须修订的机制**

1. **IMPORTANT：保留可直接利用的完整初稿，避免第二次压缩门槛。**

   补充自查成立。成员已经生成完整解答，却只能重新提炼成一条短 offer，确实可能丢失普通讨论的优势。`whole_goal` 只解决定位问题，尚未明确完整候选怎样进入试用和版本选择。

   最小修改是保留任务允许公开的原生初稿候选区：初稿有不可变 ID，offer 可直接指向作者的完整候选或其中一段，试用允许直接采用该现成候选，再接受相同检查。无需新增候选评分器、摘要 Agent 或预先合并轮次。

   对三至四人的开发配置，可直接提供这些原生候选，并把上下文成本计入预算；普通讨论获得相同候选。较大团队可另设明确的上下文边界，不能把只有 ID、实际不可读取的记录称为可见候选区。若资料规则禁止公开某段初稿，则保留本人可见原稿并使用明确允许共享的输出范围，不能自动全员公开。

2. **CRITICAL：收尾必须定义检查角色与可交付版本集合。**

   目前“形成完整候选，再由相关提供者和另一成员检查”在以下情况不闭合：全部 pass、此前没有成功试用、收尾引入多个来源，或者收尾主要增加了编辑者自己的新推导。此时不存在一个自然确定的“相关提供者”，也不能让一位提供者代为检查所有新增内容。

   还存在版本选择问题：当前版本可能是 partial，历史中却已有完整版本；收尾失败时，只允许选择当前旧版或收尾新版，可能造成不必要的交付失败。

   建议仅补一条确定的收尾分支：程序保留最近一个已进入工作流程、符合 adapter 交付形状的版本；收尾候选与这个可交付回退版本比较。没有来源提供者时，由现有其他成员检查新增内容及可见后果，不虚构提供者身份；多来源时各自声明实际覆盖范围。没有任何合法可交付版本才记交付失败。形状合格仍不代表内容正确。

3. **IMPORTANT：把“真实产物进入检查”落实为固定输入约定。**

   原样保存 Work、Trial 与 diff 是实质进步。补充草案也正确地区分了真实工具返回、模型推导和评价性说明。但“相关产物”和“重建一个关键后果”仍允许实现者任意裁剪，或者只检查容易的一部分。

   旧诊断已经展示：正确加总与错误排序同时可见，检查者仍然漏检。因此不能只保证检查者看到更多内容。需要明确 CHECK_EFFECT 必须获得最终将提交的实际字段，以及该次修改涉及的事实或推导；要求重建与该修改相连的交付关系。排序示例中，应核对实际排序与数值之间的关系，而不是再选择一个无关小计重算。这个检查目标可以用短文本表达，不需要依赖图。

   工具观察必须由运行器绑定到具体产物版本、执行输入和原始返回；模型写出的“运行成功”或“实际结果”仍属于待核对文本。没有执行器时，原生文本是实际产物，但不是外部正确性证据。

4. **IMPORTANT：关闭“无法应用”的反馈路径，并精确定义轮转。**

   新增接口已经解决了一个问题：没有 trial 时不调用两次空检查，也不能选择不存在的版本。这个修改应保留。

   但“生成有原因的应用反馈”还需规定交给谁：失败原因应进入下一次 OBSERVE，至少让原提供者能够根据真实拒绝原因修订贡献；预算耗尽时则记录为未完成的应用反馈。不能把编辑者拒绝试用记录成该贡献无用。

   固定编辑者可以保留。它让实现简单，也形成持续的采纳瓶颈；无需为了消除它再引入投票器。轮转同样可以保留，但应明确起点、跳过 pass、指针更新和已尝试成员的顺序。两周期最多试用两位提供者，N≥4 时不能承诺全部成员得到试用机会。必须区分“没有提出贡献”“提出但没有排到”“被拒绝试用”“试用后未采纳”，否则无法解释专长在哪一步流失。

5. **IMPORTANT：明确公开产物、私有证据和检查范围的权限关系。**

   “原件保持私有、贡献可公开摘录”是合理方向，但共享 Work、完整初稿、工具输出、use_record 和 Check 都可能包含由私有材料产生的内容。仅检查引用 ID 是否可见，并不能定义这些内容能否传播。

   最小做法是在任务适配器中事先规定：哪些源材料只能本人读取，哪些事实、摘录或任务输出允许分享；运行器据此组织可见输入。若实验仅模拟“初始信息分散，但解题时允许分享所知事实”，直接写明即可，无需增加自动脱敏系统。

   第三方缺少某项私有原始资料时，仍可能核对公开结论之间的一致性。例如不能确认私有分数，却能确认“给定这些分数，排序是否相符”。`scope` 应保留这种局部可检查性；既不能将局部一致升级为完整验证，也不应把一个不可核查前提扩展成整项检查都无法进行。

**相同计算预算下的区分是否充分**

现有三块验证方向正确，不需要扩展成大实验清单。但在进入实施计划前，应冻结三条对照约定：

- 普通讨论获得相同的独立初答、资料权限、工具和完整候选访问，并允许重新完整求解、主动纠错及提出替代答案。
- 预算包括初答、观察、试用、检查、选择、收尾和恢复开销；调用数相同只是辅助约束。输入、输出及可获得的推理用量应分别报告，不能用无效填充调用补齐预算。
- 在已有机制诊断块中，共用版本保存与原样提交规则，避免把减少最终改写失误全部归因于知识发现或应用反馈。固定输入回放继续只解释条件性的机制效果。

机会发现块还应区分**提出了可用帮助**与**帮助最终进入试用**。反馈块应区分**知识本身正确**、**应用正确**与**最终结论改善**。否则新增协议日志会增加，核心知识利用命题仍然难以辨别。

**可以合并或删除的复杂度**

- Work 与 Trial 使用同一种不可变产物结构；Trial 只增加基版本和使用记录，无需维护两套内容模型。
- 完整初稿直接加入候选区，避免新增摘要、全员排序或预选模块。
- 收尾复用现有生成、检查、选择操作，仅增加明确分支；不再新增“终稿整合者”。无新产物时跳过检查的简化已经合理。

**Modernization Opportunities：NONE。** 当前方法已充分使用 LLM 的自然解题、情境关联和反馈能力。训练介入策略、引入图谱或专家声誉都不是完成当前设计的必要条件。

**仍需实证、但不阻断设计完成的问题**

提供者是否比编辑者更容易发现未表述的需求；减少评价性说明是否真的降低错误沿用；双检查是否比同预算普通重算更有效；固定编辑者会否频繁拒绝正确知识；完整候选区的收益能否抵消额外上下文成本。这些都可以在上述协议闭合后检验，不能通过设计评分提前认定。

**设计可实现性：有条件成立。** 可据此搭建独立运行器主体；修订上述边界后，可以形成实施规格，不必等待实验成功。**研究贡献成熟度：尚未 READY。** 已有一个集中且有合理差异的机制假设，但其增量需要被强对照和可定位的过程证据支持。
