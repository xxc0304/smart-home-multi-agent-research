# 交互接口草案与实现边界

状态：配合 r0 的可执行性展开；待设计审查整合，不是已兼容 DeepSeek 服务的 schema。

## 一个成员真正收到什么

所有调用都有原任务、当次成员的合法私有材料、公开材料、当前剩余预算。调度器不提供评分或标准答案。工具调用及其成本独立记账。

| 阶段 | 另给的内容 | 输出动作 |
|---|---|---|
| INITIAL | 无他人初稿 | 正常解题；提交任务原生交付物与解答文本 |
| OBSERVE | 同一当前版本、公开依据、上轮未解决观察 | pass；或 target+knowledge+support+proposed_use |
| TRY | 当前版本、一条选定 offer | 试用后的实际产物+use_record；或无法应用的具体原因 |
| CHECK_USE | 原 offer、试用前后真实产物、use_record | 匹配/误用/无法判断的具体观察 |
| CHECK_EFFECT | 原任务、公开依据、offer 的公开支持、实际 trial 产物、自己私有材料 | 重建关键后果或给反例；不先给编辑者的正确性声明或本轮其他检查结论 |
| CHOOSE | 旧/新两个实际产物、两份检查、可见执行输出 | keep_old / keep_trial；说明观察依据，不生成新产物 |

CHECK_EFFECT 是新请求，不复用检查者上一阶段的隐式聊天状态。隐藏的是评价性说明，不隐藏任务所需公开事实；提供者新披露的证据会明确并入公开证据集。编辑者的模型推导可作为待核对内容，不冒充原始资料。

## 五种消息的字段解释

程序在外层注入 run_id、member_id、stage、base_version、source visibility、调用编号；模型不生成这些标识。

- Work：`artifact` 为 adapter 所定义的任务交付物；`work_text` 为普通可读解答；`open_points` 可空。程序只按段落或代码行增加位置，不再要求模型逐步登记原子关系。
- Offer：`target` 是当前位置或 `whole_goal`；`knowledge` 是提供的事实/关系/反例；`support` 是原资料引用、允许公开的摘录，或标明为自身推导的说明；`proposed_use` 是建议尝试的具体动作。`pass` 不要求编造一个贡献。
- Trial：包含新的 Work 和 `use_record`。`use_record` 写对象/条件、实际操作、局部结果；程序保存真实 diff。不能只写“已采纳”。无法应用时仍保留旧版本，生成一次有原因的应用反馈；若没有新产物，不调用两个后果检查以制造空转。
- Check：`finding` 取 `issue/no_issue_found/unable`，`observation` 写实际重建/执行观察，`scope` 指检查了哪里及没检查什么。无 `correct=true` 字段。
- Decision：动作 `keep_old/keep_trial`，以及 `reason`；真实产物从已存版本读取。无法应用时只有旧版可选，不容许选择不存在的 trial。

这不是要求每一步分析都填表。普通解题保留；额外结构只出现在跨成员交接处。首版不要求模型提交 JSON Patch；整份任务原生产物更新，程序计算文本差异。大型代码仓库未来需文件级接口，本轮不假定已支持。

## 运行器可以判定什么

可机械判定：阶段动作是否合法；输入版本是否仍当前；目标位置是否存在（whole_goal 除外）；来源引用是否可见；本轮 peer offer 是否隔离；候选是否真实存在；是否原样提交；预算和同一文本重复；已有工具的实际返回状态。

不能机械判定：知识是否真、位置是否语义相关、试用是否必要、条件是否满足、修改是否改善、无问题是否真。来源存在不代表支持充分，形状合法不代表完成任务，保持旧版不代表正确。

## 需要在实施计划冻结的工程选择

1. 模型实际服务名与参数沿用既有配置并记录，不凭产品昵称猜版本。
2. 任务 adapter 提供 artifact 类型、渲染、合法交付形状和既有可用工具；离线 gold scorer 不进入 runtime。
3. 每阶段长度和总上下文预算由真实请求体估算，超限先停止保存可交付版本；不能静默删资料或无限恢复。Schema 容量随可见资料计算，不沿用“最多12引用”假设。
4. 格式错误、重试和正常 pass 分开计数；记录首次输出、恢复后输出及额外 token，不能用恢复后的干净内容隐藏前一次失败。
5. 先以离线脚本核对状态转移和权限，再独立核对服务兼容性。当前用户只授权设计，本轮不运行这些步骤。

## 普通讨论公平性

同一单元的两方法须使用相同 INITIAL 输入和任务 schema；运行预算按真实模型调用、输入/输出 token、工具行动分别报告。协议步骤多不意味着可以给基线更少有效推理。多条初稿如何进入讨论是方法差异，应列明；固定同一初稿的回放单列为诊断。

复杂协议应与有完整推理机会的普通讨论比较。若收益只由初答提示变好或多一轮重算带来，应据实归因，不把它写成专长协作的证据。
