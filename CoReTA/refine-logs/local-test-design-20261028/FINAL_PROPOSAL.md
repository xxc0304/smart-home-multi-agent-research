# 当前设计与最终处置：源记录绑定的局部行为检验

2026-10-28。完整修订稿；不是生产实现或实验启动说明。接受第一轮三项接口建议，缩为一种数学关系。新模型API0，训练0，旧数据/原分不变。早期可行性复核与论文成熟度分开，不为9分扩组件。

## Problem Anchor

- Bottom-line problem: 让分散在成员中的局部知识在共同解答中被正确应用，并在合理成本下改善团队结果。
- Must-solve bottleneck: 局部信息已可用，但接收者可能将它用于错误对象、范围或组合；检出问题后也可能没有有效修订。
- Non-goals: 不消除所有基础模型错误；不把工作图形成、引用数或自报接受当成功；不强迫每题使用新机制；不以禁止普通组共享原件/重算制造优势。
- Constraints: 现有黑箱模型API与CPU；不依赖本地模型训练；本轮只作最小设计和既有案例离线走查，不发付费请求、不改生产架构/原评分。保持原始记录，人工设定与自动能力分开。
- Success condition: 能提出一个明确操作，解释为何可能减少实际误用；自动候选/检验/修复各自的未知清楚。后续在同信息/同工具/匹配预算对照中改善一到两个缺口且不造成更大损害即可，不要求每题胜或所有组件首次提出。

## Anchor Check / Simplicity Check

原瓶颈是局部内容进入求解后被误用，仍然对齐。当前最小数值范围只覆盖其中一部分，不能替代一般知识互补命题。W3只是旧接口中间误用见证，原终稿正确；如后续只解决自己引入的W问题，不能声称提升普通协作。

保留普通协作、资料权限、来源分享、计算器、现有候选。不加角色网络、置信度、持久检验池、全员W登记或训练。只增加一次性的源记录绑定和同一干预下的候选实际重执行，再按事前固定规则更新可绑定的局部计算。

## 方法假设与范围

假设：判断一个局部量应覆盖哪些记录、遵循什么基础关系，有时比追踪嵌套公式的实际依赖更容易。把前者交给成员提出、后者交给确定性执行器，可能减少部分错误应用。不是假设提出者总正确，也不把这种认知难度差异写成已证事实。

只完整定义`equal_record_mean`关系：对模型所认定的同单位、等权记录集合，每条记录增加d，输出应增加d/n；集合外且已绑定的记录变化不应影响该局部输出。n由记录数量计算，模型不能直接填正确输出或期望斜率。其他逻辑、文本支持、风险/偏好检验暂列后续，当前不实现。

因此它不是一般语义验证器。统计对象选错、记录集合遗漏/重复、单位解释错仍可导致错误检验。已知歧义可以回退，但“能否识别歧义”仍是模型能力，程序不能据声称unknown就保证拒绝所有模糊题。

## 第一问：如何发现值得区分的用法

输入：原任务、当前可见的局部贡献、接收者准备执行的具体动作/表达式。接收者或资料持有者可指出一个范围/对象/组合分歧。只处理当次第一个有合法来源定位、且作用位置存在的提议；这只是低成本确定性顺序，不声称选到最重要问题。

原候选C0保持；C1来自同伴已存在工作或一次局部修订，不能由宿主按参考构造。无替代时允许只报告违规，不假装修复成功；无提议时普通求解直接继续。当前离线W3焦点和W2替代由分析者指定，必须单列为oracle焦点/候选走查。

## 第二问：检验怎样产生与绑定

### 执行前的单次约定

检验提出者在看到两个候选的测试响应/通过列表前，提交原任务片段、自己原件的精确定位、`equal_record_mean`种类、认定的记录集合与适用理由。这个语义提议不依赖知道官方答案。

程序检查结构、引用可见和记录可定位；不能认证原句蕴含该关系。允许提出者主动无法确认/反对。提交即冻结本次假设；不允许看到哪个候选获胜后重写关系。暂不增加第二裁判，语义误提直接计入方法失败与改坏。

### 一次性最小接口

```
source_records: immutable id -> (original locator, literal numeric value, unit declaration)
candidate_0, candidate_1: safe arithmetic expressions over source_record ids / bound intermediate expressions
test: (kind=equal_record_mean, record_set ids, question/source locators, applicability rationale)
affected_output: an existing expression/output field with explicit dependency
```

其中来源定位与数值检查是宿主事实，单位、目标范围、记录是否应该等权是模型判断。不得把输入字段叫verified从而混同。

同一个原始单元在两个候选、多个中间表达式中只有一个不可变ID。模型须给出来源绑定，或复用已有真实绑定；同值不自动视为同来源。无可确认来源的计算数据、只有缓存结果、无法展开的自然语言推理均记为`unbound`，不由宿主偷偷补表达式。结构常数如除数可存在，但测试的期望响应不能从该候选常数反向推导。

纯算术语言只允许有限的加减乘除和命名引用。变换发生在源记录层，所有出现该记录的中间式都重新执行；不只修改某一个输出或表面变量。对全部已绑定源记录固定扫描d=100（测试增量，不是改原数据），不选择最有利年份。未来其他单位/合法值域需另审，本版不假称已有通用变换器。

第一次脚本仅按metadata拼写映射年份曾遗漏`fiscal 2019`与`fiscal year 2019`差异；最终走查改用分析者核准的实际表格行列和年度表头，检查原数字后统一变换所有同源出现。这个本地修正暴露了绑定的重要性，不是已经完成自动语义绑定。

## 第三问：反馈怎样实际影响求解

固定选择操作在测试执行前确定：

| 条件 | 允许的操作 |
|---|---|
| C0违反、C1未违反且两者完整可执行 | 在本次已接受的检验假设下选择C1，生成局部表达式补丁并重算有明确依赖的下游 |
| C0未违反 | 不因C1也通过或文字更有说服力而自动换选 |
| 两者都违反 | 不选“违反少一些”的候选，不自动判题目无解；保留原求解路线并报告局部检查失败 |
| 无绑定、无法执行、无可确认检验 | 不自动改选；普通求解继续 |
| 发现反对检验的新来源依据 | 本次自动更新撤销/停止，保留原与补丁记录；不在看到数值后悄改标准继续挑选 |

“未违反”不是正确。结果与采用假设、来源绑定一并交付；错误检验可能导致错误补丁，原C0不删除。不能将该策略的执行称作模型学会了采用。

最终产物首先是局部补丁及重算输出。若该输出直接对应原题的数值回答字段，可按显式程序结果渲染，分别保存模型原答与工具交付值。若仍需自然语言重写/开放决策，系统只完成局部更新，后续答案正确采用仍是独立未解问题；不能声称已解决端到端接收问题。

前述操作是候选机制设计，不是已完成的模型控制器。walkthrough.py只执行既有数值公式，尚未实现生产级绑定API或自动补丁集成。

## 为什么不是又一轮泛泛复核

模型提出的范围判断可能是较容易的局部任务；工具给出的候选响应不是模型自报分数。同一个源记录干预下实际重执行与事前固定的局部替换，是本候选相对纯文本检查的具体操作差异。

它仍近于旧条件执行和条件提交：如果语义关系总是需要人工填写、或仍主要靠接收者读报告自由重写，就没有跨过旧缺口。与CEGIS/TLP的思想关系已有先例；潜在研究贡献只能来自分散成员如何自动产生有效检验并帮助实际求解，未作新颖性认证。

## 案例走查与反例控制

1. 实际权益中间错误W3及已存在正确W2：原件T1/T2的Total equity行与年度列绑定到真实表达式；2015–2017每年+100时，W3+12而W2+20；2018–2019时W3+32而W2+20。全部五年扫描可区分。焦点、行列、目标集合和替代均有人为选择，新增正确终稿0。
2. 正确五年直接求和/5与同源分区求和/5：两者通过相同关系，不自动换选。重写版本是人工构造的工程控制，不是模型生成的第二正确解。
3. 错误检验：若自由允许期望2019+100时输出+32，错误W3通过、正确W2失败。v2通过固定mean模板删除了该自由参数，但仍可能选错目标集合。若把原题五年误认成2018–2019两年，再比较W2与W1，两年检验会错误选择W1。后一风险不能靠模板正确消除。
4. 股息记录平均/年度总额平均与差额方向：关系不能自行决定原题解释；走查标歧义/回退是分析者判断，不证明未来模型自动会回退。普通题没有发现分歧则跳过，不要求造检验。

## 实施与验证边界

新增训练0、基础模型0，CPU可执行；后续模型过程可能需要局部提议、检验生成和替代生成，实际请求/输入成本必须在实验计划冻结，不能宣称免费或不增加调用。

最先要验证自动形成：模型仅据合法任务与成员资料能否提出合适焦点、绑定和检验；分别记录错误集合、无检验、无替代与误改。人工规范上限不作为该证据。

后续最小对照仍需同信息/同工具/合理计算预算：普通定点复核、同候选但没有实际干预响应、候选+检验。不能靠额外获得私有原件或正确关系制造优势。最终净修正/改坏/普通任务退化为主，登记率/通过率只作过程观察。

当前只有W表示中的数值错误链，尚未在本批普通讨论错误终稿找到无歧义、可被此关系修复的案例。不能将该原型当成一般多Agent能力提升；若更广记录也无相关真实失败，应停止推广此路线，而不是特意制造模型失败。

## 当前结论

最小操作定义与人工辅助走查已完成。第二轮发现：同一已接受的目标记录集合和值足以直接求和/计数得到均值，不需要第二候选或扰动；mean+1000又可通过全部增量检查。当前equal_record_mean路线作RETHINK处置，不作为下一套研究架构实现或准备付费批；保留来源绑定和重放作为诊断工具。未解决的范围语义不能用更多执行协议掩盖。详见REVIEW_SUMMARY.md与round-2-review.md；此决定基于必要性与强简单参照，不以论文成熟度或评分9分为探索门槛。
