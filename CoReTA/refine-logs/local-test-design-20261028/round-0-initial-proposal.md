# 最小候选：成员提供可区分用法的局部检验

2026-10-28。概念设计，无新模型/API实验、无生产代码改动。研究对象是一个局部应用动作，不是新完整团队架构。MAX_ROUNDS=2，输出只作早期可行性/作用机制复核，不以论文READY或9分为实施要求。旧全局refine-logs状态保留，本次专属目录保存过程。

## Problem Anchor

- Bottom-line problem: 让分散在成员中的局部知识在共同解答中被正确应用，并在合理成本下改善团队结果。
- Must-solve bottleneck: 局部信息已可用，但接收者可能将它用于错误对象、范围或组合；检出问题后也可能没有有效修订。
- Non-goals: 不消除所有基础模型错误；不把工作图形成、引用数或自报接受当成功；不强迫每题使用新机制；不以禁止普通组共享原件/重算制造优势。
- Constraints: 现有黑箱模型API与CPU；不依赖本地模型训练；本轮只作最小设计和既有案例离线走查，不发付费请求、不改生产架构/原评分。保持原始记录，人工设定与自动能力分开。
- Success condition: 能提出一个明确操作，解释为何可能减少实际误用；自动候选/检验/修复各自的未知清楚。后续在同信息/同工具/匹配预算对照中改善一到两个缺口且不造成更大损害即可，不要求每题胜或所有组件首次提出。

## 技术缺口与方法假设

当前模型常把局部事实、说明和全局推荐一并接受/拒绝；结构化登记还可能增加文字与工作对象不一致。仅执行已选公式无法判断该公式是否正确使用成员知识。

候选假设：对于有可核查局部关系的任务，成员针对两种候选用法提出一个能区分它们的检验，实际执行后按结果修订候选，比泛泛意见和自由重写更容易定位误用并保留正确局部内容。假设未获新模型证据。

Route A：再做消息澄清。操作简单，可减少某些交接误解，但能力来源仍是通用模型读消息后提问，近AgentAsk及项目旧局部提问；本次不优先再搭提问流程。

Route B：局部可执行检验与候选选择。新增依据来自执行结果与有依据的输入输出关系，不要求强判别器；但检验依据与候选构造仍可能错。暂选B作具体化，不能把它写成已证明优于A。

## 最小数据流与新增操作

复用普通讨论的成员/资料/原件分享/计算器。最多对一个已提出争议的局部步骤干预一次；没有争议或没有可执行检验则按普通路径继续。没有独立全局协调者、信任分数、持久检验池或强制W登记。

1. 接收者或知识持有者指出一个具体应用动作：被用的贡献、准备完成的步骤、当前算式/主张。不是先要求枚举全题缺口。
2. 提出最多一个替代用法；可以来自同伴原有工作或基于原件的局部修订。两者共享任务、原件和未受影响的步骤，保留原候选。找不到替代时也可只检查原用法。
3. 原持有者看到原任务、自己资料和两种局部用法，提出一个基于所持证据的检验。输出只有焦点、原文定位、检验理由、可执行关系/输入变换；可以说无法检验。最初仅支持有明确解释的数值/集合关系。
4. 确定性执行器检查引用可见、原文定位存在、公式可执行，再执行两种用法。结果为违反关系/未发现违反/无法检查，不叫真/假。
5. 单次候选修订：若关系适用性被接受、原候选失败且替代未失败，使用替代局部动作重算受影响下游；其余情况保留原路线或交由接收者最佳努力，不将未知变错误。原模型答案与实际交付分开记录。

这里没有假设“持有资料的人必定正确”；提出的检验本身是可质疑贡献。第5步的适用性接受目前仍由模型判断，并非已有可靠机制。

## 三个问题的具体答案

### 如何发现要区分的用法

触发来自可见的两种范围/对象/公式解释，或成员对某个操作的明确异议。模型可以主动提出，程序只提供精确动作与原文定位，不按参考答案挑步骤。只取当轮第一个有合法原文依据且作用位置存在的提议，避免再搭评分器；此调度仅为初始简化，不能保证最值得查。

没有成员发现时，本机制不会触发。这是发现能力待检验，不通过人工插焦点冒充自动发现。已有W3错误用来走查时焦点是分析者挑选，明确为oracle焦点、非自动过程。

### 检验怎样产生

LLM根据原任务/局部原件选择关系，而不是从被检验用法的自报metadata里抄规格。初始允许三种通用关系模板：保持范围外数据变化不影响结果；单个同单位量变化时结果遵循已声明线性系数；按互斥完整分区分别计算与全体计算相符。系数、范围集合和分区都必须由模型提供依据，程序不替模型猜年度或统计粒度。

模板是通用数学规则，不是每题人工正确条件。它们的语义前提并不因为模板固定而自动成立。引用定位存在不认证语义；无法确认前提则不能强制改选。开放偏好题、模糊平均粒度、预测当事实等不在本版确定性覆盖内。

### 结果如何影响求解

将反馈约束到被测局部候选，而非仅把长报告附到公共稿。保留原候选，替代必须从真实材料/实际输出产生；不能人工注入正确解。若模型能认定检验适用且只有一个候选未违反，可选择该候选，并重算明确受影响部分；若两个都过，不以一致当真；若两个都败，不强行选较少违反者；无法确认检验前提时回退。

要避免同一个接收者拒绝正确检验，这里尚未有完全自动的可靠裁决：直接程序硬删会重演错误条件排除正确解，完全自由接受又可能无效。本次必须将这一点作为待研究核心，不以状态机遮掩。

## 可构造的局部走查

- 权益旧失败W3：分析者选焦点并将现有W2正确五年公式作为替代；某一年加100时，原W3加32，替代加20。可以证明关系有区分力，但最终旧答案本已选W2正确，不能报新增准确率。
- 正确五年公式与其分区SUM/COUNT重写：两者都遵循每年权重1/5，检验不应强行选择一方。
- 普通百分比题：若没有异议则直接跳过；若采用线性检验，必须固定分母并正确解释百分数单位，不能把任何输入+100都期待固定增量。
- 股息/差额边界：年度均值与单次支付均值、带方向差与幅度差不是纯计算矛盾。检验不能通过人工固定官方口径偷偷决定；本版作未知/回退。

下一项有效行为证据必须由模型自行产生焦点、候选及检验，且改变真实有错终稿；当前走查只检查手工见证和机制边界。

## 与旧方案/邻近工作的实质对齐

旧条件执行：主要把原文提成事实/硬条件筛候选；本候选尝试检查“用法对输入变换的响应”，但原文→有效关系仍是同样未解决的建模瓶颈。

旧局部应用/条件提交：成员提出建议/条件，程序一致化或宿主改选；本候选只作用于一个应用动作，并比较原/替代的实际测试结果，不要求整队维护W图。但单纯缩小范围不是新颖性。

CEGIS已有反例指导候选搜索；数据库TLP已有变形/分区oracle；AgentAsk已有局部交接干预。方法增量若存在，应是分散成员怎样根据自己知识自动产生有效局部检验并参与候选修订；当前尚未完成，不能称已有独特创新。

## 简洁性与失败边界

新增训练组件0；新基础模型0。检验执行复用安全算术后端，不允许任意Python；表达式/变换需要受限纯计算语言。当前是设计，不是已有接口。最多1焦点、2局部候选、1检验、1次修订；不新增例行全员检查轮次。实际模型调用成本要在将来设计中列出，不能因只改一处就称便宜。

主要风险：成员不发现分歧；两个候选都错；检验依据错；数据变换无法与表达式变量准确绑定；有用测试被接收者拒绝；错测试被程序硬用。后两项尚未解决，应决定早期验证能否支持继续，而不是不断加角色。
