# 权限修正后，逐条反馈是否值得加入

## 审核结论

新候选能实现意见追踪，但暂未证明它能改变语义判断。格式要求比原流程更多，且意见积累会增加上下文与输出负担，故先检验组件行为。若只比旧版与新版，会混入权限修正的影响。改用两组均修正权限的对照。

## 最小自然流程对照

- A：ground_access_only_v2，仅明确检查者、作品作者、应用者权限；保持原自由文本检查和选择。
- B：ground_issue_loop_v2，在相同权限说明上加入具体问题、逐条处置、后续版本复核。
- 两组都把重复作品全文统一放入CANDIDATES；前后稿/当前稿等位置用ID引用同一全文。原文、行号、问题记录保留，两组共同减少重复输入。
- 任务：固定开发005、006，各一次。已有005三组全错、006技术中断；这是历史失败诊断，不是未见测试集，不能作为泛化证据。
- 各组从原先存档的同一组独立初答重新完整运行协作；不得继承旧协作、旧检查意见或本次助手人工挑选的问题。005用A→B，006用B→A固定顺序。
- 005每组25次、006每组16次，总上限82次请求。两组所有阶段输出cap相同，choose/final_choose均2048；无自动补跑、无按结果挑题。没有新的INITIAL请求。
- 预先给每组严格输出总预算，按最大正常路径计算：005每组67584、006每组45056，总225280输出token。匹配预算上限不等于实际成本相同，须报告实际输入/输出及技术失败。
- 普通讨论不在此次组件对照中，之前结果不能直接作为本次同期对照。若B表现出语义收益，才回到与普通讨论的完整对照。

## 要观察的结果

1. 权限误报：相同输入下是否仍把检查者权限误套作者；两组都可能改善，不能算闭环独有收益。
2. 实质问题：逐条对照原资料，区分确切错误、证据缺失和可争议权衡；模型报issue不是金标。
3. 纠正链：问题提出→认可/驳回依据→实际修订→复核→最终保留。只增加理由或格式完整不能算纠错。
4. 错误介入：无效检查是否导致有效知识丢失或错误修订；总是维持旧稿也不能算成功。
5. 最终质量与成本：选项准确率、证据应用质量、仍未解决的实质问题、真实token和失败率共同报告。

两题一次没有统计结论。005定性录用标准未给定唯一数字权重，不强制将不选官方答案等同于每一步推理错误。准确率按原金标报告，过程结论另外依据文本证据。

## 开跑条件

已实现有界执行器、首错停批、缓存一致性校验、3/4成员全链路和格式负载检查。输入、源代码、初答缓存、调度、过程评分标准和预算在新包中重新冻结；动态后续请求由冻结代码生成并保留原始请求。未发API。真实服务对动态schema/空对象的兼容性只能在首次执行中确认，失败作为技术结果保留，不自动重试。

运行前校验完整源清单、所有准备文件、固定调度和预算。实际请求一旦usage未知或超出可计费预算即停止整个批次。只允许对完全相同值的重复JSON键做审计归并；冲突键、缺字段、额外文本等均停止，不自动纠正语义。

## 保留的限制

最终阶段只能从既有交付版本选择；若proposal与fallback相同，选择无法修复终稿检查刚发现的问题。未新增调用时这点仍成立。模型的resolved和reject都不是正确性认证。若只改善来源账目或回应完整率，没有真实判断/修订收益，应停止扩展此组件。
