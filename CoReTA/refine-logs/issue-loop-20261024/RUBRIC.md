# 过程评分及结论边界（运行前固定）

标注者阅读原任务、对应成员原件、公开贡献及实际前后稿。原件/金标只在离线评分中读取，不进入执行器。模型自报状态只作定位线索。允许uncertain，不把定性录用权衡自动判错。

每个方法按原子问题记录：问题内容、主体/条件、来源位置、首次出现、是否被提出、有效/误报/可争议/无法判断、影响的任务要求、处置理由、实际修订、后续复核、最终保留/仍有错/误改。每个判断附原文引用；重复提出同一问题计一个机会、多次发生位置。

- 有效纠正：原有确切错误或遗漏被合理指出，后稿实际修正，终稿保留。只补来源、引用意见或写“范围更窄”不自动算实质纠正。
- 论证改善：定性任务中给出更完整的证据与标准权衡，另列描述，不与确定纠错混算。
- 错误介入：错误意见导致原本正确的事实、关系或约束丢失/改错。
- 同一事实两组均可见，使用同一claim ID跨方法比较；两组后来独有的错误单列，不把不同机会分母视为同难度。
- 未出现有效错误机会时填N/A，不能把全部no_issue_found作为成功。
- 最终选项按原金标单列；不得因过程更详细提高答案分数，不得按模型投票生成真值。
- 两题一次的结果按任务逐项报告，无显著性、无泛化或超越普通讨论结论。是否修复检查权限不是本闭环独有收益。
- 成本记录所有实际请求、输入/输出、修复、未知usage、技术中断；技术失败单列，不从批次表删除，不补跑后拼接。

继续条件：出现至少一条有文本支持的实质纠正或明确推理改善线索，且误改与成本可接受，才考虑独立任务上的后续检验。这只是开发决策，不是通过统计门槛。若只改善格式和账目，停止扩大此组件。

匿名方法导出可减轻先验倾向，但输出结构会暴露方法，不能称完全盲评。本助手单独标注时须披露，不能称独立人工复核。
