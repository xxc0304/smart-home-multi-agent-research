# CoReTA v0.3 实验协议草案

日期：2026-10-18。状态：设计完成度待审；所有数字均为拟定配置，无运行结果。本轮不发出模型请求。组件协议见 round-0-initial-proposal.md，来源见 SOURCE_LEDGER.md，具体参数见 design/v0.3/run_config.proposed.json。

## 研究锚点

> 提高多 Agent 团队的协调与问题解决能力，让成员已有知识及协作中新产生的有用贡献得到实际利用；先把定向帮助、贡献检查、整合与应用反馈落实为三 Agent 可执行协议，再用已有论文采用的任务检验整体能力与互补作用。优先借鉴公开方法和官方代码，清楚区分复用接口与本项目的机制假设。能力与机制优先，成本如实记录，同成本优势与节约成本后置。本轮交付设计，不运行付费模型、训练或真实效果实验。

## 1. 主张与证据对应

| 主张 | 最低证据与对照 | 解释范围 |
|---|---|---|
| C1：该协议能提高团队任务表现 | 同任务、同成员、同工具条件下与独立汇总、静态讨论比较完整任务结果 | 主效用，不声称同成本最优；还报告单体与自行反思参考 |
| C2：部分收益依赖具体帮助被接收者实际利用 | 普通帮助和无显式应用记录变体；预定贡献位置的内容替换；下游变化及离线案例核对 | 联合支持成员贡献作用，不把单个消融解释为纯互补因果分解 |

需排查的替代解释包括：更多采样或续写、额外初审、统一汇总器自行重解、强成员完成整题、只保住已有答案。首轮不把资源效率设为成功条件；要声称机制时仍需相应对照。

## 2. 任务选择：两类主评价任务

### 2.1 数学：MATH-500

- 数据：`HuggingFaceH4/MATH-500` test，全 500 题；保留 unique_id 与原始顺序另建排序清单。
- 依据：SOURCE_LEDGER S7 所核同类协作推理论文使用该数据；S8 提供公开数据，S9 提供末端答案评分。
- 作用：多步推理中的补全、反例与方向修正；能客观比较最终答案。局部论证是否正确不由最终答案自动推出。
- 运行输入：仅 problem，类型 math；subject/level 仅用于离线分层，answer/solution 仅用于评价。
- 评分：把 gold answer 包装为数学表达式，`parse(gold)` 后 `parse(prediction)` 再 `verify(gold_parsed,pred_parsed)`，顺序固定。优先抽取 artifact 的最后一个 boxed 答案，使用固定 Math-Verify 解析配置，记录版本及超时。预测不可解析计错并单报；金标准无法解析属数据/评分故障，先在看模型输出前核查，不能随方法改变。
- 评价端评分超时先使用统一重试一次；仍失败标为 scoring_error。主表报告已定评分规则下的准确率以及 scoring_error 数量；最终发布前解决所有方法共有的评分故障或给出同一任务集合的敏感性结果，不将其静默按“答错”处理或选择性排除。
- 具体解析适配：gold 使用数据 answer 字段外包数学环境，`LatexExtractionConfig()`；预测只读最终 artifact，使用 `LatexExtractionConfig(boxed_match_priority=0)` 与 `ExprExtractionConfig()`，`extraction_mode="first_match"`、`fallback_mode="first_match"`、parsing_timeout=5。固定版本在同一 Linux 离线评分环境的独立进程主线程调用，避免平台/线程计时差异。金标准在生成任何测试回复前做可评分性核查；确需改变配置则对整套任务固定，不按某方法预测调规则。
- 限制：该公开历史集可能被底座训练接触，不声称未污染的泛化。后续再用更新任务做外部验证，不在初版膨胀任务范围。

### 2.2 代码：HumanEval 与 HumanEval+

- 数据：通过 EvalPlus 获取原始 HumanEval 的 164 个题面，评价原测试和增强测试；数据代码标记 HumanEval+ v0.1.10，`mini=false`、`noextreme=false`。软件包/仓库 revision 实施时另锁。
- 依据：S6 AgentVerse、S7 同类协作推理使用 HumanEval；S10 EvalPlus 提供增强测试与评分接口。HumanEval+ 是同一批任务的更严格检查，不算第三个独立任务集。
- 输入：公开 prompt 和 entry_point，不提供参考实现、基础/增强隐藏测试或预先运行结果。prompt 内原有的公开例子正常保留。
- 输出：完整源码 artifact，离线按 EvalPlus 支持的外部样本格式转换；任务 id 保持原值。实施时固定适配版本及全文源码/补全格式转换，不按结果挑解析策略。
- 外部样本固定写成 `{"task_id":"HumanEval/0","solution":"完整 Python 源码"}`，使用 EvalPlus 已支持的 solution 分支，不再把完整源码拼接到 prompt 后。每个重复单独输出一个包含全部164题的 JSONL 文件；空答案也保留对应 task_id。评测参数固定 `dataset=humaneval`、`base_only=false`、`mini=false`、`noextreme=false`，统一使用所锁版本的时间限制默认值并记入清单。该接口已核官方 evaluate.py 与 data/utils.py。
- 对 B2/B3 的题目子集，不能直接把不足164题的样本交给默认全集评分：官方 evaluate.py 要求样本任务覆盖载入的完整题集。离线评分端先从同一锁定 HumanEval+ 原数据导出精确子集，设置官方支持的 `HUMANEVAL_OVERRIDE_PATH`，使评分数据 id 集合等于该批实际评价 id 集合；记录母数据哈希、子集 id 和子集文件哈希，测试内容保持原样。此覆盖路径只存在于评分容器，不能进入 Agent 输入。无合格帮助按零差处理的轨迹复用自然结果，干预不可构造的缺失保持缺失。
- 评分：每个完整团队轨迹最终只提交一个程序；分别报告原始测试与增强测试的 pass@1。三个独立重复按三次完整系统采样评价，不能据隐藏测试在三份中选择或报告 pass@3 替代主指标。
- 第一版无在线代码工具，LLM 检查只是文本检查；末端执行在隔离容器、禁网及有时间/资源限制的环境进行。不得因本机缺容器而在宿主直接运行模型生成代码。
- 限制：函数级任务与公开历史数据不能证明大型软件协作能力；高基线接近天花板时如实报告，不按测试表现换成有利子集。

### 2.3 开发与初步验证题

数学开发：GSM8K 原始 train 选 50 题。代码开发：`google-research-datasets/mbpp` 的 `sanitized` 配置 train 选 50 题。选取算法为题面规范化后 `sha256("coreta-dev-v1|" + task_id)` 排序取前 50；样例/接口检查先用其中各 3 题，有限真实试点用其中各 10 题。种子 17；其余开发题用于模板修订与评分检查。

已核 MBPP sanitized 数据卡：字段为 source_file、task_id、prompt、code、test_imports、test_list，train 共 120 题；没有单独 entry_point 字段。开发适配只读取 prompt，并在离线准备时从公开训练断言的 AST 提取函数接口：对各断言的 Name 型调用取交集，去掉 Python 内置函数及 test_imports 中的导入名；只保留恰好一个共同函数名且位置参数个数一致、无星号展开的题。向 prompt 附加所需函数名和位置参数个数，填写 PublicTask.entry_point；不传断言值、预期输出、断言正文、参考 code 或 imports。接口无法唯一确定的题记适配不支持，按哈希排序顺延替换，并保存替换清单；不足 50 题则报告实际可用数，不能读取参考代码补接口。此处使用的是公开训练题的接口元数据，正式 HumanEval 仅用其原公开 prompt/entry_point，不从隐藏测试推导接口。

开发题和正式题先做规范化题面重复核查，重叠项从开发集顺延替换。近重复及训练污染不能靠哈希完全排除，记录检查方式和限制。

任务 id 固定规则：GSM8K 使用 `gsm8k/train/{冻结数据零基行号}`；MBPP 使用 `mbpp/train/{原整数task_id}`；MATH-500 保留 unique_id；HumanEval 保留原 task_id。哈希选题使用此规范 id，题面去重使用 Unicode NFKC 后合并空白的字符串，不用答案或最终得分。MBPP 开发评分是在同一隔离环境执行该训练题的官方 test_imports/test_list，全部断言通过记成功；它不是 HumanEval+ 或 MBPP+ 正式分数，也不向运行过程返回结果。

选择这些任务是可复用、可判分、能承载候选机制的设计判断，不代表已观察到互补或普遍失效。开发任务和正式任务存在分布差异，正式结果为负时需考虑这种适配问题。

## 3. 模型、成员与生成配置

- 第一套配置：A0/A1/A2 均为 `Qwen/Qwen3-32B`，独立上下文；A0 为主解题者，A1/A2 切换帮助与检查。无专门训练、离线角色搜索或能力路由训练。
- 显式 `enable_thinking=false`；temperature=0.7、top_p=0.8、top_k=20、min_p=0，依据 S12 非思考模式建议。若服务不支持这些字段，不能静默忽略：切换到可验证支持的服务，或在开发阶段重新冻结并如实说明配置。
- 输出上限：draft 2048、review 1024、contribution 1536、lead_update 3072、final 2048 tokens。它们是初版工程上限，非官方推荐最优推理长度。开发时检查截断率与格式失败；过高则调整所有相关条件的对应上限后重新冻结，不在正式题上调。
- 输入上限 24,576 tokens；固定 tokenizer 与 chat template，按方法规格裁剪过期请求包并记录。
- 三次完整重复，logical seeds = 17/29/43。实际调用种子由 task_id、重复、成员、阶段和序号确定；初稿不含方法名，以便共享。供应商不支持 seed 时记录不支持，使用独立重复，不声称精确复现。
- 每个题目×重复先生成 R0 三初稿银行并冻结。所有多 Agent 条件使用同一银行；单体使用 A0 的那份。正式方法调用顺序按 task_id 的哈希确定并交错，避免整组方法对应不同服务时段。
- Finalizer 模型、模板和参数相同，输入包体现各条件实际产生的信息。保存 Finalizer 前后的 artifact，区分协作工作与末端重解。

服务地址、模型 revision、tokenizer revision、量化/部署后端、包版本与可用上下文为实施时运行清单必填项，当前不猜测其可用性。不下载权重或假定已有 GPU。选此固定模型旨在第一版可比较性，不作为最新最强主张。

## 4. 三块核心实验

### B1：整体能力主结果（必需）

| 条件 | 操作 | 正常模型调用上界 |
|---|---|---:|
| Single-finalized | A0 初稿→共同 Finalizer；另报原始初稿得分 | 2 |
| Solo-refine | A0 初稿→两次自行修正→共同 Finalizer，无同伴内容 | 4 |
| Independent-aggregate | 三初稿→共同 Finalizer，可自然补全和重解 | 4 |
| Static-debate | 三初稿→两次同步全员交流更新→共同 Finalizer | 10 |
| CoReTA | 三初稿→固定初审→A0 更新决策→最多两轮定向协作→共同 Finalizer | 12 |

三类基线家族为单体/反思、独立聚合、静态交流。Independent-aggregate 是 MoA-style 简化变体；Static-debate 为 S4 启发的受控适配，不冒充原文模型及提示完全复现。所有条件同题面、同底座、同可用工具；不要求实际调用/成本相等，主结论首先是架构表现。

正式评价：MATH-500 全 500 题 + HumanEval 全 164 题，每题每条件 3 次完整重复。主比较为 CoReTA vs Static-debate，Independent-aggregate 与 Solo-refine 为必要解释参考。均值、差值和区间全部报告；不能因只赢 Single 就称为协作架构优势。

成功证据：主比较的配对提升具有稳定方向且区间能支持正收益，至少一个任务明确成立；若只在一个任务成立，限于该任务表述。两任务都提升才可作跨数学/代码的较宽描述。零或负结果如实报告；高方差、天花板或小样本敏感性均可导致证据不足，不能强行归入成功/失败。

主表分别给数学准确率、HumanEval 原测试 pass@1、HumanEval+ pass@1，另给错误率、截断率、调用与资源记录。代码主指标为增强测试 pass@1，原测试是辅助指标，不计作独立主假设。

### B2：组织机制对照（互补解释必需）

在正式评价前，按 `sha256("coreta-mechanism-v1|" + task_id)` 预选每个任务族各 100 题，三个重复；不依最终成功、初稿分歧或是否求助选择样本。若任务少于 100 则全取，此处 HumanEval 为 164，足够预选。

- Generic-help：保留主解题者、动作选择策略、角色、初审与整合；将发送给帮助者的具体请求替换为通用审查/补全要求。检查者和后续主解题者只能读取实际通用请求。原定向字段不通过历史 Decision、raw trace 等路径泄漏回去。后续动作基于本变体自己的状态，不强制重放原 CoReTA 轨迹的时机或收件人。调用机会和上限保持，记录实际次数。
- No-application-record：保留候选更新、贡献和检查，去掉显式 Application 载荷与对应历史提示；主解题者仍能自然评估贡献。该对照检验显式登记与反馈提示的增量，不代表完全移除内部反馈。
- CoReTA 对应轨迹复用 B1，仍按部署口径计入成本；采用同题同 R0 配对。初审步骤在两个变体中都保留，因此它们有助排查收益是否仅来自固定初审。

变化同时可能影响提示负担、内容选择与时序，不将分数差唯一归因于一个抽象心理机制。不为了“删模块”直接砍掉其他条件可用的调用额度。

初审解释的条件：只有完整方法相对保留初审的 B2 变体有明确增益时，才有证据反对“差异完全来自共同初审”。若 B1 提升而 B2 无明确差异，结论限于整体协议有收益，不能认定定向请求或显式应用记录是收益来源，也不能估计初审的独立贡献；无明确差异不等于两个方法等效。若后续确需定位共同前缀之后的增量，可另行预定“三初稿→同一初审→A0更新→Finalizer”开发诊断；它估计继续协作的整体增量，仍混合额外调用与内容作用。本轮不自动新增该运行或扩大正式实验矩阵。

No-application-record 的完整英文阶段模板、输入白名单及 application=null 的专用输出约束见 [PROMPTS.md](../design/v0.3/PROMPTS.md)；实现时不得只删除历史变量而留下普通模板的应用记录要求。

### B3：贡献内容的下游作用（互补解释必需）

从 B2 预选集合再次按独立前缀 `coreta-content-v1` 预选每任务族 50 题，三个重复，共 300 条指定轨迹。目标位置为该轨迹第一个实际 HELP 或 ALTERNATIVE 的 provided 贡献；资格在最终结果前确定。没有该事件的轨迹记 no_eligible_help，整体意向分析中差值记 0，并单报资格比例。

在贡献到达、检查和应用尚未发生的时点保存状态，比较原贡献后续与冗余贡献后续。冗余版本按请求目标，从已有候选对应步骤提取/复述现有内容，尽量保持主题、格式、长度（目标 token 长度 ±20%），不添加新事实、错误答案或新建议，来源角色标签保持不变。无法得到合格冗余文本的实例记 intervention_unavailable 并单列，不用空白文本悄悄代替。

替换对象为整个 Contribution：body 按下述提取规则重建；basis_refs 仅指向分支前已有候选/初稿；check_suggestion 固定为“Check this restatement against the public task”；status 保持 provided；request_id 绑定同一前缀请求。不得保留原贡献特有的建议、引用或元数据。冗余分支使用自己的 run_id 和新贡献事件 id，只复制到请求为止的共同前缀；REFERENCE_INDEX、后续 Review.subject_id 和 Application.contribution_id 均绑定新贡献事件。原贡献、其检查、应用、后续动作及 Finalizer 输出不进入分支视图或历史。

默认冗余构造不用额外模型或隐藏真值：先按请求 target_step_ids 收集当前候选对应步骤，再按原步骤顺序补充其他现有步骤及 summary，逐段拼接到不超过原贡献 token 长度的 120%；不新增、重复填充或改写原有论证。实际长度不足 80% 时标记 length_unmatched，保留该分支，同时单报长度接近子集。若没有可取内容则标记 intervention_unavailable。这种替换仍有连贯性与长度混杂，因此只作为内容依赖诊断。分支的检查者、接收者及 Finalizer 均只读取分支自身事件，检查与应用后续重新运行。仅替换检查后或已应用后的内容会泄漏原结果，禁止。

原始支路可复用 B1 自然轨迹，冗余支路按同一逻辑随机种子继续，提示变化不保证同随机轨迹。记录可构造配对样本的最终结果差、A0 接收后候选变化、拒绝/未决/采纳及 Finalizer 前后变化。无合格帮助的 no_eligible_help 可按预定政策差值记零；intervention_unavailable 缺失替代分支结果，不能当零或静默排除。

对预选的 N 条轨迹设可观察差值总和为 S（含无合格帮助的零差值）、缺失干预数为 U，则总体平均差值只报告保守界限 [(S-U)/N, (S+U)/N]，因为二元成功差值在 [-1,1]。另报可构造配对总体的平均差、资格率和可构造率；只有 U=0 才直接给完整总体点估计。成功/失败案例都保留。解释为指定贡献内容对后续过程的作用，不称为纯自然间接效应或完整互补分解。

## 5. 指标及人工核对

### 5.1 自动指标

- 最终任务成功率及 Finalizer 前当前候选成功率，使用同一末端评分。
- 三份初稿至少一份正确的覆盖率、A0 初始正确保留率、A0 初始错误纠正率、初始三份全错后的最终成功率；分母和样本数明确。
- 合法请求率、无法帮助率、提供贡献率、采纳/拒绝/未决比例、重复请求和协议故障率。它们是行为指标，不能单独当作协调质量。
- 自报 resolved 仅作记录，不作为真实问题解决率。其与最终成功一致性另报。
- 每题调用、tokens、格式修复、可能计费的失败、时延及已知费用，记录物理实验成本与部署口径成本。R0 缓存减少实际研究调用，但不是方法免费初稿。

数学得分主要评价最终答案，代码通过测试不保证一般程序正确。既不能以引用某成员判定因果使用，也不能把 initial-all-wrong success 当作能力上界被突破的充分证据。

### 5.2 离线贡献核对

预选各 30 题、只用重复 17，共 60 条轨迹，包括无求助轨迹。对首个帮助事件逐项核对：是否相对已有输入增加可辨认内容；依据是否支持/存在缺陷/无法判断；接收者有没有可见应用；后续任务是否成功。第一轮仅给公开任务与匿名化轨迹，提交贡献/应用判断后，第二轮才解盲参考解和测试结果，必要时补充修订理由并保留前后标注；这些离线信息不得反馈给生成过程。

评分者看不到方法名称和最终成功标签，先判贡献与应用；再解盲结果分析。若资源允许两人独立标注后报告一致性；只有一人时如实标单人探索性分析，不假装已获得双人认证。该核对补充 B3，不能替代受控结果。

贡献类型按 [离线标注规则与空表](../design/v0.3/CONTRIBUTION_ANNOTATION.md) 记录，至少区分已有完整答案的选择/保留、协作中新完整解的采用、局部贡献与既有内容联合补全，以及无法判断。分类基于可见文本而非角色、自报采纳或最终正确性；完整替代解是允许的有效协作行为，但不能自动计作局部互补组合。

60条轨迹明确从 B3 预选集合中，各任务族按独立前缀 `coreta-annotation-v1|task_id` 的 SHA256 排序取30题，只取重复17；先于结果和求助资格固定，因此保留无帮助轨迹。标注主对象与 B3 一致，为首个 HELP/ALTERNATIVE 的 provided 贡献；若只有 cannot_help，则保留该过程并记无合格贡献，不以之后更成功的事件替代。后续如发生不同类型的应用可另记次级事件，主对象不变。

将类型与 B3 配对差、接收后候选及最终结果交叉报告，但仅在这60条已标注轨迹内作探索性分层，列清无合格帮助、缺失干预、无法判断和每类样本数；不将人工类型外推给全部300条，也不称其为随机分配的机制类型或纯因果分解。类型重叠时明确分母，不汇总成互斥百分比。三初稿全错后成功、引用某成员、或冗余替换后下降，均不能单独证明局部能力互补。

## 6. 统计与数据使用

题目为基本单位：先对同题的三个独立完整重复求平均，再对方法差进行题目级配对 bootstrap，10,000 次，报告均值差及 95% 区间。代码两个测试集同题相关，不能当两倍独立样本。若使用显著性判决，对数学准确率、HumanEval+ pass@1 两个预定主比较作 Holm 校正；探索性分层和机制分析标清。

正式题不按初稿正确性、分歧、是否适合互补来筛。标签只用于事后预定分层。164 道代码题可能使区间较宽，不用重复种子冒充新增独立任务；不保证当前样本量能检测小收益。

每个计划实例都进入运行记录。协议错误使用预定 fallback 并按最终输出评分，空输出计错，同时报告故障率。基础设施共同故障按固定重试处理，补跑只能由运行状态触发，不能由分数触发；残留失败主分析保守计失败，再给完整配对敏感性分析。评分器自身故障与方法错误分开。

## 7. 执行顺序与规模

| 步骤 | 内容 | 进入后续的依据 |
|---|---|---|
| E0 实现核查 | 契约解析、引用、状态转移、信息隔离、评分适配；使用构造记录和开发题 | 关键路径按规格运行，格式/评价故障能定位；这不是效果证据 |
| E1 开发试点 | 各 10 开发题、种子 17；Independent、Static、CoReTA | 检查交互是否实际发生、截断/格式错误及评分问题，修订后冻结；不以必须正收益作为继续条件 |
| E2 数学主评价 | MATH-500 全集，5 条件，3 重复 | 完成比较并定位失败，先得一份完整结果 |
| E3 代码主评价 | HumanEval/增强测试全 164 题，同条件重复 | 检验第二任务类型与边界 |
| E4 机制分析 | B2 各族100题、B3各族50题及离线核对 | 根据预定方案区分主效用与机制证据 |

E2/E3 的设计预先冻结，不根据 E2 测试分数修改提示再宣称 E3 是同一冻结方法。若确需修订，升级版本、说明已见数据，并重新安排独立评价。

E1 三条件正常调用上界每题 4+10+12=26，共 520 次（按每条件独立部署计）；初稿复用可降低物理请求。E2/E3 共 664×3=1,992 个题目重复，五条件正常调用上界为每实例 32，共 63,744 次。初稿银行只物理生成一次时，上界约 47,808 次；成本表两种口径同时保留。

B2 两个变体共 200×3×24=14,400 次正常调用上界，原 CoReTA 不重复生成。B3 冗余支路最多六个后续调用，300×6=1,800；默认冗余提取不新增生成调用，如额外重跑原支路则另计。所有上界未含结构修复与网络重试，实际早停可减少。整体按阶段执行，不一次性提交大批次。

GPU/费用/工时不凭空估算：本方案走已有或租用的模型端点；单次平均延迟与 token 用量由 E1 记录。阶段费用按实际价格和输入输出估算，时长按调用时延与允许并发估计。尚无端点、价格或预算信息，本轮不生成金额承诺，也未授权任何调用。任何真实付费阶段须按明确批次和资源范围安排。

## 8. 扩展项与负结果解释

必要扩展取决于主张：若声称异构专长利用，必须加入预先固定且经开发资料描述的异构成员池，并与强成员单独执行及同模型团队比较；若声称更强模型普遍有效，需新增底座重复。它们不自动由当前同模型结果推出。

若整体提升而 B2/B3 不支持，结论限于整体协议有效。若只纠正初始选择或靠 Finalizer 重解，应相应调整机制解释。若全流程没有优势，分析是否需求识别、贡献质量、检查或整合失效；不凭单轮结果直接宣布宽方向无效，也不靠增加有利子集掩盖结果。

同成本曲线、更多人数、训练路由、大型软件/网页任务、复杂记忆与效率贡献为后续可选研究，不进入本轮实现必需项。
