# OBSERVE 重复字段故障复核

## 观测到的事实

- 中断发生在 `hb-dev-006-r1 / ground_full_public_v1 / OBSERVE`，不是 GROUND 阶段。响应 JSON 中 `offer.target` 在对象开头和末尾各出现一次，两个值完全相同。
- 当前 OBSERVE schema 只定义一个 `target`。请求没有被截断：模型输出 1,038 tokens，低于该阶段 2,048 token 上限；原响应和请求均保存在批次日志。
- Gateway 对重复键采取严格拒绝，且该版本的格式重试数为 0，因此这一调用抛出 `SCHEMA_ERROR` 并触发批次停机。
- 同一响应的解释较长，claims 与 knowledge、support、proposed_use 有内容重叠。这是可见的冗余，但单个样本不足以证明冗余导致重复键。

## 修正范围

新执行版本只对完全相同的重复 JSON 字段值作确定性折叠。这样处理不会在字段值之间作语义选择。若重复字段值不同，或 JSON、schema、动作校验仍有其他错误，执行器继续拒绝并停止。该过程不再次请求模型、不更改有效字段内容，也不增加网络请求预算。

每次折叠写入 `format_repairs.jsonl`，记录阶段、字段名、策略和原始响应哈希；原始响应仍由 `responses.jsonl` 保留，成功阶段记录 repair 数。批次进度另计格式修正数。

## 研究与实验边界

旧先行批次维持 `stopped_on_first_technical_error`，不回填修复、不把 006 计入结果，也不续跑旧 manifest。修改后的准备件使用新 manifest 和新目录；它只改执行容错，不改变协作机制、提示内容、方法对照、任务或评分。

这项修正只覆盖“重复键且重复值完全一致”的格式问题。它不能保证修复截断、缺字段、无效引用、内容错误或服务端结构化输出不兼容。新版本的本地脚本传输可以验证处理行为；是否在新 API 响应中遇到及修复该故障，须在独立授权的新批次中观察。
