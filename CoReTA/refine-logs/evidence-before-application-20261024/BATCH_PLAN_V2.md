# 三组完整开发对照 v2

沿用BATCH_PLAN.md的005/006/007/008、两次重复、三方法和官方选项评分。v2补充执行器与逐题评分参考，不更改架构、任务、金标或预算。完整上限520请求、1337344输出token；实际费用另计输入和输出，尚未发生API费用。

阶段一固定005-r1与006-r1，共130请求；阶段二为其余6个配对单位，共390请求。执行器每次必须显式选择阶段；阶段二要求同一manifest哈希、阶段一完成且两题三组技术上齐全的记录。只按技术完成情况推进。若根据结果改方法，关闭本版本，后续作为新开发批次，不能合并比较。

每题每重复独立生成成员初答后，三组共享相同cache哈希，各自后续隔离。初答payload与冻结件逐字匹配，源码、资料、配置、评分参考和提示均核验。零重试/修复，首个技术错误停批，已完成和失败内容保留，禁止覆盖输出或静默恢复。未知usage阻止继续。单组与全阶段均有请求及输出预算。

005是多目标招聘权衡；006未明确特质等权；007完整资料下无人满足全部a-j，重叠报告不能重复计数；008部分时间/路线不能作确定排除。官方exact-match照原金标计算，不能把不同选择自动标作事实错误。过程标注使用独立OFFLINE_PROCESS_REFERENCE.json：逐题公共/私有原文及行号、推断边界、去重和应用判据。参考表只用于离线评分，不进入任何成员packet。其全部原句不是全部都必须使用，主张单元须保留对象、关系和条件，合取推导可关联多个原文位置。

三组过程统一标注：主张支持状态、出现位置、实际应用前后、最终保留、错误机会是否存在、是否识别及应用中新错误。缺机会记N/A，歧义记uncertain；无claims字段的普通讨论仍按实际论点标注。支持的知识能构成有用贡献，不要求贡献者自己完成修复。识别错误、修正应用和保留正确结果分别报告。

固定过程汇总：每条轨迹分别列出有依据且实际使用的不同主张数、进入终稿的无依据/矛盾主张数、应用新增错误数，以及错误机会→识别→正确应用→最终保留的逐例链条。重复出现只计一个主张；uncertain单列。可补充条件比例，但分母为本轨迹实际机会，不能把三组不同机会的比例当作同难度能力比较。未完成的人工标注保留为空，不自动计0。最终选项与成员初答的官方评分由脚本独立导出；过程结果须有原文定位支持。

score_grounded_batch.py导出24个固定团队结果位置、缺失/中断、官方exact-match和全过程证据。方法匿名ID只减少直接标签，轨迹结构仍可揭示方法；不得称严格盲评。人工标注留原句位置和不确定性，不由模型自报approved取代判断。脚本不自动赋予语义分，也不因schema通过推断正确。

工程验证采用禁止网络的真实Gateway与脚本传输，覆盖三人/四人Choice完整流程、批预算与跨组cache、异常首错停批及输入上限。长历史检查是选定压力输入的本地容量探测，不能保证所有真实后续永不超长；客户端每次请求仍执行32768输入上限检查，超长停批、不强行截断。API服务兼容只能在获准运行后观察。

本版本可供审阅与本地验证，启动API须依据本批具体数据、目的地和请求上限的授权；不复用旧诊断许可。
