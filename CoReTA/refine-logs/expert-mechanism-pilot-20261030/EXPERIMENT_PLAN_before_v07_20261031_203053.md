# 专家优势与团队协作：当前执行计划 v0.6

2026-10-31。**当前处于首个实验设置准备阶段；本轮尚无已训练专家、独立能力校准或真实团队结果。** 本页替代旧v0.5作为现行入口，旧版本保留。研究问题和任务方向未变，收敛的是执行组织。

## 1. 我们究竟要知道什么

多智能体团队为何有时不能利用具有真实任务优势的成员，甚至损害其判断；哪些过程能保留有效贡献并实现有益纠错？MuSiQue/Qwen/LoRA是首个实证设置，不是研究命题本身，也不要求每题必须严格几跳。

先构造并校准任务优势，再观察普通团队的实际损益，之后才按证据选择干预。旧H1来源可核对性、H2收到信息后的判断落实仍是候选；分享/理解/应用/整合是核读位置，不是新增必跑原因实验。

## 2. 唯一当前待办：最小任务训练执行流程

目标是让已备训练数据能够正确接入一个任务adapter训练流程，避免拿到机器后才发现模板、loss或保存加载问题。优先复用现有库，不搭训练平台，不引入协作训练。

完成条件：
1. 明确读取1796题修订候选及原V200，展示实际system/user/assistant边界，评分标签不进入生成式验证输入。
2. 检查loss只作用于assistant监督，输入资料与padding不被误作目标；没有截断掉监督或关键资料的静默处理。
3. 检查一个adapter的保存/加载与基础模型对应关系；仅CPU小型fixture时明确其不证明Qwen实机兼容/能力。
4. 对实际聊天模板完整输入/目标显式检查长度；实际显存、步耗时、精度和费用等依真实后端短步验收，不提前保证。

本轮审核没有启动这项实现。离线流程验收完成后，有资源再短步训练验收；无资源如实报告依赖，不继续扩数据审核来填补等待。

## 4. 专家构造与资格

同一个具备对话能力的Qwen起点B；E为B加一个任务LoRA，普通成员为B的独立会话，不需要先训练四个模型。4B/8B、版本和精度依真实资源决定，4090未落实。先答案/支持编号任务SFT，不加协作训练、RL、大规模CoT生成或超参网格；最多两次主要训练尝试，V选模后C核验。

期望独立答案EM差5–10个百分点，非统一资格线、不要求每题/每跳数都赢。报告配对差与关联不确定性，区分答案、格式、引用和解释/回应能力；证据不足如实标记，不以“训练过”当专家。

## 5. 能力成立后，才做普通团队比较

四独答→分享冻结初答→四轮随机顺序、每人一次、即时广播→四人私有终答。公开消息自然语言，初答/终答按评分格式；不因共识提前停止。专家身份主条件公开是助手建议，当前仍须在运行配置中明确披露条件、actor、seed、投票规则和模型参数，不冒称用户已逐项选择。

必要读数：E初答、四初答直接聚合、普通团队终答、E无消息4次重思+终答；另保留所有成员终答和收件。无消息复用同E初答，仅匹配E自己的额外生成机会，不称等全队总算力。最高票/均匀平票适配已有显式实现候选，不用gold别名合票，随机选择与期望评分分开。

分别看团队是否低于E初答、讨论是否优于初答投票、E相对无消息是否更易改错，也报告E初错得到纠正。答案一致率不代表实际采用，轨迹相关不唯一识别从众。先核实际过程，再挑最多1–2项干预。
