# 按需互助架构：定向原始文献核查

检索日：2026-10-18。研究问题：不全知控制器怎样发现具体瓶颈、发给谁、要求什么；怎样利用成员的局部互补性而不是把所有预算交给固定最强者。目标为无需离线策略训练的架构设计，不是 benchmark 提案。两轮窄搜，六篇 primary 定点核验，未跑实验或代码。沿用 deep-research 的问题冻结、primary 核验和机制对照原则，按委托限制不扩为全面综述。阅读级别均为正文方法定点阅读；不能等同完整复现或创新性认证。

## 先给设计判断

三个不同决策不可混为一个 router：**发现“当前哪一步缺什么”→让潜在帮助者暴露“我具体能补什么”→核验这项帮助是否解除瓶颈。** AgentAsk 已直接做 when/what/whom/how，但靠训练控制器；blackboard 已明确允许主代理不知道谁知道什么、帮助者自行响应；LASE 已做无参数训练的按需升级；contract-net 已有局部状态、出价、撤回、预算及可行性检查。这些都能借鉴，动态求助本身不能作为首次贡献。

现有结果没有使“所有剩余预算交固定最强者”在一般任务上必然次优。互补收益最清楚的来源是不同私有信息、工具/数据访问权或可实测操作能力；若所有成员掌握同样信息、最强模型同时最擅长诊断与执行且价格允许，单强者可能是最优。架构需要识别并利用**局部可交付能力**，不能仅靠 persona 制造互补性。

## 六篇机制对照

### 1. AgentAsk — Lin et al.，ACL 2026；arXiv:2510.07593v2，2026-01-19

Primary：[正文及附录 A](https://arxiv.org/html/2510.07593v2)；[ACL PDF](https://aclanthology.org/2026.acl-long.1294.pdf)。已读 §3–4、A.1–A.2。

- **真实操作**：每个交接边观察 `(子目标, 发送者, 接收者, 消息, 近期局部上下文)`，输出 `(是否问, 被问者, 短问题)`。四类风险为数据缺口、信号损坏、指代漂移、能力缺口；向上游补字段/核来源，或向适合同行求指导。局部干预后才放行原流程。
- **训练分类**：强 teacher 从执行日志构造示范→SFT→E-GRPO；属于离线控制策略训练，不满足目标限制。可用现成强 LLM 作 clarifier 是推理替代方案，不能把训练版成本或效果直接迁移过去。
- **黑盒可行性**：被协作成员可以是黑盒；复现其学习控制器需要可训练模型。prompt-only clarifier 可黑盒实现，但这是我们的变体。
- **可借操作**：把求助锚在具体交接边，显式编码“缺什么—问谁—要什么最短回复”，避免重开全体讨论。
- **未解限制**：主要固定原编排后修边，不是一般在线构建互补合作计划；控制器仍需从不完整上下文认出问题，能力缺口的存在不自动告诉它正确帮助者。

### 2. LASE — Yoa et al.，ICML 2026 / PMLR 306；arXiv:2610.16343v1，2026-10-12

Primary：[PMLR](https://proceedings.mlr.press/v306/yoa26a.html)；[方法 §3、附录 A/B/F](https://arxiv.org/html/2610.16343v1)。会议出版在 2026 年中，不应把十月 arXiv 上传当首次发表。

- **真实操作**：leader 先独解；答案 span 最小 token logprob 或最大熵越阈值才触发。依次低成本 adversarial check→support→可选 expert，每次只跟一人交互，leader 更新后重新检查并早停。
- **训练分类**：测试时阈值策略，无需策略权重训练；附录报告阈值 sweep。无训练不等于无配置/无验证调参。
- **黑盒可行性**：要有 token 概率信息；纯文本 API 不能原样实现。口头置信或多采样分歧能作替代，但须重新验证。
- **可借操作**：分阶段升级、每次只获取一项反馈、帮助后立即检查是否应停止。
- **未解限制**：不确定性是触发信号，不能定位具体推理缺口；leader 承担综合及最终权威，文中 peer 索引本身不构成在线能力发现算法。理论改进依赖正确 seed、条件放大及无 seed 时保守性，不能当无条件保证。

### 3. LLM-Based Multi-Agent Blackboard System for Information Discovery in Data Science — Salemi et al.，arXiv:2510.01285v2

Primary：[§3、案例附录 E](https://arxiv.org/html/2510.01285v2)。本轮未独立确认正式录用状态；检索到 OpenReview 页面不能代替录用核验。

- **真实操作**：主代理 ReAct，可规划、推理、执行代码或 requesting help；将所需信息发到共享板，不指定收件者。各 file agent 掌握不同文件簇，search agent 能联网，自行判断能否贡献。回复放独立 response board，仅主代理可见，防止帮助者相互影响。
- **训练分类**：prompt/工具编排，无该架构专属策略训练；文件聚类是预处理（默认 LLM 看文件名），不是学控制策略。
- **黑盒可行性**：可；信息、工具访问权和分区状态使成员有真实互补性。
- **可借操作**：不知道“谁知道”时发目标型请求，让局部持有者认领；回复独立，保留拒答；空响应时改写请求或自行取证。
- **未解限制**：主代理仍须说清自己缺什么并决定采用谁；所有 helper 监看请求带来随成员数增长的筛查成本；自选响应不保证准确。数据发现专长不直接等于一般数学推理能力匹配。

### 4. MasRouter — Yue et al.，arXiv:2502.11133

Primary：[§3–4、附录 D.2/E](https://arxiv.org/html/2502.11133)。作为训练路由的明确对照保留较早工作；不把它伪装成近六月新作。

- **真实操作**：输入 query，经级联网络选协作模式、逐步角色分配、每角色底层 LLM；以执行质量和成本共同优化选择模块，支持异构模型池。
- **训练分类**：需要专属 controller 训练；基础 LLM 可冻结，仍不是“无需离线策略训练”。
- **黑盒可行性**：执行端可以黑盒 API；路由网络另训。
- **可借操作**：成本目标应分解到“谁做哪个角色”，而非给每个 Agent 一个固定全局分数；角色、模型、人数是不同预算旋钮。
- **未解限制**：主要 query 条件下配置整套 MAS，不自动跟踪执行中突然暴露的具体瓶颈；预定义角色和 profile 不等于当场验证过的能力。适合作强学习近邻，但不能直接满足本方案限制。

### 5. LLM-X — Lorenzoni, Alencar & Cowan，arXiv:2605.11376，2026-05-12

Primary：[§3–4](https://arxiv.org/html/2605.11376)；[元数据](https://arxiv.org/abs/2605.11376)声明 accepted at AGENT 2026 Workshop，co-located with ICSE 2026。

- **真实操作**：发起者 CFP→承包者 Offer→Accept/Reject→Ack；能力协商、typed JSON、deadline/TTL、scope、消息重试。policy 决定等第一项、有限候选或全体候选。
- **训练分类**：协议/规则，无专属策略训练。
- **黑盒可行性**：协议可包黑盒 API，但**实验代理是 Python wrappers / scripted payloads**；不能称已实证 LLM 互补推理或能力识别。
- **可借操作**：区分“申请能力声明”和“批准执行”；bounded collection 避免等待所有成员；求助有明确生命周期。
- **未解限制**：是通信基建证据，不解决怎样发现未知推理瓶颈或判断真实胜任度。正文 §3.2 与 §4.1 对 Low/Medium policy 的先到/超时表述还有不一致，因此不据其 policy 名称推导效果。

### 6. MAS-DecStream / LLM-MR-CNP — Lajili & Brahmi，arXiv:2608.12371（2026 年夏季预印本）

Primary：[§IV–V](https://arxiv.org/html/2608.12371)；[元数据](https://arxiv.org/abs/2608.12371)列提交日 2026-07-19，与编号月份不协调，故保留此元数据异常；属于近六月范围。

- **真实操作**：本地资源/QoS 压力触发求助；候选先查自己 telemetry 和工具，回复 propose/refuse 及约束原因。无法选定时仅向未决候选渐进披露上下文，允许修订/撤回；最后按确定性可行性与 utility 决定，并保留资源防超订。
- **训练分类**：提示及确定性工具检查，无策略权重训练；few-shot 有通用示例，不能称完全零先验。
- **黑盒可行性**：可，文中用 API/local models；最多三轮并逐步缩小候选。
- **可借操作**：让“我能帮助”附可检查的局部状态；只针对导致未决的字段再次询问；候选承诺可撤回，已分配预算应占用和释放。
- **未解限制**：硬资源可测，通用认知专长不可如此直接测；不能把可行性 checker 原样迁移成真理 checker。作者明确其管线对照同时改变定性上下文访问和 LLM 使用，不是 LLM 单因素因果证据。

## 面向新架构的可执行组合（推导建议，不是文献已验证结果）

建议以**局部求助契约**为控制单位，而非每轮全员作答。一个契约至少包含：受阻子目标、当前状态与已有产物、观测到的失败/缺失、希望获得的交付物、允许上下文范围、最大调用/工具成本、验收动作、超时与终止条件。交付物可以是缺失事实、候选构造、最小反例、工具执行、证明一步、定位日志，不必强制统一成主张证书。

1. **产生求助**：执行者遇工具失败、前置输入缺失、重复无进展或互不兼容的局部结果时提交契约。轻量守门人可查结构缺失/依赖未满足；认知缺口还要允许执行者和旁观者独立提报。没有规则能保证发现所有“自信但错误”，因此保留少量独立检查配额。
2. **发现候选**：已知能力目录先定向给少量候选；目录不能覆盖时采用 blackboard 的窄范围广播。候选只交短 proposal：能补的具体部分、依据/可访问资源、预期成本、需要的最小额外上下文、拒答边界。此时不让每个人完整解题。
3. **选择操作**：选择低成本且有可检查交付的候选；先买一个有边界的 help action，再判断瓶颈是否解除。为避免“最强者名望统治”，排序依局部交付与可验证资源，不依据全局排行榜。仅凭自报能力仍不足，需要工具可行性、一次小型可核验产物或历史有效帮助记录。
4. **续作与撤回**：接受交付→更新受影响状态→原执行者继续；验证失败只撤该交付和依赖项，不重开全体。未决时按 contract-net 补一个字段或换一个候选；超过预算才升级强者、重构子目标或保留失败。

这里真正值得发展的算法部件是：**不完备状态下形成足够具体的求助契约、用小成本 probe 识别局部补充能力、把实际解除瓶颈的结果反馈给下一次请求选择**。在线记录/计数不等于离线策略训练；若采用 bandit 或在线更新，应明确其冷启动与探索成本，而不能把学习成本隐去。是否值得采用主张级补全、证书、局部权限，应由任务交付和可验证性决定，本轮文献不要求预选它。

## 可收窄的研究空位

可以主张研究“无需离线控制训练、在不全知能力目录下的执行中互补求助”，但不能仅凭本轮称已有工作从未实现组合。与最近邻的实质对照是：对 AgentAsk 去掉离线 teacher/SFT/RL 后怎样维持诊断；对 blackboard 怎样避免全员筛查和自选失准；对 LASE 怎样从置信触发推进到具体缺口与具体帮助者；对 MasRouter 怎样应对执行中能力切换；对 CNP 怎样用可观察交付而非自报认知置信约束出价。这个空位足以支持继续做架构，不需要因为存在动态近邻而放弃。

## 检索边界

第一轮：AgentAsk、LASE、LLM blackboard/contract-net。第二轮：对应正文的训练方式、能力自选、typed offer、可行性验证及 MasRouter 对照。近六月主要补到 LASE、LLM-X、MAS-DecStream；AgentAsk 与 blackboard 是点名核心，MasRouter 是必要训练对照。未无限扩展，未核代码实现、未穷尽历史 distributed problem solving。已有 [AGENT_PRIOR.md](../expertise-human-transfer-20261018/AGENT_PRIOR.md) 的 SAT 提醒仍有效：无需更新基础模型权重的离线策略搜索也违反“不要离线策略训练/搜索”的严格版本，不能仅称 training-free 就纳入。其证书/具名缺陷等亦不能作为首次。
