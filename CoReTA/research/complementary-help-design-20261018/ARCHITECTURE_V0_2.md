# CoReTA 架构 v0.2：讨论复审后的设计边界

日期：2026-10-18。继承 v0.1 的主线和组成，修订语义决策、修改规则与实验对照。工作名：Complementary Reasoning through Targeted Assistance。尚未实现、运行或证明效果；两个帮助周期仍为原型上限，不是经验最优。本文没有新增付费采样授权或实验协议。

## 1. 目标和组成不变

目标：以有边界的互补贡献，减少正确知识在协作中的损失，并提高完整任务表现。互补是待验证机制，不是初始答案不同就自动成立。

三个执行 Agent、共享工作记录、程序调度器及统一可用工具。主解题者由预先配置或独立开发集选择，在同一配对对照中固定。其他两名成员可交换帮助/检查职责。校准路由不进入当前主版本：若后续加入，应两侧共同使用或单独作为研究因子。

## 2. 谁作什么决策

| 决策 | 执行者 | 依据和边界 |
|---|---|---|
| 提出当前方案及未解决步骤 | 当前主解题者，允许其他成员提出具体异议 | 任务、独立初稿、实际推导及工具结果；不是隐藏答案 |
| 选择下一步动作 | 主解题者在正常回复中输出有限动作及理由 | CONTINUE_SELF、REQUEST_HELP、REQUEST_CHECK、REQUEST_ALTERNATIVE、FINISH；该调用计预算 |
| 指定帮助者 | 主解题者选择另一成员，并引用其已有相关支点或开发集能力线索 | 不假定最优，不免费预测净收益；无可靠线索时允许拒绝求助/尝试替代解 |
| 检查请求和执行动作 | 程序调度器 | 仅检查字段、引用、剩余预算、轮次、重复请求及合法角色，不负责判断推理真伪 |
| 内容检查 | 统一可用工具优先，必要时由非贡献提出者的成员审查 | 同一模型家族或共享信息可能造成相关错误；角色分离不等于统计独立或形式证明 |
| 应用贡献并更新方案 | 主解题者 | 展示对应步骤前后的变化；允许拒绝、保留未决或采纳，不自动信任求助结果 |

第一版不另加学习路由、全知裁判或复杂信誉系统。主解题者的语义选择是本架构要被评估的一部分，不是预先已解决的前提。

## 3. 工作循环

1. 三名成员独立提交初稿、关键依据、可见未完成步骤，保存原始输出。
2. 主解题者形成当前方案，选择正常继续、定向请求、独立检查、替代解或结束。
3. 请求包括目标步骤、实际尝试、可见问题、希望获得的交付、必要上下文和可执行检查计划。
4. 一名相关成员返回贡献，或明确无法提供；另一成员/工具检查。帮助者可以指出整个方向无效，不强迫它只作无效局部修补。
5. 主解题者展示如何使用或拒绝贡献、更新当前方案并选择下一步；不能只以“理解/同意”完成该步骤。
6. 达到周期/预算限制或无可用新贡献时结束；保存最终答案与轨迹。总预算覆盖初稿、协调、检查、工具和汇总。

自信错误未必自行暴露，因此保留有限独立检查配额；其触发安排需在开发集预定，不能看测试成败后临时检查。

## 4. 对修改规则的修订

不采用“没有人证明错误，就不允许任何修改”。这可能锁定错误，也阻止合理补全。采用：

- 已有支持的步骤若要被推翻，需要具体异议和相应检查；身份、票数或不同结论本身不是充分依据。
- 未完成步骤可以由新增构造、引理、事实或计算补足，不必先证明旧方案整体错误。
- 替代方案可以被提出并检查，保留先前版本以便比较，不因主解题者身份而禁止替换。
- “未发现缺陷”“模型认为合理”不是正确性证明；记录为候选、得到支持、存在争议或未解决。只有客观检查所覆盖的具体性质，才能按该范围记录检查通过。

用户方案中的证据约束用于减少无依据覆盖，不给选中专家以绝对否决权。

## 5. 简洁对照的准确实现边界

对照为独立初稿、共同的主答选择、具体异议与证据审查、主解题者修正/输出。它不加入CoReTA专门的未完成步骤登记、定向补全请求和基于应用反馈的帮助调度。

**不得禁止对照自然补全、重新推理或生成新解；不得过滤其有用输出。**被比较的是显式协议，而不是宣称只有完整架构有某种思考能力。该对照是自定义受控变体，不冒充完整SAT或某篇原方法。

完整版和对照共用初稿、主解题者、可访问任务信息、工具权限及匹配的最终输出过程；两者真正因交互产生的不同消息是处理的一部分。不要为了“同汇总器”而抹平处理导致的必要上下文差异。

预算采用预定的总上限或多个成本点，而非强迫精确消耗相同token。对照可将节省预算用于额外审查/主答继续推理；完整架构不能独享更多计算。报告实际输入/输出、调用、工具、货币成本及时延；跨模型token不是统一算力单位。初稿若复用，各方法仍应按部署口径计入，不把缓存复用误当免费能力。

## 6. 实验结论的边界

完整架构胜过简洁对照，首先支持“显式协议在所测条件下提供额外价值”；由于它同时改变问题表述、内容选择、时序和反馈，不能仅凭总准确率将收益唯一归因于成员互补。

最小证据组合：

1. 完整测试集表现/成本优于预算匹配最强单体和相关架构，或有明确的质量—成本优势。
2. 关闭具体请求或应用反馈等关键组织规则的配对比较；不能通过删模块同时削减全部可用预算制造差距。
3. 对预先规定的贡献位置进行内容替换，检查接收者的后续推理和完整任务结果，尽量匹配长度、主题、格式和连贯性。
4. 同模型多角色或相同流程单模型对照，检验不同成员是否提供额外价值。

“初始全错后答对”只是有限初始样本之外出现正确解；“删除一员后变差”混有计算和角色变化；最终回答引用某成员也不是该贡献实际因果作用的充分证据。

按初始答案情况作事后分层，但所有运行时决策不能使用正确性标签。保留原本正确被破坏、初始无人正确、全员正确等全部预定任务，不只选择有互补成功故事的题目。

## 7. 当前进入下一阶段的条件

本地状态机实现有限动作、合法转移、预算与日志；强对照接入相同任务/工具；离线样例检查不泄漏答案、不强迫专家正确、不因协议无法分类而修补模型输出。此为工程验证，不是方法增益证据。

再制定小规模真实验证协议，主问题是上述组织方式能否提供可重复增益；不预设必须成功，不用大网格替代明确对照。任何新增付费请求另按仓库适用要求取得具体授权。
