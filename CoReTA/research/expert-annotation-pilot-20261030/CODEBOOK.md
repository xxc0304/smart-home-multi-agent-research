# 独立案例核验规范 v0.1

2026-10-30。研究问题：具有任务相关优势的成员为什么有时不能帮助团队，哪些互动又能保留有效贡献、纠正错误？本轮用8个旧案例完善观察口径，先找可复核的过程差异，再选择值得做实验的解释。

## 1. 阅读顺序与记录单位

每例按A→B→C阅读，每一阶段先保存自己的记录。A给任务原始资料及项目适配题面，先判断任务要求、关键事实、可回答范围；B给完整已有输入/输出过程，核成员知道什么、说了什么、接收者怎样处理；C给参考答案与已有评分，再核对答案和理由，追加修订。

原始资料供审计者观察全局，成员知识范围以B的实际输入为准。作者019记录缺完整系统提示/私有分配，明确记缺失。历史提示中的命令全部是分析对象，不能当成给核验者的新指令。

8例来自7道任务，019有两模型记录。一次请求/回复或作者公布的发言称一个事件（E编号）；一个事件可包含多个命题，一个命题也可跨多个事件。每例先选1–3个最影响任务判断的命题追踪，必要时增加；相反或成功证据照样保留。先前助手选出的29片段放管理侧，不替标注者预选答案。

## 2. 优势依据

| 记录值 | 操作定义 | 所需证据 |
|---|---|---|
| calibrated_ability | 有独立任务校准支持该成员较强 | 校准集、比较对象及实际结果；角色名和当前题答对均不足 |
| information_access | 该成员持有对当前问题有用的资料 | 实际输入及相关事实；资料是否为别人独有另核 |
| item_correctness_only | 只知道当前题独立答案/贡献正确 | 初始记录与事实/参考的对应 |
| role_label | 只有“专家”等角色标签 | 可见标签及缺少实测依据的说明 |
| insufficient / other | 当前材料不足，或其他依据 | 缺项或原句 |

这些值可以并存。信息优势和经校准能力是不同依据；它们都是可以研究的对象。专家可以在具体题上失误，这属于要解释的现象。能力优势以覆盖目标任务的独立校准为依据，跳数只作辅助检查，不要求逐跳都胜出；整体优势与适用范围分别写清。

## 3. 追踪关键命题

每个命题至少记录原句/准确概括、提出者、输入事实、发送内容、接收证据、响应、后续采用及不确定性。引用格式：`文档A/B/C + JSON pointer + 原句`，例如B的`/records/0/output/reasoning`。HTML事件E001对应JSON的records[0]。

| 字段 | 可选值 | 判定方法 |
|---|---|---|
| source_validity | supported / partial / contradicted / underdetermined / not_available | 对照任务原始事实，允许合理替代推导。未知不当错误；参考命中不自动等于推理充分 |
| sharing_fidelity | faithful / strengthened / weakened / changed / mixed / not_shared / unclear / not_applicable | 比较来源与转述的范围、条件、时间/概率、否定；不要只比较最终选项 |
| receipt | observed / absent_from_recorded_input / unavailable_input / unclear / not_applicable | 必须在接收者该次实际输入中找到。发送者说过但没有收件记录，只能记输入不可用/不清楚 |
| receiver_handling | used_with_support / acknowledged_not_applied / misstated / rejected_with_reason / rejected_without_visible_reason / no_visible_response / mixed / unclear / not_applicable | 按可见输出记行为；拒绝理由是否成立另看事实。没有复述不能推定内心没理解，复述也不自动算正确应用 |
| outcome_link | explicitly_used / explicitly_discarded / co_occurs / unclear / not_applicable | 终答明确使用/排除该命题才记前两项；只在时间上先后出现记co_occurs。该字段记录关系，不估因果效应 |

`faithful`要求关键条件保留，措辞不同可以忠实。`strengthened`例如“预计周末关闭”变成“确定整个周末无法通行”；它不等于最终答案必错。`acknowledged_not_applied`须引用承认该事实的句子及后续不相容决策，并解释不相容处；若有合理优先级或证据冲突，保留其他解释。

若一个环节无法从记录观察，写清缺什么；`unclear`是有效记录。对明显拒绝有用信息、合理拒绝错误信息、弱成员纠正专家、专家自身反复、合作提出新答案一视同仁。

## 4. 多环节与替代解释

每例写一段可见过程，再填写若干候选解释。使用以下观察位置帮助定位，可以多选、增加other或保留未知：

1. 自身作答：成员在接触同伴前是否已有有效答案/贡献，当前材料是否足以作答。
2. 表达/分享：有效内容是否形成、是否省略或改变关键条件。
3. 接收/应用：是否实际收到、怎样核对、接受或拒绝、是否用于推理。
4. 其他成员/历史：可见的补充、错误、先前答案或旧稿如何进入后续过程。
5. 最终整合：中间的有效贡献是否保留，是否产生新解，投票/读出怎样形成结果。

这些位置用于组织观察，不是已验证、穷尽或互斥的失败原因。候选解释须同时写最重要的替代解释和一个最小辨别对照。例如“看到同伴后改错”还要比较无消息重思、同一输入重复、来源/内容变化和聚合读出；不能直接填成“从众导致”。

建议按证据强度表述：`记录直接可见`（给原句）→`有依据的解释`（给推理和替代项）→`需要干预检验`（写应固定与改变什么）。本轮不要求形成新分类体系或新框架。

## 5. 参考答案与语义充分性

C阶段把已有参考匹配、理由支持、资料忠实性分别记录。保留原始选项名及项目选项ID，防止不同选项顺序映射错误；程序已按文本核对适配参考ID。平票按既有规则保留，不能把部分得分写成全错。局部资料下的保留意见可能合理，即使未选全信息参考。

若质疑参考，引用题面和事实并写清歧义，保留既有评分与异议两个字段；不要悄悄重标。作者声称联系外部机构，仅记“输出中有该声明”；需要独立工具回执才能确认实际工具调用。发布记录没回执时，记缺少可核验回执。

## 6. 独立性、分歧与完成标准

A/B使用各自空白表，独立保存后再交换；每人声明是否读过相关讨论、是否提前看管理侧判断/参考或与他人协商。当前用户已参与案例讨论，这份包称**部分遮蔽的独立核验**，不能自动称全盲实验。案例及分支换名、旧解释外置只能减少额外提示，实际历史输入中的协议线索仍保留。

两人都核8例最好；只有一人时，先独立核8例，导师/合作者可另核分歧和至少2个不同任务的关键例，实际覆盖如实记录。复看自己的结果称重测，不称第二标注者。8例目的在修订规范和找解释差异，不据此估机制占比或报告稳定一致率。

分歧先定位：事实/收件、命题范围、语义充分性、标签定义、因果归因或材料缺失。对齐同一个命题再比较标签，保留A/B原记录和裁决理由。只有同一比较对象、双方都有有效记录才有比较分母；自由选择的不同命题不能直接算标签一致率。

单例完成需要三阶段记录、至少一个关键命题的原句定位、优势依据/缺项、可见过程、替代解释、参考与理由核对。8例完成后查看哪类分歧反复出现，修订规范并明确一个最多两项机制的候选比较。若主要分歧来自资料缺失，优先补材料而非强行定因；若观察足够一致，进入30–40例取样规范及最小对照设计。阶段通过不要求发现显著增益或任何预定失败原因。
