# 从这里开始核验

2026-10-30顺序更新：先读[助手八例分析](../expert-case-analysis-20261030/REPORT.md)。本页是后续需要独立人工证据时的操作工具，当前不要求先填写；人工记录仍为0。

先读[判定规范](CODEBOOK.md)，再打开[8例材料入口](../../data/expert-transfer-annotation-20261030-v0.1/participant/index.html)。每例按A资料→B过程→C参考的顺序阅读，先保存当前阶段再打开下一阶段。HTML默认折叠长输入，需要判断实际收件时展开。

建议分两次完成8例，先安排约3–5小时/人，再记录实际耗时调整。A顺序S01→S08；B顺序S08→S01。两人独立填写，之后才交换结果。你若已经看过相关讨论，直接标明“已接触”，仍可进行核验。

记录可以选一种方便的方式：

- 直接在[研究者A中文记录表](REVIEWER_A.md)或[研究者B中文记录表](REVIEWER_B.md)写答案，附事件ID和原句。
- 使用[data/templates中的结构化空表](../../data/expert-transfer-annotation-20261030-v0.1/templates/)，复制到同包`submissions/你的编号/`再填；不要覆盖模板。结构化校验命令见下方。
- 在本聊天按“S编号＋下面几个问题＋原句”逐例回答；助手可整理格式，原始人工判断保留，歧义再核对。

每例需要回答的核心问题：

1. **A阶段：任务要求什么，哪些事实重要，现有资料能支持什么判断？**
2. **B阶段：谁有什么优势，依据是什么？**资料优势、经校准能力、当前题答对和角色名分开。
3. **追踪1–3个关键贡献：说得对吗、分享有无变形、是否实际传到对方、对方怎样处理？**引用事件E编号、字段和原句。
4. **最终整合发生了什么？**有效内容保留、丢失、新解或无法判断均可。
5. **你认为最值得解释的现象是什么，还有什么替代解释，需要什么比较才能区分？**多个环节可以共存。
6. **C阶段：与参考答案核对后，答案和理由分别怎样？你要修订前面的哪一点？**原判断保留，新增修订。

独立记录完成后用[分歧表](DISAGREEMENT_TEMPLATE.csv)对齐同一命题，先核证据再裁决。你可以先完成S01，其余按相同方式继续。助手已有分析和源身份映射在管理侧，初判前暂缓阅读。

在CoReTA根目录校验已填写JSON（只核格式、引用和完成状态）：

```powershell
.venv/Scripts/python.exe -X utf8 research/expert-annotation-pilot-20261030/validate_human_records.py
```

当前还没有人工提交。空表不算完成；程序不能替人判断贡献是否正确，也不能验证一个自称独立的记录是否实际独立。旧案例不要求按跳数划分或把每例强行归入唯一原因。
