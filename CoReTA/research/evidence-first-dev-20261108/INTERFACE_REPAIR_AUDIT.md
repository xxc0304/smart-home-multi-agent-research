# 名称／编号接口修复建议审核

2026-11-08。助手自审provisional，非独立人工审核；新增模型调用0，未实施新运行器或新批次。

## 判定

PASS先减少无关的答案映射负担、保留原结果及四条件公平比较。REVISE“已证明两套顺序导致失配”“只改最终输出即可”“把长度预算同时改变后的旧新差异归因于名称修复”。现有评分在旧合同下可复算，不是评分器把明确提交的正确ID判错，也不应宣布整批数据无效。

## 实证核查

- BINDING_CONFIRMED.json包含5个完整任务中明确的同一工作消息名称—ID不一致，支持确有映射/交付问题。它不是全量失配率，也不能从最后工作推定私密最终回答的隐藏意图。
- 原prepare保留description并随机shuffle possible_answers生成option_N；原文候选排列与新清单可能不同。但只有一个显式ID映射，无逻辑冲突字典。原位置依赖和顺序负担是合理假设，未做单因素验证，不能称确证原因。
- 原answer()对全文搜option_N、要求全篇只有一个不同ID。实际ID1/M4、ID30/M1和ID30/M2三份EOS初答都有唯一独立ANSWER行，分别为option_2、option_2、option_1，却因正文提到其他ID被记null。这是另一项过严接口/解析设计，不是已确认无法作答。旧合同也要求正文不用其他ID，故保留原null而不改原主评分。

## 必要修订

1. 保留原题事实及带路线/属性信息的候选段落，不为统一顺序删掉或改写证据；额外候选清单只列原名称，不新增随机编号映射。暂时使用与作者候选清单一致的顺序。后续若测位置稳健性，应作为另一个受控因素。
2. 名称合同覆盖初答、首次普通意见、各轮工作及私答，而非只修最后一次。否则F首轮及后续仍传播旧错号，无法评价干净的新协议。
3. 工作/初答只解析一个明确ANSWER字段，私答解析整个名称字段。先固定允许的大小写、空白、包裹标点等机械归一化；完整候选匹配，Mr. X与Mr. X's son不得子串混认。无答案、多答案、非法名称记null，不按理由/gold猜测或改写。若支持简称，映射须预先列明且唯一，不边看答案边加别名。
4. 名称和理由冲突只能作为单独过程标注，不作自动纠错。即使直接名称输出也可能发生工作到私答改变，并不保证此类错误被消灭。
5. 四条件全部统一修改、固定新配置和样本后重生成受影响的初答与后续。不得把旧ID轨迹只重做末答后叫作新四组复现；如仅固定旧上下文换输出，那只是末步局部诊断。
6. 长度预算另做工程预检：预定已知映射问题/初答超限的开发案例作压力用例，公开其按故障选取而非代表性采样。依据可运行性选一个全组统一上限，冻结后不按答对/答错或某题超限单独调整。若同时改编码/预算，可用于新协议内部四组比较，但不能用旧新涨分证明去编号或方法的单一因果贡献。

## 有界后续与验收

先完成候选名称解析和旧完整输出回放（含上述三个独立ANSWER字段、前缀冲突、多答案/未知、失败保存），再在预定少量开发案例上技术试跑，核查所有阶段的格式合规、实际长度和资料隔离。不能承诺模型永不超限或永不改答，要求故障可隔离、可保存、有明确分母。

技术通过后才决定同任务/条件全流程的新比较；若新协议结果与旧版不同，明确属于新协议而非把旧数据修成正结果。研究目标仍是有效专家判断保留及普通有效纠正，接口修复不自动成为论文方法贡献，不追加无上限的接口诊断。

本审核没有启动新GPU任务；下一执行需要在用户要求开始后完成上述准备和冻结，不新增例行逐项批准流程。
