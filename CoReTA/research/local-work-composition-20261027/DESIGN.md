# 局部工作组合：由实际工作暴露依赖，并在补全后接续

2026-10-27。文献约束后的最小候选设计 v0.1。用户授权设计与调研；未修改运行架构，未启动 API，未产生新效果数据。本文可以作为后续原型的实现规格起点，尚不是已冻结的可运行实验协议。

## 1. 目标与核心假设

目标：成员拥有局部、不完美的知识/资源优势时，让这些优势在共同求解中产生可追踪的实际作用，提高最终任务表现。

核心假设：当成员因缺少跨域输入无法独立完成整题时，让它先完成局部操作、保留阻塞该操作的输入，并由互补成员补全后继续执行，可能减少无依据补全、有效贡献闲置和下游重复解释。新增能力要体现为实际工作接续，而非更多采纳声明。

**最小可检验变化**：模型在没有每题人工正确分解/连接的条件下，形成一个尚缺跨成员输入、但已有实际局部工作内容的产物；另一成员补足后，原操作被接续，其结果进入最终求解。单纯记录“缺信息”、多问一轮或生成可运行代码都不能代替这项事件。

本设计主要针对两个缺口：

1. 有可用的局部知识，却因为无法独立证明整题该怎样改而没有形成可用贡献。
2. 局部工作已经正确，但下游重新解释或重算时丢失对象、条件或作用，未进入最终比较。

隐含输入发现与语义绑定是本设计要检验的认知操作，不能在接口里假定已解决。源规则本身解释错误不属于程序可以自动消除的错误；缩小工作范围是否能改善它另作观测。

## 3. 组成：成员、共享工作记录、程序执行器

使用任务原生的 N 名成员。初期资料不同、模型相同；角色取决于哪项工作由谁开展，不预设三种专家或必须三人。每个成员都可以做局部工作、响应别人的输入需求、接续自己尚未完成的工作。最终提交者是执行职责，轮换/配对控制，不附带知识权威。

共享记录保存原始任务、已披露原件、工作项、尚缺输入、返回产物及实际连接。成员仍有自己的私有资料；别人披露的来源对所有成员可见，不能因自己未持有而当作无来源。系统保留来源归属，不自动转成可信度排序。

程序只做权限和结构检查、引用解析、有限算子执行、依赖追踪、预算及日志。真正的对象含义、输入适用性和规则解释仍由模型判断。新增贡献是覆盖哪项实际操作，而非程序维护功能本身。

### 3.1 最小工作对象

模型不需要填写一套复杂审查表。每项工作只有以下内容；ID、拥有者、版本和运行状态由程序补充：

| 内容 | 含义 |
|---|---|
| `target` | 回应整题目标、某个已有缺口，或哪个局部步骤；不能使用隐藏金标的步骤名 |
| `result` 或 `operation` | 已完成的值/表/证据片段，或具有明确输入输出的转换/计算 |
| `inputs` | 缺少的输入；说明需要什么对象、量/事件、单位、时点/版本。非所有字段必填，缺失不默认为当前版本/零/false |
| `basis` | 当前成员实际可见的原件句柄；私有内容若作为共享依据，需同时披露支持该项工作的原文 |
| `scope` | 原件明确的适用条件；对解释性假设单列为假设，不混作事实 |

`result` 与 `operation` 为两种产物，不能把普通文字强行编译为布尔条件。贡献无需始终包含操作；找到关键原文或一个已对齐的数据行也可以直接补足别人的输入。

**程序可执行的首版范围**：有明确参数的算术、比较、集合及时间运算，用有限表达式和可追踪值实现。成员负责从本地资料生成表达式及输入定义；程序只实现通用运算。首版不执行任意生成 Python，也不由实验者为每题编写正确函数。超出这个范围的自然语言局部成果仍可被正常使用，但不计为程序已经保证了其后果。

### 3.2 输入连接的实际分工

供给方看到缺口后，引用“目标工作.输入”，返回数据/结果、原件及适用范围。这是连接提议，并不自动成为正确连接。

消费方是开展该项操作的成员。它在正常接续调用中判断返回内容是否适用于自己的输入，输出 `输入 ← 已有产物ID`，或保留待补、指出具体错位。程序按该连接取值，避免重新抄写。同一成员可以消费自己或他人产物；数据先到时可以先发布，后来再建立连接。

选择消费方负责，是因为它应知道本操作需要什么；这比一个成员裁决所有领域关系更局部，是待验证的机制假设。供给方仍可质疑误用，其他成员也可提交另一操作，消费方没有绝对否决真值的权力。

这不是“持有者天然更懂输入”的设定：如果原操作需要超出其局部知识的概念才能定义输入，当前分工就可能无效。日志须记录该类失败，而不是补上人工正确接口后记为自主成功。首版先限定一种可解释的局部操作；算术/集合/时间三类是可选范围，不要求一次实现全部。

程序拒绝明确单位/类型冲突、失效版本、缺引用、循环自支持；同义词、任务相关性、预测含义仍不在机械保证范围。两个值字符串相同不代表同一对象。没有可核对的上下文时，必须保持该连接的未知/条件性，不能悄悄填默认值。

下游结果继承上游尚未证实的假设及预测标记；算出一个数值不会将其升级为无条件事实。解除某项假设需要新增支持，不能因为“运行成功”自动清空。继承由程序实现，但前提是模型已正确表达该条件；漏提条件仍须计为语义接入失败。

## 4. 工作流程：一次起步、至多两次接续、一次提交

以下是首个原型的有界配置，不是最佳轮次结论。执行层面最多 `3N + 1` 次模型调用；N=4时为13次。所有调用和生成均计预算；尚未指定实验任务数量或授权付费。

两次接续只允许检验该预算下的完成能力；后期才发现的新依赖可能来不及补足，须与错误绑定分开报告，不能由调度成功宣称任意深度依赖都能完成。

### 起步

成员只拿原始任务和自己的资料，尝试完成有用的局部工作，至多发布两项；信息足够时允许给出完整解，不强迫拆分。没有贡献可返回空集合。任务入口只提供原始问题，不由人工预先分解成正确子问题或指定谁该补谁。

这次不强制生成共同完整旧稿。若研究依赖历史旧稿的修复，必须另设修复条件，不与从零共同求解混报。

### 第一次接续

所有成员读取同一快照中的工作项、缺口及已披露原文，结合自己的私有资料，选择一次最相关的工作：补一个输入、完成一个可接续操作，或主动发布遗漏的有用工作。允许回答“当前材料无法提供”，无需伪造帮助。

小N原型采用广播快照和成员自选，不先预测最优专家，也不靠自报置信度选人。重复或冲突返回均保留；程序不按票数合并不同值。广播开销会计入成本，后续有数据再判断是否需要路由优化。

### 第二次接续

成员看到新增供给，重点接续自己开展的工作：建立输入连接，或指出具体不匹配并保留待补。已经齐备且表达式可执行的工作由程序计算；新结果沿已建立的合法依赖自动向下游传播，无需每传一次值再调用一个模型。

第一轮已完成连接时不必等第二轮才算。两次接续仍缺输入就保留缺口，到期不追加无界轮次；循环图没有新证据支撑时不算完成。其他成员可提供替代工作，不要求只能修补既有方向。

### 最终提交

最终提交者读取原任务、已披露原件、工作结果及尚存分歧，进行剩余的全局比较并按任务原生格式提交。可继续正常推理、拒绝错误操作和必要时重建；不能只凭“同伴做了/代码跑了”决定接受。

对于能由完整计算直接得到的最终数值/候选，提交者引用结果句柄，程序只负责渲染其选择的结果值，避免理由与数值抄写不一致；相同功能也向基线开放。程序不替提交者选择哪个有争议的推导为真。

**待补不等于可以不交答案。**任务要求必选时，两组均按同一 best-effort 规则交付答案并标注限制。程序不因内部图未闭合就把答案强改为null，不重现以“没有合法候选”为由自动压制回答的问题。任务本身允许拒答时，才可按原任务协议拒答；未知也不能被程序自动当作合格或不合格。

## 5. 错误与分歧：修正作用于哪一层

| 情况 | 动作与保留内容 | 由谁判断 |
|---|---|---|
| 输入事实错误/过期 | 修改该数据节点，失效并重算依赖结果，保留操作 | 有原件的成员提出；模型识别事实/时点变化，程序追踪下游 |
| 数据正确，但接错对象/单位/时点 | 解除这条输入连接，保留双方产物，补找对应输入 | 消费方正常接续或他人具体质疑；程序只检查明确元数据冲突 |
| 操作漏条件或规则理解错误 | 创建操作新版本；旧版本及其结果不再作为已支持结果 | 成员给具体原句与差别；没有可靠工具时仍可能判错 |
| 两份资料冲突且无法判定 | 保留两个明确有条件的局部结果；至多两份待比较供给，其他不静默丢弃 | 模型选择如何比较并在最终答案说明，程序不投票认证 |
| 无资料、没匹配到输入 | 保持待补；到期按共同提交规则输出 | 不默认false、不发明前提、不无限追问 |

至多两份待比较供给只是原型的计算预算限制，不是“两个分支能覆盖真相”；排队/未处理项需日志披露。第一版不建立动态信誉、两个置信度、全局仲裁Agent或组合式大搜索。版本失效与依赖追踪为保障真实接续的基础设施，不单列创新。

## 6. 贯通设计走查：维修窗口

以下为**自编静态走查**，人工展示预期执行语义，没有模型生成，不能作为效果结果，也不冒充011原题全文。

任务：比较P、Q能否在09:00前就绪，并在可行者中优先选费用较低者。费用和任务截止时间为公开信息。

- A的资料：P完成维修需要从开工起30分钟；Q已就绪。A生成 P的 `finish = start + duration`，duration=30分钟，缺start；可同时生成 `finish <= deadline` 的后续操作。
- B的资料：P当前08:00尚未就绪；计划08:20开工。它提供08:20，并保留“计划”而非“已发生”的模态。未提供实际启动的保证。
- C的资料：当地规定只有维修验收后才能交付。它主动发布一个尚需验收时间/结果的要求；即使主计划没提出，仍可补入。
- A接续：预计完成08:50。若没有验收结果，不能把P变成无条件已就绪；可以得出“按计划开工且验收及时完成时，满足09:00要求”。
- 最终比较：若题目要求保证交付，P的未决验收会影响选择；若题目要求按给定计划预测，则须按该任务语义比较。该判断不由库存式布尔过滤器替代。

这个例子刻意保留未决，而非安排四个值刚好组成正确答案。它展示规则、事实、预测和需求的分工，也展示程序能算08:50但不能认证验收或预测实现。

### 对应失败走查

1. B给的是Q的08:20：显式对象ID冲突可阻断连接；若模型自己误标为P，仍是语义错误，计错而非程序成功。
2. 30分钟适用于旧维修版本：更新scope并重做操作；不能只换开工值保留错关系。
3. A从“当前未就绪”写 `P.ready=false`：若范围明确是当前时刻，这可以是正确事实；将它直接接到09:00的就绪判断才是错误映射。其他成员可凭原文提出修正；系统保留原文和纠正渠道，但不承诺自动识别，计为语义连接失败。
4. B的计划无法满足“保证”要求：输入可以真实但不足以闭合该操作；保留条件，避免把预计自动转成确定。

### 6.1 真实历史023的适配走查

核读 [公开任务](../../data/task-packs/hiddenbench-local-contribution-dev-20261025-v1/hb-local-dev-023/public/task.json) 及 distributed/A1–A4 原件：任务为本周六约90人的可餐饮宴会。A1持有Lakeview唯一通路洪水封闭且预计周末仍不通；A2持有Grand Oak网上不可用源于软件故障、本周可电话临时预订；A3持有Library不允许餐饮、仅密封零食；A4持有当地道路安全提示。

这些材料确实分别影响当前判断。候选可让A1形成道路可达性限制、A2形成对通常提前预订规则的当前例外、A3形成餐饮限制；来源和适用范围应保持。但它们大部分已经是可直接应用的事实，**无需先构造待补函数**。只有与具体预订/通行确认有关的输入才应保留未知，不能为了表现互补人为将一句原文拆成多名成员的任务。

因此，023适合检查范围保留、原文覆盖及提交一致性，不适合单独验证“开放输入的局部工作接续”带来的增量。已有条件表也能处理这些限制；如果新设计在此只重复布尔筛选，就没有新增机制。这是真实案例适配审查的结果，不是新增模型运行或预测它必然失败。

## 7. 为什么它与已经试过的不同

| 已做操作 | 本轮需新增的可观察行为 |
|---|---|
| 成员给事实、主答重新解释 | 成员完成局部转换/计算；下游以句柄消费，而非默认从文字重做 |
| 直接替换理由/选项 | 不知道整题该选什么，仍可交付待补输入的局部操作 |
| 已有条件表筛候选 | 条件/操作由成员在各自资料中自然形成，缺口由实际工作暴露；不预置每题正确字段和依赖 |
| 接收者拿固定报告做复核 | 请求可由任一工作持有者发起，谁使用输入谁负责接续；没有固定通用检查者 |
| 字段声明“已采纳” | 日志中存在输入连接、运行结果及下游消费；声明或引用不代替实际使用 |

如果实现只多了字段、但成员仍交整题意见且整合者仍重做全部关键工作，应判为设计未落地，而非用最终一次成功掩盖。

## 8. 任务适配与实验对照草案

本轮没有冻结数据集或付费批次。整体评价从事先确定的目标任务总体抽样，保留无需互补的普通任务；机制诊断可以额外抽取自然跨来源依赖任务，但需单独报告，不能替代整体效果。不能按候选成功筛题。

### 8.1 任务选择

- 已有004/023可审查信息与简单限制的执行，不作为新机制普适性的主要正证据；011可作语义边界反例，不能人工修正条件后当自主成功。
- 首选考察表格/文档中的跨来源转换与比较，先审查公开基准原生结构。TAT-QA有真实表格与段落、混合数值推理及答案尺度，可作候选；它本身不是多Agent基准，也可能太容易，不能只因适合算子就直接宣布选定。
- 依文档/表格等自然资源边界分配给成员，不按正确解步骤分配；所有需要的表头、单位等随所属资源保留。分配规则在看模型输出前固定，至少交换资源/成员对应以控制身份。
- 限定一类操作是首轮机制验证的合理范围；若有效，再在多跳证据或规划任务检验不依赖代码的接续，不将跨任务扩展提前写成结果。

### 8.1.1 整体评价与机制诊断分别取样

依据2026-10-27用户纠正，不能只评价预计适合本架构的题。首个原型的目标总体暂限数值/表格文档任务，不预先承诺所有开放任务；在这一总体内部也必须保留多种资料关系：

- 一名成员的资料足以完成：检查是否干扰已有正确工作。
- 汇集事实即可解决：检查额外组织是否无益或有害。
- 跨来源转换/计算需要接续：检查目标机制能否增加有效工作。
- 资料存在歧义、条件或错误解释风险：检查接错输入及错误传播；人工控制另报。

以上按资料和任务结构在看模型结果前标注，不命名为“需要我们架构”的题，因为普通讨论同样可能解决。主结果保留总体抽样比例；若为小试均衡抽取或额外增加某层，披露分层结果，未经权重校正不把人为混合比例的总分当自然分布成绩。

已有六题全部保留作开发/边界材料，不因依赖弱而排除；它们不能作为全新确认样本。后续数据按context划分开发/确认，避免同一表格换问题后声称未接触。依赖诊断的阳性例与普通任务的结果保持可区分，但前者不能替代后者。

### 8.2 必需主对照

1. **普通多成员协作**：相同私有资料分配、原件共享权限、通用计算器、轮次和总预算；可自由提问、分解和组合，不能禁止其自发做出相似好行为。
2. **当前候选**：局部工作、未决输入、自选供给、消费方连接、程序续算。比较的是显式组织方式是否增加净价值。
3. **强单Agent**：可访问全部原件或同样文件访问工具，享有同样总预算与计算工具，可自行模块化和复用结果。若任务装不下上下文，提供与多Agent相同的按需访问能力，不强行塞超窗。

三个条件均开放相同程序工具和结果句柄渲染；最终提交者按任务/配对固定并跨题平衡，不从测试答案选整合者。候选若没有强于普通协作，不能靠单体差来宣称架构提升。

### 8.3 有信号后再做机制隔离

使用同一批模型自然生成的局部产物，保留原件和信息总量，比较直接连接续算与仅以文字呈现后重新构造。这个下游诊断只能检验消费方式，不能代替端到端协作。

把缺口/接口/依赖由人工给对的条件独立标成上限，不能混入自主成绩。还应区分改变旧稿可见性、减少过早整题承诺与输入接续本身的作用；首轮不同时加入示例、置信度和新复核提示，避免归因再漂移。

### 8.4 评价与停止条件

主指标是按原任务评分的最终质量，同时报告正确答案损害、未作答、总调用/input-output tokens/时延及技术失败。过程指标分开记录：局部操作是否正确、输入需求是否实际成立、返回值是否匹配、补全是否真的触发执行、结果是否参与最终比较。有效利用的语义标注需明确口径，不能用引用次数代替。

同时报告主总体及各资料关系层的结果，并给配对的双方正确/仅候选正确/仅基线正确/双方错误，区分补救收益和错误介入损害。研究目标是总体净收益、目标困难上的改善及普通任务上没有明显系统退步；不要求随机采样中每道题都不输。允许的退步范围和成本上限应在正式验证前确定，不能看到结果后放宽。普通题上的稳定退步不能仅靠难题提升就不披露。

小试只判机制是否值得扩大，不凭少量重复宣称稳定显著；重复不当作独立题目。实际样本规模、成本上限和最小值得关注差值须在选定任务、完成离线审核后另行冻结。

预定停止/收缩：只在人工正确接口下成功；自然局部操作错误抵消接续收益；强单体和普通协作已低成本同等解决；主要差异来自工具、额外预算或删除旧稿；新增工作量主要是成员互相要求重读和复核。出现这些结果时应报告边界并调整研究选择，不继续叠加通用裁判救效果。

## 9. 下一项实际交付及当前就绪状态

设计阶段已明确工作对象、依赖发现入口、自选响应、消费方绑定、机械续算、局部修订和统一提交。自然语言输入匹配仍是待检验能力，没有宣称已经解决。

下一项交付应是**离线最小原型和准备审查**：

1. 审查少量公开任务的原生资料，决定首个任务族及可复现资源分配，保留强基线可能满分的事实。
2. 固定最小schema、表达式和输入连接格式；复用现有权限/日志/预算设施，不重写全项目。
3. 用真实历史全文及静态反向案例走通：缺输入、错对象、单位/时点冲突、规则版本改变、循环依赖、无人供给、核心合法但可选连接无效、最终必答。将技术失败与语义失败分开。
4. 保存批次科学意义和执行准备两项审核；修好准备问题后重新冻结。任何付费批次仍需具体数据/目的地/次数的授权。

**当前裁决：值得进入离线原型和任务适配工作；尚不具备直接启动付费实验的条件。** 本次无训练需求、无新增API、无虚构成功率。
