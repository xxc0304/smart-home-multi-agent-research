# CoReTA 条件化专长组合：近邻已有条件组合，研究增量取决于局部知识如何取得

日期：2026-10-20。研究与设计材料；本轮没有运行模型实验、测试或修改实现。

比较层级补充：本文的“近邻”包括思想前身、形式操作先例和现代方法，不能统一解释为架构重复。SAT 的离线组织策略学习与 CoReTA 的机制驱动设计应分别比较；2012 条件论证与 DAREC2 属符号多智能体前身。详见 [比较层级校正](COMPARISON_SCOPE_CORRECTION.md)。本报告未建立整体架构被覆盖的结论。

## 摘要

当前候选解释是：成员在知识不完整时被要求完成整题，可能把有依据的局部关系与未经支持的补全绑定；团队继而围绕整答协商，损失本可组合的知识。候选机制尝试发现条件依赖、保留局部条件关系、让互补成员补足条件并形成完整解。本次从澄清探测、LLM 知识交接、经典条件推理三个视角检索并核读方法，纳入十五项机制工作、两篇问题锚点和一项理论边界对照。直接先例既包括条件变化与定向澄清，也包括跨成员补条件和个体不可得解的群体构造。因此，贡献不能停在条件账本、追问或组合本身；值得继续研究的是，不完美成员如何取得和维护可靠的条件化贡献，并据此区别应补条件与应改规则。该定位是文献比较所得的候选空间，尚无本项目新实验支持。

## 1. 研究对象与问题

固定主命题：当成员具有相关专长差异时，怎样可靠使用这些差异，减少无依据折中与有效知识流失，同时允许纠错和组合新解。当前比较针对最近提出的条件化机制；旧的固定检查者/整合者实现不代表该机制已经实现。

- RQ1：哪些工作已实现条件探测、局部贡献保留、同伴补条件和完整解组合？
- RQ2：它们实际操作什么对象，依赖什么信息或验证能力，与当前候选差在哪里？
- RQ3：哪些应当成为核心近邻，哪些可复用，剩余贡献需要具体到什么程度？

问题起点的两篇论文各拆开了不同困难：[Multi-Agent Teams Hold Experts Back](https://proceedings.mlr.press/v306/pappu26a.html)研究识别专家后仍用不好其知识；[HiddenBench](https://proceedings.mlr.press/v306/li26ej.html)研究团队未探索其他成员尚未表达的信息。二者支持专长利用与信息探索的研究价值，尚不能直接证实“整答中的猜测污染局部知识”就是其失败的因果机制。

## 2. 检索与核验方法

采用 deep-research，三个独立视角均先广搜，再按原文算法和提示词收窄。关键词包括 conditional argument / distributed abduction / assumption dependency / clarification / counterfactual information gain / minority claim recovery / handoff gap。范围截至研究日，不设年代下限，以免漏掉比近期 Agent 论文更直接的经典机制。

引用以会议、出版社、作者论文为依据。逐项核对身份、阅读位置与运行时信息；将正式出版、作者自报录用和仅确认预印本分开。未获取足够正文的 EPRAG、仅有项目仓库的 Corollary，以及只定位到片段的补充线索，不进入方法覆盖判断。出处与阅读范围见 [SOURCES.md](SOURCES.md)，逐分支笔记保留更细的算法证据。没有检查各项目实现代码或独立复现论文数字。

## 3. 比较轴：相同词语可能对应不同操作

| 操作层 | 要回答的问题 | 主要近邻 |
|---|---|---|
| 条件与缺口发现 | 哪个未确定信息会改变结果，应当问什么？ | ICE、ClarifyGPT、Ask or Assume、CIGAsk、KBD |
| 局部贡献的交接与修订 | 保留什么、向谁补什么、失败后撤回哪里？ | SAT、AgentAsk、VulAgent、SAVeR、StateWise、CoCoA |
| 条件关系的组合语义 | 补条件怎样接入原推理，冲突与未决支持怎样处理？ | 条件论证、DAREC2、ATMS、学习式 assume-guarantee |

这些是操作分类，同一方法可能跨层；下文按其最直接的贡献归属讨论。最终判断不使用“有/无条件管理”这样的粗二元相似度。

## 4. 条件探测已经具体到可执行流程

[ICE](https://arxiv.org/html/2311.08718v2)改变候选澄清并观察答案分布；[ClarifyGPT](https://linshi-website.github.io/paper/ClarifyGPT.pdf)先执行多个候选程序，用行为差异定位应问的需求。二者都使缺口发现超出自报置信度，但探测结果并不证明某条局部关系正确。与二者相比，[Ask or Assume](https://arxiv.org/html/2603.26233v3)侧重把缺口检测与执行分工，[CIGAsk](https://arxiv.org/html/2609.24290v1)侧重用反馈的反事实价值训练提问策略；后两者的模拟用户可见完整意图或上下文。

| 工作与身份 | 已实现的核心操作 | 与 CoReTA 的关系及边界 |
|---|---|---|
| ICE，ICML 2024 | 对输入生成多种澄清，集成回答并分解不确定性；也提出向用户提供澄清选项 | 最接近条件变化探测；没有跨成员条件关系组合接口。输出敏感性不是规则真值 |
| ClarifyGPT，FSE 2024 | 采样程序、执行聚类、比较不同功能、定向提问、细化需求后再生成 | 最接近差异→问题→补信息→完整解；自动用户评估使用正确测试辅助，不等同不完美同伴 |
| Ask or Assume，2026 作者自报 Findings 录用 | Intent Agent 逐轮检缺口，必要时强制执行者询问用户 | 新增缺口检测角色已有先例；求助来源掌握完整原 issue |
| CIGAsk，2026 作者自报 Findings 录用 | 用保留/删除用户回复后对正确答案的似然差奖励，学习 Think/Clarify/Answer | 训练阶段归因已收反馈，不是运行时发现未知条件或检验条件规则 |
| KBD，AAAI 2026 | 自适应提问并根据答案分布估计知识边界 | 可借鉴边界探查；没有实现单题局部关系的跨成员前件补足 |

本节出处：[ICE 正式记录](https://proceedings.mlr.press/v235/hou24b.html)、[ClarifyGPT 正式稿](https://linshi-website.github.io/paper/ClarifyGPT.pdf)、[Ask or Assume v3](https://arxiv.org/html/2603.26233v3)、[CIGAsk v1](https://arxiv.org/html/2609.24290v1)、[KBD 正式记录](https://doi.org/10.1609/aaai.v40i40.40670)。最新两项的录用信息未找到独立 Anthology 条目，不能写成已经正式出版。

## 5. 当代 LLM 方法已覆盖相当多的保留、追问与修复动作

[SAT](https://arxiv.org/html/2609.22682v1)的真实冻结协议已经追回被共识遗漏的局部主张，并让成员围绕必要条件互补修复；[AgentAsk](https://aclanthology.org/2026.acl-long.1294.pdf)则在交接边上决定何时问、问谁、问什么。前者是局部贡献组合的强对照，后者是定向交接修复的强对照；不能只把它们视为理论上能模拟任意提示的通用框架。

| 工作与身份 | 已实现的核心操作 | 当前候选需要说明的实际差异 |
|---|---|---|
| SAT，2026 预印本 | 提取 claims/assumptions；挑战缺失条件；同伴支持、批评和修复；最终追回遗漏贡献。原文有初答全错后协作成功案例 | 需说明怎样将有效条件关系与错误补全分离，并在补全被否定时继续保留、使用该关系 |
| AgentAsk，ACL 2026 | 交接前检查缺失项，选择相关成员提出最小问题，回复后下传；控制器经过训练 | 追问本身已有；尚需定义条件化贡献的持久对象、前件支持及组合更新 |
| VulAgent，Findings ACL 2026 | 保留漏洞假设、触发前提与路径；逐条件检查，再作路径审查 | 显式条件对象已有；主要验证漏洞候选，且 plausible/unknown 保留不等于前提已证实 |
| SAVeR，ACL 2026 | 识别缺失假设等失败片段，设接受条件、局部编辑后复查 | 已覆盖保留无关步骤与局部修复；内部 persona 不是分布私有知识的互补成员 |
| StateWise，2026 预印本 | 改变/删除已有记录并比较行动，补外部证据后限定范围修订记录 | 最接近已有前提的依赖探测；未表达条件的发现、关系恢复和同伴实例化仍需另定义 |
| CoCoA，2025 预印本版本 | 内外知识 Agent 各先答题，再以答案为条件归纳知识，第三者整合；可进一步蒸馏训练 | 互补知识显式化已有；其 conditional 指按候选答案生成知识，不是保留尚未满足的逻辑前件 |

本节出处：[SAT Appendix A/C](https://arxiv.org/html/2609.22682v1)、[AgentAsk §4 与提示词](https://aclanthology.org/2026.acl-long.1294.pdf)、[VulAgent §3 与 Appendix G](https://aclanthology.org/2026.findings-acl.928.pdf)、[SAVeR §3](https://aclanthology.org/2026.acl-long.1440.pdf)、[StateWise §3–4](https://arxiv.org/html/2610.05241v1)、[CoCoA §2](https://arxiv.org/html/2508.01696v1)。预印本标签只表示本次确认的版本，未推断当前一定未录用。

[VulAgent](https://aclanthology.org/2026.findings-acl.928.pdf)核查候选路径的前提，[StateWise](https://arxiv.org/html/2610.05241v1)核查行动依赖的记录，[SAVeR](https://aclanthology.org/2026.acl-long.1440.pdf)修失败片段：三者对象不同。删除记录、消融反馈和编辑失败步骤都可能被称为反事实，但不能因此混为同一算法，也不能凭一次扰动判定知识真伪。

## 6. 经典条件推理比泛化的“人类团队类比”更直接

[AAMAS 2012 条件论证](https://www.ifaamas.org/Proceedings/aamas2012/papers/4C_2.pdf)明确让同伴证明一个待补条件，并把其支持接入原论证；[DAREC2](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ICLP.2011.175)将未解目标、假设、约束和待检查状态分布给能接续的成员。两者都超出最终答案选择，但输入已经是逻辑程序；它们没有建立从混合真假自然语言中获得真实规则的能力。

| 工作与身份 | 可直接借鉴的机制 | 不能直接移植的前提 |
|---|---|---|
| Cooperative Dialogues with Conditional Arguments，AAMAS 2012 | 同伴证明 L 后，将待补集合由 E1 更新为 (E1−{L})∪E2；可递归补条件并构成个人不能推导的论证 | 共享本体、形式程序与诚实协作；例子属于符号系统，不是 LLM 全员初答失败实验 |
| Multi-agent Confidential Abductive Reasoning / DAREC2，ICLP 2011 | 本地推理、未解目标路由、假设一致性检查与回溯 | soundness/completeness 有指定逻辑语义与有限性条件；一致假设不是现实真值 |
| ATMS，1986；算法核读 1988 修订稿 | 保留多套支持环境，冲突只撤掉相关支持，其他路径可继续成立 | 它维护给定规则的依赖，不能自行保证提交规则为真或选择适当专家 |
| Learning Assumptions for Compositional Verification，TACAS 2003 | 用查询和反例自动学习环境假设，分别检查假设是否足够与环境是否满足 | 可靠查询来自形式模型检查；不能假设 LLM 自审拥有同等判别能力 |

出处：[条件论证 §3–4](https://www.ifaamas.org/Proceedings/aamas2012/papers/4C_2.pdf)、[DAREC2 §4](https://drops.dagstuhl.de/storage/00lipics/lipics-vol011-iclp2011/LIPIcs.ICLP.2011.175/LIPIcs.ICLP.2011.175.pdf)、[ATMS 算法原文](https://dekleer.org/Publications/Corrected%20AAAI88.pdf)、[学习式 assume-guarantee 原稿](https://ntrs.nasa.gov/api/citations/20030017771/downloads/20030017771.pdf)。ATMS 原始 1986 全文未成功提取，算法细节归于可读修订稿；TACAS 正式版与 NASA 技报年份/作者记录见来源表。

这也修正了两种过强说法：条件补足并非新近才出现；自动学习条件也并非必然由 CoReTA 首创。[学习式 assume-guarantee](https://ntrs.nasa.gov/api/citations/20030017771/downloads/20030017771.pdf)已有条件精化，[ATMS](https://dekleer.org/Publications/Corrected%20AAAI88.pdf)已有依赖撤回。现代 LLM 方法仍可能在不完美语义输入下提出新的操作与经验发现，不能因存在符号前身就宣布该研究无贡献。

## 7. 综合：应当固定哪些最近邻

| 所比较的能力 | 优先近邻 | 对 CoReTA 的约束 |
|---|---|---|
| 条件变化暴露缺口 | ICE；ClarifyGPT | 不能只改几个条件、再泛泛追问 |
| 局部贡献保留并产生新解 | SAT | 不能只保护少数正确观点或证明一次全员初错后成功 |
| 定向向相关成员补信息 | AgentAsk | 不能只加一个会提问的协调者 |
| 条件化对象及逐前件检查 | VulAgent | 不能只增加假设字段和检查状态 |
| 跨成员条件闭合与递归组合 | AAMAS 2012；DAREC2 | 不能把补前提、组合新解本身当首创 |
| 扰动与修订粒度 | StateWise；SAVeR | 需具体说明干预对象、证据来源和何时更新 |

当前最需要逐动作比较的是 SAT、ICE、AgentAsk，以及作为概念/算法前身的 AAMAS 2012 与 DAREC2；若最终方法突出显式条件对象，则 VulAgent 同等重要。这是按比较轴固定的集合，不再每遇到一篇关键词相近工作就重开整套架构。

[Multi-Agent Constraint Factorization](https://arxiv.org/html/2601.15077v1)可提供局部约束组合的抽象视角，但其凸集合/投影等条件不等于 LLM 文本满足这些条件。它是理论边界对照，不能替代上述实际算法，也不能为当前架构提供现成正确性保证。

## 8. 尚待设计的研究增量

依据上述比较，值得继续具体化的候选问题是：**怎样让成员交付其知识实际支持的局部关系，暴露未经支持的补全；在条件被纠正时保住仍有效的关系，再以互补成员的证据组合完整解。** 关系可在协作前直接生成，也可从既有推理中恢复，不必强制先生成一份完整错误答案。

该机制至少要解决四个相互区别的判断：

1. **缺什么条件**：从资料、推理和不同候选行为中提出候选缺口，不能预先由研究者把所有关键槽位标好再称自动发现。
2. **能怎样改变条件**：干预须与成员已有信息相容，且不能泄露答案。两个样本不能唯一识别任意函数或完整适用域。
3. **保留的关系是否成立**：条件值未知与关系本身可疑必须区分；把“猜 u 所以 v”改写为“若 u 则 v”不会自动修复错误推导。
4. **别人是否真正补上了**：支持要有来源和适用范围；允许对方也返回条件关系，处理冲突与循环，并只撤回依赖失败支持的部分。

这四点是方法责任，不是建议再添加四个固定角色。可以复用条件论证的补足语义、ATMS 的替代支持，以及 AgentAsk 的问询控制；新的贡献应落在其中某个困难操作和相应失败解释上，而不是组件数量。

未来证据应拆开两条主张：整答协议是否确实造成局部知识流失；候选机制是否因保留和接续这些关系获得收益。完整资料单体、资料集中整合、普通讨论、直接提示局部知识、定向澄清和强 SAT 类修复都提供不同替代解释。“全员初答都错，最后答对”是值得观察的结果，单凭它还不能归因于知识组合；还需看具体贡献被采用后是否真正影响新解。本节是设计约束，没有启动新实验。

## 9. 结论与边界

RQ1：条件变化探测、定向追问、局部贡献挽救、前件检查和群体新解构造，均已有具体先例。RQ2：最关键的设定差异是条件来自哪里、关系以什么方式取得、补足者是否可能错，以及裁定依赖的是形式 oracle、完整意图还是不可靠模型。RQ3：CoReTA 可以继续探索从不完美贡献中取得并使用条件关系的机制，但目前不能据检索宣布该机制已经解决或具有足够顶会贡献。

本报告没有得到“一切已被同一篇覆盖”的结论，也没有得到“完整组合没人做所以新颖”的结论。它将最近邻落实到实际动作，并把下一次设计需要回答的问题固定下来。范围是定向近邻研究，非穷尽整个多智能体领域；本项目早期失败未构成对当前未实现机制的否证，论文原有结果也未在本轮独立复现。
