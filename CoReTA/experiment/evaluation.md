# CoReTA 评测约定

本文件是评测入口，不为所有任务另造一个统一分数。每批的冻结 manifest、评分代码、任务包 README 和 `EXPERIMENT_REVIEW.md` 决定该批的具体样本、主指标与停止规则。

## 每批共同报告的维度

1. **任务结果**：按任务原始规则或事前冻结的适配规则评分。答案正确本身不证明贡献被正确理解或采用。
2. **过程证据**：分别记录相关信息是否可见、贡献是否被发现/接收、依据是否正确绑定、是否实际用于工作、修订是否有支持、终稿是否同步。不要把“有正确知识”合并成单一的采用率。
3. **成本**：记录请求数、输入/输出 token 和工具调用；报告增量成本，不以请求轮次相同替代预算匹配。
4. **失败类别**：分开报告技术中断/格式错误与语义错误；保留未完成批次和缺失项，不静默删除。
5. **分层结果**：按事前定义的普通题/依赖题、任务族和条件分开报告。不同任务、不同重复或开发与留出样本不事后池化。

## 任务专属评分

- Moon Survival：使用 `data/task-packs/moon-survival-v1/README.md` 和相应冻结评分文件中定义的排名误差与有效性规则。
- HiddenBench 衍生任务：使用相应任务包和 run 的参考答案投影与评分脚本；明确其为项目适配任务，不直接套用原基准总体数字。
- MATH / HumanEval 等早期链路：使用与该批次绑定的官方或项目评分实现，见 `scoring/` 和对应 `engineering/` / `runs/` 记录。
- 其他任务：在 `EXPERIMENT_REVIEW.md` 中先写出任务、官方答案、主指标、过程指标、成本、失败规则，再运行。

## 运行门槛

`EXPERIMENT_CHARTER.md` 规定研究意义与准备审核；`EXPERIMENT_PREFLIGHT.md` 规定付费模型运行前的本地检查。修改任务、提示、schema、配置、预算或评分后，重新冻结并审核受影响部分。任一门槛未通过或未获本批次运行授权时，不调用付费模型。
