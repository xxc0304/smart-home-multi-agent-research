# 一个具体例子：每个条件到底收到什么

2026-10-30。以下是**按D开发题可见原文手写的演示**，不是任何模型的真实回答，也没有实验增益。

题目：`When was Wesley Alba Sturges's institutional employer created?`

给定资料中，P17写他在Yale Law School任教，P15写`Yale Law School (1843)`，并另写Yale College在1887年改名Yale University。按题目给定资料，机构匹配与日期关系必须一起核对。

为了展示操作，手写四个初答：M1回答1843，指出法学院与大学更名不同；焦点M2先答1887；M3也答1887并引用P15/P17；M4不给终答，提醒要区分雇主机构。这些人为设置只供接口与语义例子，不算专家校准或自然错误事件。

| 条件 | 与C00不同的内容 | 保持一致的内容 |
|---|---|---|
| C00 | 常规回应 | 全部20段、M2先前答1887、M1/M3/M4消息 |
| C10 | 增加“P15/P17、标题、哪些发送者引用”的定位表，正文仍在原资料中 | 同题/原文/初答/消息，不替任何人补正确来源 |
| C01 | 加入后果核对提示：哪些陈述支持、排除或未确定当前候选判断 | 不给正确后果，不要求跟随M1 |
| C11 | 同时加入上述两项 | 相同任务与消息 |
| G | 加一般性检查提示 | 对照多一段提示/注意力的作用 |
| N0 | 去掉所有同伴消息 | 全部原文和M2自己的1887初答仍在 |
| N1 | N0加同一份后果核对提示 | 检查此提示是否只是改善自身推理 |

模型看到的消息只有实际表述和来源编号；上表对正误的说明、M1候选配置E的身份都不进入payload。M3的引用编号合法，但其推断把更名日期当创立日期，因此引用合法性不能代替语义有效性。

### 长度检查带来的修订

v0.1把发送者引用的原段全文再复制一遍，压力输入达17,918参考token。v0.2只增加索引/标题/引用者，正文保持完整单份，压力输入降至10,802。此例七条件输入为2,992–3,410参考token。数值不含真实后端聊天模板、schema隐藏包装或思考token；不是显存/上下文保证，也不是模型实际usage。

S的含义现在是**已有来源定位更清晰**，不能据其效果直接声称“信任改变”；A/G长度和实际推理仍须报告。没有来源引用时S可以不生效，这类题保留并记录，不按结果静默删除。
