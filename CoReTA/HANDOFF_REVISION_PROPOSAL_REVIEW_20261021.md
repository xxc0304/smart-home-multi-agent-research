# 核查后接续修改建议：设计复审

日期：2026-10-21。审核刚才提出的“具体修改建议→相关贡献者回应→整合者比较”的方案。采用research-review本地流程；未委派外部审稿者。`review_independence: same-family`，`acceptance_status: provisional`。无新实验、无运行时代码或已冻结协议修改。

## 1. 结论

保留“修改前后需要比较依据”的方向，收窄“增加贡献者回应”部分。方案是针对当前负结果的待测修订，不是已成立的新架构或创新贡献。现有SPEC第5—7节和REPLY已覆盖相关成员路由、局部检查、拒绝错误建议及保留未决；不能将它们重新描述成新组件。

推荐先明确修订决策，再按需启用现有check/ask；不将每次核查强制扩成一轮辩论。

## 2. 上一条建议中成立的部分

- 集中CoReTA工作版本L1为6→10→12，有可定位的修订退步；核查意见已收到，driver实际接受并改变排序。这支持检查采纳依据，而非继续修格式。
- 旧关系未被证明，不推出相反关系成立；指向来源的引用不自动支持来源没有给出的比较判断。应检查替代方案的依据，而非仅要求处理了V引用。
- 普通讨论允许后续成员反驳错误纠正，这提供了一个值得检验的机制候选。

## 3. 必须修正的推断与设计

### 3.1 普通讨论成功不证明多方回应是成功原因

两条轨迹不仅有互动结构差异，还包含不同采样、完整初答、上下文、回忆经典排序与调用量。集中CoReTA的C4已经提供正确完整排序，但整合时未保留；这说明错误在最后两次核查之前已发生。仅补核查后对话不能声称修复了全部失效。

应分别观察初次整合损失与后续修订损害，不把普通讨论的一次成功直接归因于特定组件。

### 3.2 指出错误不应以能够提供修复为前提

成员可以证明候选不满足原题，却不知道正确替代答案。检查者不必每次给出完整修复。应区分：

- **发现缺陷**：观察、矛盾、反例或任务违反成立，可使旧结论失去支持；
- **提出替代**：若要采用新结论，还需说明它如何处理上述缺陷。

“没有替代方案”不能成为拒绝有效反例的理由；反过来，“提出了反对意见”也不能认证替代方案。二者可以在同一回复的简短文字中表达，当前不必新增一组复杂字段。

### 3.3 不能默认找原作者，也不能假定多一人更正确

本次正确排序C4的作者A2本身就是driver。要求交回原作者可能形成同一模型的自我重复。集中条件下资料持有者A1又恰好是提出错误修订建议的检查者，返回资料持有者也不保证得到更好判断。

应根据当前缺少的判别资料或操作选择成员；原作者可澄清自己的意思，原始资料持有者可确认事实，另一成员可检验局部推导。身份与参与人数不提供正确性担保。没有可以完成的检查时，不为凑齐互动而请求。

### 3.4 不应强制“每次核查后都请人回应”

明显计算错误可直接重算修复；已经提供充分依据的建议可直接采用；无实质理由的建议可直接拒绝。只有某项关键资料、推导或冲突尚未对齐且有望取得时，才使用现有ask/check。程序能约束预算与引用，不能机械认证一段自由文本已经构成充分证据。

### 3.5 保留旧答案也不是默认正确

如果新意见已有效推翻旧结论，就不能因缺少完整修复而继续把旧结论当作已支持结果。应标为未决，尝试其他路径或以有局限的完整候选交付。最终任务可能要求给出一个顺序；选择最佳努力候选与宣告其关系已成立必须分开。

## 4. 收窄后的最小设计

保持CONTRIBUTE/APPLY/REVIEW/REPLY四种调用，已有成员、资料权限、预算和输出格式不扩张。以下为设计建议，尚未改提示或代码。

1. REVIEW定位一项重要问题，区分“已发现的缺陷”“尚缺支持的疑问”和“可选修改”；不要求每次都找到缺陷或给出修复。
2. APPLY在改变被质疑结论前，比较原方案与替代方案的任务依据：新观察究竟否定什么，替代结论又由什么支持。可以接受、部分接受、拒绝、求助或保留未决，不以修改幅度证明已处理。
3. 若判断取决于他人可访问的资料或可完成的局部检查，沿用现有request→REPLY→APPLY，只问一个可改变决策的问题。不是让成员再泛泛表态赞成谁。
4. 无法取得判别依据时，记录该关系未决并按预算给出最佳努力候选；不默认反转，不按投票、置信度或隐藏分数选取。

无争议路径仍可为3次贡献+1次整合+1次核查；按需回复计入原最多3次干预和20次总尝试，不增加固定轮次。该设计让协作更有针对性，是否有效仍需实测。

## 5. 如何避免把新增文字或调用量误认成机制收益

先用相同公开贡献与同一初始工作解作开发分支，分别评估初次整合和后段修订，避免不同初始采样掩盖问题。既有NASA失败可作已知诊断案例，但不能作为修改后独立验证集，也不能使用参考排名在线挑版本。

优先隔离两项变化：先比较现有修订与明确比较依据的修订；如还需要检验定向回应，再与采用同一比较规则但没有该回应的分支比较。若归因于跨成员回应，还需控制相近的额外推理机会；成本可仍为次要指标，但额外计算量是机制归因的混杂因素。

关注最终正确性、纠正错误的修改与引入错误的修改。对双方都错但最终改善的情况也保留连续指标；不能只报告原答案正确时是否被保护，以免退化为禁止修改。所有分支预算和记录方式预先固定。

主评估仍需事先选定的信息差任务及资料效应检查。这与本次局部修订诊断互补：前者检验专长利用条件，后者检验是否更可靠地改变结论。不得为了复现原论文而只筛选普通讨论失败的样本。

## 6. 创新性与处置

“让原作者回复”和“让整合者比较理由”本身不能当作新的核心创新，且前者大部分已有实现接口。当前贡献是把负结果定位到可检验的修订决策问题。只有后续形成不同于泛用反思/讨论的具体控制机制，并证明它改善专长利用，才适合上升到方法贡献。

因此，上一条建议应降为**待验证的最小修订假设**：先改清决策规则，复用现有接续能力，按需调用；不宣布已经找到了普通讨论成功的原因，也不立即搭建新组件。
