# 项目小阶段审核机制

制定：2026-10-30。直接依据：用户要求“每一个小阶段进行审核，看看当前有没有按计划执行、有没有偏离中心”。本机制与现有research-workflow记录方式、WORK_PLAN及EXPERIMENT_CHARTER衔接；不以更多文档代替研究进展。

## 研究中心与当前工具

总问题：**多智能体团队为什么有时不能利用具有真实任务优势的成员，甚至损害其表现；哪些过程又能保留有效贡献并实现有益纠错？**

专家自身表现、表达/分享、接收理解与使用、其他成员干扰、最终整合是候选分析环节，不是已验证的唯一分类或原因。训练Qwen专家、信息分持、oracle专家揭示、E/R等均是研究工具/候选设置，不自动成为新的项目中心。判断新价值按实质新增认识或改进，不要求绝对原创，不因局部相似不断收缩问题。

## 何时审核

- 每个有明确目标与交付的小阶段结束时，默认审核，不等待用户提醒。例如资产盘点、对象定义、近邻比较、8例试标、采样扩展、任务选择、训练/实验方案、试跑、结果分析。
- 小阶段开始前，在工作执行表或当前方案中写清目标、范围、主要交付和完成条件；可复用现有W编号，不为每个工具调用建阶段。
- 发生改变研究对象/主要任务/主张、预算明显变化或重要反例时，立即补一次受影响项审核；长阶段未结束但需要交接时做中途检查，不假称已结项。
- 实验开始前仍执行EXPERIMENT_CHARTER及相应预检；阶段通过不替代实验启动审核、资源到位或用户已有授权范围。

## 每次检查什么

| 检查项 | 必须回答 | 记录要求 |
|---|---|---|
| 对准中心 | 这项工作怎样帮助解释专家优势利用/受损或有益纠错？ | 用一句话连接具体研究问题；训练成功不是论文问题已解决 |
| 按计划执行 | 计划做什么、实际做了什么、有什么未做/额外做？ | 对照W编号与实际文件；草稿、下载、提取、人工核验、盲标分开记 |
| 证据与主张 | 当前能知道什么，仍不能知道什么？ | 给原文/数据定位；观察、假设、因果结论分开；重复不当独立题 |
| 本阶段价值 | 新消除了哪个不确定性，是否足以支持下一动作？ | 阅读/准备阶段不要求显著提升或完整创新；近邻按实际贡献比较 |
| 替代解释与偏移 | 是否在追工具、训练规模、局部个案或仅追正结果？ | 区分已发生偏离与潜在风险；列最重要的替代解释及必要处理 |
| 资源与范围 | 人工、GPU、API、时间是否实际可用，工作是否在授权内？ | 计划资源不当现有资源；GPU申请不阻断独立离线工作 |
| 下一步 | 哪个具体动作最有信息价值、什么结果算完成？ | 最多列3–5项，指明依赖；不自动扩阶段、换主线或增加开支 |

## 判定与处理

- **PASS**：本阶段完成条件与证据相符，可以执行记录中指定的下一动作。仅代表该范围通过，不等于整篇论文、训练或确认实验通过。
- **REVISE**：有具体缺项、混淆或计划偏差。先在已授权范围内修正，再复核受影响项；独立可做的阅读/整理可以继续，不停下反复向用户询问例行修正。
- **STOP**：该条路线/动作已经没有明确研究价值、存在不能接受的研究完整性问题，或依赖条件不允许执行。停止对应动作，保留记录并给出替代工作；不等于擅自取消整个研究方向。

审核结论必须写明“允许推进什么、暂不进入什么”。不能用“总体基本通过”掩盖关键缺项；也不能因为一个受限步骤未通过而冻结所有无依赖工作。

若确需改变主问题、重要资源承诺或超出现有授权，明确提出具体变更及原因；常规审核和可逆修正默认执行，不新增逐项用户批准流程。

## 谁审核与怎样记录

助手默认做有证据的逐项审核，标为“助手自审”；不能称作独立审稿或人工复核。重要转阶段仍按WORK_PLAN由导师/合作者复核；独立案例标注必须有真实独立判定记录，不能用助手自审替代。尚未完成的独立复核如实保留。

记录写入当前计划目录的STAGE_REVIEWS.md，同步WORK_TRACKER中的审核列、CURRENT_STATE/handoff；涉及新假设或范围取舍时更新brainstorm。每个小阶段通常一条短记录即可，只有复杂阶段才单独建文件。已有通过项不因下一次对话重新全套审核，只检查改变或受影响部分。

每条记录至少包含：日期/W编号、目标与完成条件、实际证据、按计划与对准中心判断、关键缺项/替代解释、PASS/REVISE/STOP、允许的下一动作、审核者与范围。
