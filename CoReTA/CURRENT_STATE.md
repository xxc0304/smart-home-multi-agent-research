# 当前状态与交接（2026-10-18）

## 研究问题

团队如何将成员已有知识或新产生的贡献用于接收者的具体未完成步骤，避免正确专长在讨论中被覆盖，并使协作带来完整任务收益？目标不止于帮助弱成员，还包括提升团队整体能力。

## 当前设计

三个执行 Agent 先独立起草；预定主解题者形成工作方案，选择继续、自主求助、请求检查、请求替代解或结束。帮助请求指向具体步骤，其他成员提供贡献并接受工具或另一成员检查。主解题者展示采纳、拒绝和方案更新，再决定后续动作。程序调度器只检查结构、预算和合法性，不免费判断答案正确性。初版最多两个帮助周期，这是原型限制，尚非最优结论。

详细规则以 [ARCHITECTURE_V0_2.md](research/complementary-help-design-20261018/ARCHITECTURE_V0_2.md) 为准。主解题者在配对比较中固定；学习路由不是当前主版本。允许检查和替代错误方向，不赋予专家绝对否决权。

## 待验证的贡献

- 显式的步骤定位、定向帮助及应用反馈是否优于普通讨论、审查或聚合。
- 在总预算匹配下，是否优于强单体继续推理和相关架构。
- 收益是否来自成员贡献被实际利用，而不只是更多调用、选择或汇总。

这些是研究假设，当前没有实现、实验数据、有效性结论或已确认首创的主张。

## 下一步顺序

1. 固定最小协议、任务与评分、预算口径及比较方法的实现边界。
2. 实现本地端到端流程，验证调度与日志，不用脚本输出代替模型能力证据。
3. 小范围真实试点，检查帮助是否发生、是否被应用及失败类型；付费运行另按具体协议授权。
4. 通过试点后再扩大任务与模型，进行预算曲线、模块消融和贡献内容干预。

所有方法使用相同任务信息、工具权限及预算上限；对照允许自然补全和继续推理。完整任务集为主要评测范围，不仅挑选初稿分歧或成功互补的样本。仅准确率提升不足以唯一证明互补机制；需要预先规定的干预及轨迹证据。
