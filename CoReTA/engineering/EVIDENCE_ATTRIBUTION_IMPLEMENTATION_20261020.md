# 证据对象与版本归属：v7实现及离线验证

## 解决的具体问题

旧规则把任何审计记录中的精确不等都再次归为当前缺陷。即便旧对象已被替代，忠实保留旧反例也会阻止关闭。新增独立v7，不改任何旧运行、评分或候选。

## 规则

每条审计显式声明current/historical、audited_version、source_record_id。历史记录绑定唯一原记录，原版本、主张、案例ID、fact/item/input、expected/observed乃至其余原payload值保持不变（仅允许明确映射issue归属）。混合旧/新对象的记录不能自动转换成成功。

repair要把历史反例视为保留证据而非当前阻塞，必须同时满足：独立检查与原业务校验通过；原记录及案例完整重查；replacement_bridge说明removed并绑定全部原记录；当前同issue的审计明确绑定当前版本/步骤、覆盖原检查项且未被反驳；任一同issue当前审计失败、出现新异议，或依赖still_used/unknown时继续阻塞。

旧effective_outcome仍为finding_open，追加active_effect=historical_retained。旧账本与原问题证据不覆盖、不删值。关闭仍需原settle判定。rebuttal未放宽。

桥梁的“确实不依赖旧错误对象”仍需模型/人工核查，程序只验证绑定、版本和声明一致性，不能从任意数学/代码文本机械证明依赖消除。即使全套fixture通过，也不能宣称能识破所有虚假removed声明。

## 离线验证

新增8项检查，全套208次测试执行通过，入口help正常。真实A2混合输出不满足新schema，明确拒绝；没有修改它或改记旧结果。正例是人工显式拆分历史记录与当前记录、添加桥梁的fixture，仅验证状态机。

该fixture中原反例及旧effective_outcome保持，i0001可转为addressed；仍依赖/未知、替代失败（包括未被桥梁列出的失败记录）、漏检查项、错版本/来源、改写原观测均被拒绝。实际语义正确性仍待真实模型验证。

检查了9份已有冻结计划，所有来源hash匹配。本轮0 API，无新评分。设计、代码、契约schema和测试单独保存。
