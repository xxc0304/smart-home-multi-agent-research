# 最小检查适配器与逐问题状态投影实现

## 实现范围

新增独立src/coreta/minimal_review.py，不继承旧Runner，也未接外部模型或整题调度。旧运行器、提示和实验结果保持冻结。采用design/convergence规格：模型仅提交新观察、当前检查和逐问题理由，程序负责身份、版本、历史材料与记录生成。

### 已实现

- packet预检角色独立、当前目标版本、历史原案例定义、公开材料和必需约束。
- 按packet生成动态schema：issue键、case/target/task句柄有明确允许值。
- 请求关联ID由程序生成，绑定packet快照与当前候选身份；过期/重复响应不接受。
- 原始请求/响应、历史新观察、当前检查、逐项错误、状态投影分别追加保存。旧case从不改写；反驳可提交不同的新观测。
- 同对象修复、对象替换、反驳原异议三条处理路径。替换仍要求removed解释和当前检查；这属于模型语义判断，程序不证明实际依赖移除。
- 同量精确有理数不等保留当前冲突；不可解析精确数、uncertain、缺案例/约束或当前反例均阻断关闭。
- 新反例先处理；相关问题保持open。单个issue schema/句柄错误不会自动污染其他独立issue；整包JSON、角色或候选身份错误阻止全部关闭。
- 输入预算预检、完整原文反馈及适配器实例级两次修复上限。后续调度接入必须使用同一任务的共享额度，不能为每轮重建实例而重置修复数。

## 离线验收

新增15项测试，全套223次执行通过。覆盖三正例、改变原观测但保留历史、缺新观察不能关闭、仍依赖/不明、替代失败、重复/未知案例、角色与原文缺失、过期/重复packet、新反例优先、局部问题失败隔离、不可解析精确值、预算和修复额度。

原三正例为人工设计，不能当模型结果。边界回放收集9组既有运行中的29份去重真实输出，新适配器全部拒绝旧输出格式，没有自动迁移或把旧失败记作新成功。这只证明旧格式不会误通过，不证明新协议可恢复这些真实失败，也不是语义回放。

10份已有冻结计划来源hash全部一致。本轮0外部API、无新评分、无架构效果结论。

## 尚未完成与下一步

当前是离线适配层，不是已接入可运行的完整CoReTA。还需从真实当前候选/issue/证据状态构造ReviewPacket的程序映射，验证原文与每个句柄的归属，接入共享预算及provider完整/截断状态，然后冻结一次组件调用。

现有简单设计packet只绑定current_targets和原case；实际问题的required_task_refs必须来自明确的受影响约束，不能假装程序能从自然语言自动发现所有依赖。语义正确性、桥梁是否真实移除错误依赖以及模型遵守新契约的能力仍待验证。

下一步先做真实状态→packet映射与离线预检，保持同一正确候选；通过后一次单独标记的新契约组件核查，不直接跑完整题集或6次批量实验。
