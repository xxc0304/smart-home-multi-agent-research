# 审计引用契约修复与离线验证

新增独立 task_audit_reference_v3，继承冻结的来源绑定v2；不改写旧运行、提示或评分。

## 实现

- apply输入动态列出每个issue的expected_evidence_record_ids，首轮无审计记录时明确为[]。
- 明确区分审计记录ID与普通事件/步骤引用；普通支持引用仍放evidence_refs。
- 提交前逐issue反馈期望、实收、缺失、额外和重复ID。错误输出原样保留，不自动清空或改写。
- 集合一致后仍调用原完整validator，继续执行异议回应、repair/rebuttal、候选变化和后续检查要求；空审计集合不能跳过这些要求。
- 新入口 coreta.run_closure_reference，沿用预算及来源绑定；没有新增模型阶段或调用预算。

## 验证

5个新增测试，全套177次测试执行通过，CLI帮助可用。真实两份失败apply输出均重放出4个issue的ID冲突，原输出未改变。人工构造的空ID修正版仅验证该引用门控通过，不代表模型已学会、整份proposal通过或数学正确。匹配ID后父validator仍被调用，错误修复仍被拒绝。冻结v2计划25个文件哈希全部一致。
