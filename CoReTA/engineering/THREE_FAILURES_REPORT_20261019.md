## 3. 数学5134：CoReTA没通过；一个对照靠另一解释命中gold

CoReTA仍使用题面字面关系 `300=0.85×Ann`，得到Ann=`6000/17`、Alfred=`5881/17`，总量=`16981/17`，并指出非整数汽车数。建设与检查阶段增加了交叉等式、整数一致性核对，拒绝了某初稿把“15% fewer”改成“15 fewer”的923解释；最终未得到原gold983。

独立继续推理条件的A0在第二轮同时给出：

1. 字面解释的 `16981/17`；
2. 将关系改读成“Ann比Jared多15%”，得到345、338，总计983。

最终化保留两个boxed，最后一个是983。现有 `scoring_worker.final_boxed` 明确取最后一个框，因此prefinal与final均得到1分。

这是对照的原始评分通过，但不应报告成合作补出正确局部推导：该条件独立继续推理，983来自改变比较基数的替代解释，同时输出两个答案也不满足我们期望的单一明确最终答案。没有修改评分规则把这个1分抹掉，也不能只报这个1分而省略解释。

## 4. 代码615：所有条件仍未通过

三份初稿都采用：

```python
return [sum(t) / len(t) for t in tuples]
```

CoReTA最终仍是各内层tuple求平均。建设与检查阶段用了具体手算核对，如 `((1,2,3),(4,5),(6,)) → [2.0,4.5,6.0]`，没有提出按列平均的新方案。原测试要求各列平均，故仍未通过。

这里不能把完成了手算核对说成补出了缺失算法；当前交付主要确认了同一种题意解释，没有产生能满足原评价的改变。契约疑点与原0分均保留。

## 5. 代码802：原分仍0，并暴露真实流程故障

共享初稿主要使用查找最小元素位置的二分方案。CoReTA综合后，A1建设性输出两次引用：

```text
coreta-revision-3c517d99e0fb:e0003#s4
coreta-revision-3c517d99e0fb:e0003#s7
```

当前可见索引实际提供的是 `v1:s4 / v1:s7`，没有上述事件步骤别名。一次格式修复后仍未更正，运行器拒绝该贡献，未进入后续A2检查及A0应用；最后基于最后有效综合方案完成故障最终化。最终代码按原测试未通过。

因此这条轨迹不能描述成“完整互补流程执行后仍错”，更不能从它直接判断整个互补机制有效或无效。故障也暴露了修复提示只报泛化invisible reference、没有具体列出错误引用及合法替代的不足。当前记录未通过静默补别名或重跑覆盖。

另外，**被拒且未提交的贡献文本**还含有独立于格式的推理错误：对 `[1,1,2,1]` 声称候选返回3，并声称旋转0次也有序。按候选的 `hi -= 1` 代码手算，hi依次3→2→1→0，返回0；原数组也不是升序。可见“提供了一段证明”本身不代表有效局部贡献。该内容未进入A2检查，不能说检查者已认可或错误已传播到共同方案。

原测试的非循环有序数组问题仍存在；本次没有为了通过测试把隐藏规则补给模型。程序引用问题和贡献语义问题都值得继续诊断，但不是本轮临时修改实验条件的理由。
