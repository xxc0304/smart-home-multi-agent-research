# 独立请求的引用及中断策略修正

适用：新版本局部资源校准等彼此独立的请求。现有已冻结/中断批次不追溯变更。多Agent依赖链需另外明确分支失败后果，不能盲目套用。

## 本次根因

旧校准第14次JSON可读，只将引用首字母You写成you。旧规则要求逐字引文并让任何违约中止全部请求，因而13份接入后失去后10个独立观测。预检确认了程序会执行这条规则，却没有解决规则过于脆弱的问题。

## 已落实的变化

1. 模型只交来源编号source_ids，原文由宿主从当前可见资料确定性附上。无跨成员读取，无猜测真值。新接口不再要求模型抄写引文。
2. 主体结论可读而注释缺失或错误时保留结果和质量标记。无效来源编号不渲染证据，不能伪装成合法引用；评判可据此判缺少依据或错误应用。
3. 单个不可读结果隔离为quarantined，不重试，继续原计划其他独立请求。连续两个不可读停止；传输故障、用量未知、预算/冻结异常立即停止。没有扩大24次请求上限。
4. 每个预定槽位导出completed / quarantined / failed / not_run与原始记录。completed只表示主体可读，不等于正确；不得把缺失范围默认为范围正确。
5. 新接口不得启动旧manifest，不将旧14次与新结果拼接成一次完整实验。旧隔离文本仍可单列做定性分析，不能回写原接入状态。

## 已验证

28项相关本地测试通过；单次坏JSON模拟执行完24次、23份接入、1份隔离，零重试。连续坏输出、超时和未知用量按规则停止。完整新载荷模拟及48份历史公共层回放通过。旧冻结r2 hash检查仍有效。

新文件：tools/local_judgment_handle_contract.py、prepare_local_judgment_calibration_v2.py、run_local_judgment_calibration_v2.py。新准备包为runs/local-judgment-moon-calibration-prepared-20261025-r3，审核记录同目录。

本次修复未新增付费模型调用。新服务格式行为尚未实测，不能保证零违约；修正目标是减少可避免的机械格式负担，并避免单条独立失败毁掉整批信息。
