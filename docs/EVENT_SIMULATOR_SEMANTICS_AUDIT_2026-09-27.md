# HomeCoord-Bench 事件模拟器语义审查

日期：2026-09-27  
状态：代码级语义审查与离线回归；不构成物理校准、并发 API 测量或领域审核。

## 同一虚拟时刻的事件顺序

事件队列按 `(timestamp_ms, priority, insertion_sequence)` 排序。当前阶段顺序是：

| 阶段 | 事件 | 同刻语义 |
|---:|---|---|
| 0 | 外部状态更新、动作完成 | 外部事件预先入队，因此同一时刻先应用外部更新，再应用动作完成效果；多个同类事件按入队顺序处理。 |
| 1 | 新任务发布 | 读取上述更新和完成后的共享状态，并记录当时的状态版本。 |
| 3 | 提案返回 | 根据虚拟返回时间进入协调流程。 |
| 4 | 动作开始 | 再检查前置条件，并应用动作开始效果。 |

因此，边界时刻上的既定次序是“外部更新 → 动作完成 → 任务读取状态 → 提案返回 → 动作启动”。动作完成与外部事件同刻时，完成效果最后写入相同状态路径。阶段编号在实现中使用具名常量；同刻测试锁定了外部更新、完成和任务发布的顺序及任务看到的状态快照。

## 状态版本与动作生命周期

- 初始状态从 `initial_state.version` 开始。外部事件把版本提高到至少当前版本加一；若输入给出更高版本，则采用更高值。
- 动作开始效果非空时，启动会递增版本；动作完成总会递增版本，即使完成效果为空。
- 提案带有任务发布时看到的版本。模拟器不会仅因版本号变旧就拒绝动作；只有当前前置条件不满足时才拒绝，并根据版本判断拒绝原因是否为 `stale_state`。
- `action_started` 应用开始效果，最终物理效果延迟到 `action_completed`。已启动动作目前不能取消，也没有补偿／恢复执行语义。
- 动作结束后，其资源预留现从活动预留集合移除；历史事件仍保留在轨迹中供审计。

## 模拟轨迹到评测器的映射

事件模拟器把外部 `state_update` 原样投影到评测轨迹；`action_started` 投影为带动作区间和开始效果的 `action_effective`；对应的开始效果状态更新不会再单独投影，以免重复应用；`action_completed` 投影为完成时的状态更新。投影事件没有另行添加序号，评测器按时间稳定排序，所以同一时刻保留事件模拟器输出的先后顺序。

`first_action_start_latency_ms` 由真实启动事件计时；`first_goal_progress_latency_ms` 只在动作开始／完成效果使目标距离缩短且当前约束满足时计时。`task_completion_time_ms` 可以由外部事件满足目标，而 `task_service_rate` 统计必要动作是否被服务，两者需要并列报告。每项被接受动作的预计完成时刻由启动时刻加声明持续时间计算；当前模型没有中途取消。

## 已锁定与仍未覆盖的边界

新增的同刻回归测试验证：如果外部更新、动作完成和新任务发布发生在同一虚拟时刻，轨迹按上述顺序记录，任务请求快照读取完成后的状态及版本。全套离线事件测试还覆盖提案异步返回顺序、前置条件重检、动作效果分阶段写入和完成时的约束检查。

后续补齐了在途前提失效的来源：外部更新、另一动作的开始效果、另一动作的完成效果都会检查已在途动作的显式 `requires` 是否由真变假。逐条记录保留首个触发来源、任务与 Agent；总数按受影响动作去重，另报跨 Agent 数。用制冷期间另一个 Agent 关闭空调的配对探针验证了两个动作阶段；原 9 草稿基线矩阵的结果与报告哈希保持不变。探针见 `docs/AGENT_CAUSED_INFLIGHT_PROBE_2026-09-27.md`。

以下边界仍需在扩充评测前处理或明确排除：

1. 决策提供器是同步调用的；随后按实测或设定的延迟安排虚拟返回事件。它可以重放逻辑上的并发到达顺序，但不测真实并行 API 请求、网络抖动或服务端排队。
2. 在途前提失效仅针对 episode 明确写出的 `requires` 与状态补丁；未编码的物理依赖和连续环境演化不会被自动推断。检测到失效也不会中止动作，不能将该计数当作修复能力或因果风险的完整度量。
3. 安全状态变化会由外部更新、动作开始效果和完成效果共同计入过程约束指标，但专门的 `unsafe_state_onset_during_action_count` 在动作开始效果应用前登记活动动作、在完成效果应用后移除动作；由动作开始效果触发的安全恶化可能漏计，而由完成效果触发的变化会记录当时仍登记为在途的动作。该计数应结合违规区间与完成违规指标解读，尚不适合作为独立的因果归因量。
4. 轨迹评测器以稳定排序保留相同时间戳的输入顺序。若轨迹先被导出、重排或由其他实现生成，应显式保留事件序号；只保留时间戳不足以恢复同刻因果顺序。
5. 每次动作完成都会递增状态版本，即使完成效果为空。这代表动作生命周期发生了提交事件，不等同于状态值一定改变；报告版本变化时需保留这一口径。
