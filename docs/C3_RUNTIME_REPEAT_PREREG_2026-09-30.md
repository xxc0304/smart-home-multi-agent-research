# C3 计算开销与模型重复：运行前方案

固定此前规模／发布网格与输入哈希。计算开销测量覆盖六个2/4/5 Agent结构、同时及紧急晚到两种发布、三种策略（等齐期限、已发布可行性严格版及安全服务退化版）：36组，每组2次热身、20次正式测量，共72次热身及720次正式运行。

以 perf_counter_ns 测量带计时包装的完整模拟器耗时，以及每次精确可行性求解调用耗时。完整耗时包含验证、脚本决策、调度、日志和评估，不能称为纯协调器耗时；求解调用耗时也不包括完整协调逻辑。记录中位数及范围、运行平台，不外推真实家庭端到端时间或大规模求解性能。不把20次运行的计时尾部宣称为部署P99。

**本轮不向虚拟时钟直接注入测量值。**当前协调延迟机制先完成部分可行性判断，再等待派发；可靠的计时接入需要“判断完成事件＋重新读取状态／预约检查”的设计。完整模拟器的总耗时也不能当作每个动作的协调耗时。先分别报告，避免双算或错误因果推断。

模型复验：N2-1／N4-1／N5-1，每组同时发布、紧期限、高压力条件独立重新采样3轮；共33个DeepSeek请求，每请求最多一次尝试。Agent请求隐藏评分答案，组内并发；组间顺序运行。不是新任务结构或领域外验证。

每轮保存提案后，在四个条件中配对复评：紧期限同时高压力、紧期限晚到高压力、宽松期限晚到高压力、紧期限晚到低压力。四种同信息策略是门控重试、等齐期限、已发布可行性严格版、退化服务版；晚到条件另列完美预告。计划171次回放。晚到等条件仍是固定提案反事实，不能说模型根据晚到现场状态重新推理。

报告授权及服务选择正确性、提案返回顺序、全任务服务／按时、逐任务启动等待／完成迟延和缺失数。不删错误提案；API失败留存，相关回放缺失，未完成批次不能按成功统计。保存中间进度，再次运行不自动重发已记录失败批次。资源周期／功率／期限为受控设定。
