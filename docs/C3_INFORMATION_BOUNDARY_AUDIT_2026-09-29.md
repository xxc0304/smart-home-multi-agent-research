# C3 在线信息边界审计：强规则的满分来自什么

日期：2026-09-29。状态：探索性机制回放，不是冻结 benchmark，也不是现实部署性能。

## 对照设定

在完全相同的两个任务模板、三档名义资源压力、六个到达时刻与“无插入”配对条件中，复用先前 6 批并发 DeepSeek 提案。每种策略回放 126 个条件，共 378 次回放；**没有新增 API 调用**。126 个条件高度相关，不能当作 126 个独立样本。

所有策略使用相同安全门控和设备容量。`ObservedTaskFeasibilityCoordinator` 与 `RobustReserveCoordinator` 都在尝试启动动作时调用同一个小规模精确排程检查。前者只纳入**当前已发布且未完成的任务**；后者额外知道一个潜在紧急任务的精确功率、时长、截止时间和六个可能到达时刻，但不知道是否真的到达、何时到达。`GateRetryRule` 是不预知未来、被安全门控拒绝后再尝试的较简单规则。

## 关键结果

| 模板与名义压力 | 条件 | 仅看已发布任务的精确排程 | 精确未来先验参考规则 | 安全门控重试 |
|---|---|---:|---:|---:|
| 厨房，ρ=1.2 | 紧急任务插入 | 0/18 全任务按时 | 18/18 | 0/18 |
| 厨房，ρ=1.6 | 紧急任务插入 | 0/18 | 18/18 | 0/18 |
| 早晨出发，ρ=1.6 | 紧急任务插入 | 0/18 | 18/18 | 0/18 |
| 厨房，ρ=1.6 | 无插入 | 3/3；首动作中位 1.072 秒 | 3/3；首动作中位 120.100 秒 | 2/3；首动作中位 1.063 秒 |

低压力（ρ=0.8）下三种策略都能在两个模板中完成任务；早晨模板 ρ=1.2 时，仅看已发布任务的精确排程和强先验规则也都能完成。不能只报道上述有差异的行并声称普遍方法缺口。`ρ` 是模板的名义负载/容量比例，不是现实家庭发生频率。

这个对照支持一个**机制层面**的结论：在当前模板里，知道未来任务的精确候选集合能显著改变决策；不存在插入时，这种保守预留又可能极大拖慢厨房的首动作。结果**不支持**“现实在线协调器必然无法达到强规则的效果”，也不支持“我们已有新算法”。

## 信息泄露与有效性边界

1. `ObservedTaskFeasibilityCoordinator` 在排程检查时，从 episode 中仅筛选已经发布且未完成的任务；不读取 `potential_urgent`。未来任务的实际到达由模拟器事件队列处理，策略看不到本次是否插入。
2. 本轮发现请求中的 episode 标识包含未来到达条件；此外，协议对 `goal_visibility=all` 的 Agent 会给全局 `goals`，可能泄露未发布任务。当前两个 C3 专业 Agent 模板设置的是 `goal_visibility=local`，所以**全局目标在这两个专业 Agent 请求中原本就不可见**；目标泄露主要是其他架构／新模板的风险。现已为动态任务实验加入可选的 `blind_future_task_arrivals`：在适用时隐藏未发布目标，并使用不含未来到达条件的公开标识。无插入／有插入的同一已发布任务请求已做一致性测试。**但这轮仍不是真正在线模型盲测**：模型提案来自此前任务共同发布条件的保存回放，改变发布时间后没有重新询问模型；保存提案可能已经受原始上下文影响。
3. 当前任务功率、周期和截止时间在发布后被当作精确已知；它们主要是受控假设，设备可控性与时变负载仍待核实。穷举检查只覆盖 3–4 个固定负载任务。
4. 厨房插入条件的 0/18 与 18/18 来自同一模板、三批提案、六个到达时刻的重复组合，不能作为跨家庭统计显著性证据。

## 对后续研究的判断

把强先验规则定位为**信息上界参考**，不能当作普通在线基线；把只看已发布任务的排程器定位为强但信息合理的机制基线。已用修正后的请求完成一轮真实模型小样本，见 `docs/C3_BLINDED_LIVE_MODEL_PILOT_2026-09-29.md`。接下来应研究较现实的先验（例如仅有历史到达范围，且时长/功率是区间而非精确值）。这些先验要有来源或明确声明为敏感性设定。只有在多模板、同信息强基线下仍出现稳定的安全—按时—响应取舍，才值得推进新协调方法的主张。
