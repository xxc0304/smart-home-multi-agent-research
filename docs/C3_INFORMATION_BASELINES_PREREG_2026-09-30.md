# C3 强基线与信息差对照：运行前方案

日期：2026-09-30。本批继续使用上一批已锁定的 108 个规模／发布／期限／容量输入和已保存模型提案，不新造冲突或改期限，不新增 API 调用。程序为 `homecoord_bench/probe_c3_information_baselines_20260930.py`；源输入、提案及本批分析设计哈希保存在 `revision_drafts/20260930_c3_information_baselines/manifest.json`。

## 三个版本

| 版本 | 决策信息 | 执行能力与目的 |
|---|---|---|
| 已发布可行性严格版 | 仅已发布任务、已接受动作、公开服务周期及负载 | 用精确小规模可行性搜索决定是否接受当前启动；继续使用现有派发规则 |
| 已发布可行性服务回退版 | 与严格版相同 | 若已发布任务已无法全部按时，则通过共同门控继续完成服务，允许报告超期 |
| 完美预告预留版 | 额外公开晚到任务的身份、周期、负载、期限和精确发布时间 | 保留不可中断能力，检验增加未来信息是否改变结果；它是有信息优势的诊断对照 |

前两版使用已有 `ObservedTaskFeasibilityCoordinator`。服务回退由隔离输入的 `observed_feasibility_fallback=true` 开启，历史输入不受影响。完美预告版使用已有 `RobustReserveCoordinator`，只对 `urgent_late` 单一未来任务条件运行。它的预告是从受控未来事件提取的额外信息，不能充作现实预测器，也不能当成相同信息条件下的方法优胜。

三个版本都使用同一不可中断固定周期和共同启动前安全门控。公开周期和负载来自专业 Agent 可见的工具描述，两个服务预设成本相同；不依赖隐藏的正确操作来推断周期。精确检查当前可行性不等于全局最优调度：未来响应时延未由搜索保证，派发顺序仍为已有规则。

## 全量运行与指标

两已发布版覆盖全部 108 条件、所有响应排名，各新增 5,256 个离线单元；完美预告版覆盖晚到条件的全部排名，新增 1,752 个。合计 12,264 个新单元。对上轮固定的三组真实模型提案做相同回放，共新增 126 个单元。全部旧五策略结果保留作配对参考；未来预告版单独标注信息优势。

同时报告全部任务服务、全部按时、最终服务目标、首次安全动作时延和可行性回退次数。若严格版因按时已不可行而不再服务，不能仅因没有违规称其更优。所有低压力与宽松期限控制保留。模型部分属于固定提案反事实回放，仍不是各条件下在线重新推理。

记录每个单元的模拟器墙钟耗时，包含事件处理与排程检查；它不是纯协调器计算时延，不计入虚拟首动作时间，因此不能据此宣称更强的搜索有零计算代价。未来若进入端到端实验，需要实测并计入调度开销。

## 必要检查

验证公开工具成本与声明负载一致；检查删除未发布任务及其元数据不会改变两个已发布版的发布前动作；验证服务回退不会读取未来元数据、不会绕过门控。检查新旧策略使用的所有源文件哈希未变，完整报告失败与服务损失。任何规则不足、信息不足或新实现缺陷都分别记录，不称为已确认的新算法空白。
