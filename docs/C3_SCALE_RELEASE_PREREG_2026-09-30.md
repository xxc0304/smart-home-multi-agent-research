# C3 规模、发布时间与期限试验：运行前方案

2026-09-30。本方案与程序在本批可行性检查、策略回放和模型采样前固定。继续评测协调价值的条件依赖，不改变 HomeCoord-Bench 命题。

## 候选构造

固定八设备池与种子 `2026093002`，分别生成两组 2 Agent、两组 4 Agent、两组 5 Agent 的设备集合，全部纳入。各任务使用既有设备池的受控功率、周期和紧截止窗口，每位 Agent 提供两个分类服务预设及关闭工具。预设资源成本相同，所请求预设按独立确定性种子选取；这仍是清楚需求与小工具目录的试点。设备服务与热模型、卫生模型、真实充电量无校准联系。

Agent 数量改变时设备组成也改变，因此结果只表示覆盖了这些规模，不能声称纯粹增加 Agent 数量造成某个成功率变化。共用设备池生成的集合也不等于独立真实家庭样本。生成代码为 [`probe_c3_scale_release_20260930.py`](../homecoord_bench/probe_c3_scale_release_20260930.py)，输入哈希将记录于 `homecoord_bench/revision_drafts/20260930_c3_scale_release/manifest.json`。

## 三个配对因素

1. **容量压力**：总负载／容量比 0.8、1.2、1.6，0.8 是无容量冲突对照。
2. **任务发布**：全部同时；最早截止任务晚 60 秒；最早截止任务先发、其他任务晚 60 秒。延迟发布的任务保留其发布后的完整服务窗口，避免把“未知未来请求”与“人为减少该任务的完成时间”混在一起。
3. **期限**：紧档沿用设备池窗口；宽松档每个任务窗口等于自身周期＋全部任务周期之和＋10 分钟，目的是明确的充足期限对照。宽松档和低压力档是不同控制：宽松期限仍可能有容量冲突，而低压力不会有本批容量冲突。

共六集合×三压力×三发布时间×两期限，共 108 个输入条件。先锁定全部输入，再对每个条件用知道全部任务的理想排程标注可行性，并复核返回排程的发布、容量和期限。不可行条件保留；单个设备功率大于预算或任务本身不可排程，不解释为协调失败，也不按结果改参数。

## 基线与信息边界

固定五策略：独立＋共同安全门控、门控后重试、约束协调、等齐**已经发布任务**的提案、容量感知期限规则。专业 Agent 仅见自身任务、局部状态、自己的三个工具；不见全局评分目标、容量压力标签、其他任务或标准动作。模型请求使用匿名公开 ID。中心规则使用容量、已发布任务的期限和负载上界；不读取未来发布任务的身份、期限或发布时间作决策。理想排程只用于事后题目诊断，不作为在线策略。

对 2/4/5 Agent 分别穷举 2/24/120 种提案时延排名，响应持续时间为 800＋排名×200 ms，**相对每项任务发布时刻计时**。错开发布时，排名不等于全部任务的最终返回顺序，需如实标为响应时延排名。完整正确提案回放为 `2×(2+24+120)×2×3×3×5=26,280` 个单元。它们是六个作者构造集合的配对干预，不是 26,280 个独立样本。

## 真实模型采样与结论范围

在查看离线结果前固定每个规模第一组 `N2-1/N4-1/N5-1` 为 API 子集。各采一批，同时发布、紧期限、压力 1.2，共 11 个并发专业 Agent 请求。记录工具合法性、需求选择、并发返回顺序和 API 时延，不按输出替换失败任务。

采样后的原始动作与返回时延另做 270 个容量／期限／发布模式的**固定提案反事实回放**。这些回放的请求条件发生变化，没有重新让模型读取变化后的期限和时刻；不能称模型实际在全部条件下重新规划。局部目标和设备初态在发布干预中保持可执行，所有动作仍需统一安全门控。只可解释为“给定该组真实模型提案，改变调度条件的结果”。

主要报告每个集合及条件的任务服务、全部按时、最终服务目标、首个安全动作时延；单独列不可行条件。比较返回顺序时等权，跨规模聚合不能把 5 Agent 的 120 排列当成比 2 Agent 的两排列更多独立证据。既有强规则成功、截止宽松无额外协调收益、未来任务让等齐失效等结果都保留。
