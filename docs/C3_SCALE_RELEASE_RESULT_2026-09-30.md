# C3 规模、发布时间与期限试验结果

日期：2026-09-30。运行前方案见 [`C3_SCALE_RELEASE_PREREG_2026-09-30.md`](C3_SCALE_RELEASE_PREREG_2026-09-30.md)。本轮覆盖 2、4、5 Agent，每种规模两个作者生成的设备集合，108 个容量／发布／期限条件全部有理想可行排程，并通过专业 Agent 输入审计。完成 26,280 个正确提案离线单元、11 次真实 DeepSeek 请求、270 个真实提案的固定条件反事实回放，另有三个事后承诺动作机制检查。

## 主要发现

**协调收益取决于资源、期限和请求发布时间。**资源宽松时，所有策略都按时；期限宽松时，重试及三种协调策略都最终服务全部任务并按时。紧期限与紧容量同时存在时，简单重试能恢复服务，但不保证按时；等齐当前请求的提案在同时发布时表现良好，未来紧急请求晚到时仍可能超期。这与“协调总是更好”或“等齐总能解决”都不相符。一个五 Agent 结构在晚到条件下仍全部按时，也要保留这个正例。

**这些结果覆盖六个结构，而非 26,280 个独立样本。**2、4、5 Agent 设备组成不同，不能归因成“只增加 Agent 数量导致失败”。响应时延排名的阶梯间隔也由实验设定，规模越大最大响应时间越长，不能直接当实际模型规模开销。

## 完整回放与对照

所有输入由固定八设备池及种子 `2026093002` 生成，六组均保留：

| 集合 | Agent 数量 | 设备 |
|---|---:|---|
| N2-1 | 2 | 洗碗机、热水器 |
| N2-2 | 2 | 充电桩、洗碗机 |
| N4-1 | 4 | 烤箱、水壶、充电桩、灶台 |
| N4-2 | 4 | 灶台、烤箱、水壶、热泵 |
| N5-1 | 5 | 洗衣机、热泵、洗碗机、热水器、水壶 |
| N5-2 | 5 | 充电桩、灶台、烤箱、洗衣机、热泵 |

每集合两档期限、三档容量和三种发布时间；2/4/5 Agent 分别穷举 2/24/120 个响应时延排名，五策略全部运行。排名对每项任务发布后的响应持续时间赋值，所以错开发布时它不是全局返回顺序。

低压力 `ρ=0.8` 的所有条件、所有策略都全部按时。期限宽松时，重试和三种协调策略在所有容量与发布时间条件下都全部服务且按时。资源收紧后，独立不重试策略存在服务损失；重试与三种协调策略在**全部条件**下都最终服务全部任务。因此重点应放在按时结果和等待成本，而非仅用最终服务打败不重试基线。

下面表格限定**紧期限、最紧容量 `ρ=1.6`**，数字为全部任务按时的响应排名数／预定排名数。每行是一个结构上的配对干预，不作跨行独立家庭统计。

| 集合 | 同时发布：重试 | 同时发布：约束协调 | 同时发布：等齐 | 同时发布：容量感知 | 紧急任务晚到：等齐 | 紧急任务先发：等齐 |
|---|---:|---:|---:|---:|---:|---:|
| N2-1 | 1/2 | 1/2 | 2/2 | 2/2 | 0/2 | 2/2 |
| N2-2 | 1/2 | 1/2 | 2/2 | 2/2 | 0/2 | 2/2 |
| N4-1 | 12/24 | 8/24 | 24/24 | 10/24 | 0/24 | 24/24 |
| N4-2 | 12/24 | 8/24 | 24/24 | 10/24 | 0/24 | 24/24 |
| N5-1 | 60/120 | 60/120 | 120/120 | 80/120 | 120/120 | 120/120 |
| N5-2 | 44/120 | 42/120 | 120/120 | 66/120 | 0/120 | 120/120 |

最早截止任务晚到 60 秒时，其自身服务窗口保持不变，其他任务的功率、周期、目标和窗口也不变。晚到造成的是当前规则已启动先前任务，未来请求到达时可能缺少容量；不是故意压缩晚到任务的可用时间。不是所有晚到结构都会失败：N5-1 中等齐仍全部按时。

宽松容量且同时发布时，即时策略首次安全动作均为 900 ms，等齐在 2/4/5 Agent 上分别为 1100/1500/1700 ms。200/600/800 ms 等待来自固定的响应时延阶梯；没有人为加协调计算耗时。

## 真实模型提案

运行前指定 `N2-1/N4-1/N5-1`，在同时发布、紧期限、压力 1.2 下各采一批并发专业 Agent 请求，共 11 次。11/11 动作合法且符合本地需求，11 次 API 完成、无失败，累计 14,053 输入 token、1,565 输出 token。每个结构只有一批，不能估计稳定模型成功概率。

采样后的提案和并发时延固定，回放至全部 18 个条件和五策略，合计 270 个单元。下面只列紧期限、压力 1.6 的等齐结果：

| 采样结构 | 同时发布 | 紧急任务晚到 | 紧急任务先发 |
|---|---|---|---|
| N2-1 | 全部按时 | 至少一任务超期 | 全部按时 |
| N4-1 | 全部按时 | 至少一任务超期 | 全部按时 |
| N5-1 | 全部按时 | 全部按时 | 全部按时 |

宽松容量、同时发布下，等齐对即时策略的首动作额外等待为 38、404、896 ms；首个即时动作分别为 1616、1442、1508 ms，等齐分别为 1654、1846、2404 ms。三批任务不同，不能据此估计 Agent 数量与真实 API 开销的普遍函数。

**错开发布和期限变化是固定提案的反事实回放，模型没有重新读取每个变化条件。**因此只能说真实提案能进入该评测并呈现相关调度差异，不能说已验证在线 LLM 对晚到请求的适应或重规划能力。当前三选一需求清楚，11/11 正确也没有显示复杂语言能力缺口。

## 超期机制的事后审查

另选运行前已指定的三个 API 结构，用固定自然任务序号排名，在晚到、紧期限、压力 1.6 下检查等齐策略的实际早期启动。该检查在看完结果后开展，明确列为事后机制诊断，未改锁定输入。

- N2-1 在 900 ms 启动洗碗机，紧急热水请求在 60,000 ms 发布。锁定这个实际启动后，知道全部未来的理想排程也找不到全体按时方案。未启动前有可行方案。
- N4-1 在 1500 ms 启动灶台和烤箱；锁定两项实际启动后，晚到水壶任务的截止在理想排程下也无法全部满足。未启动前有可行方案。
- N5-1 在 1500 ms 启动热水器和洗衣机；锁定后仍有全体按时方案，实际等齐规则也全部按时。

该诊断把失败定位到**已经承诺的不可中断动作与随后请求的期限相冲突**；在这些明确的固定负载假设下，它超过了“最终任务没完成”的笼统解释。它不证明所有在线方法都无法解决：可能的策略还包括事先声明的未来事件、预留容量或动作中断。当前五基线没有这些能力；理想排程也仅用于诊断，没有给在线基线未来答案。

信息边界回归检查还验证：在 N5-1 的代表性晚到条件中，删除尚未发布任务及其元数据，五种策略发布前的动作序列都不变；各策略只等待已发布任务，响应时延按各自发布时间计。九项相关测试通过。

## 对 benchmark 的启发与下一步

本轮补上了此前主要限于同时发布的证据：除了资源压力，还要区分期限宽紧和任务发布顺序。三个因素属于清楚的评测条件，无需将每个因素都扩展成论文核心新命题。现阶段支持继续建设可复现的冲突—时延 benchmark，尚未证明方法原创性、现实事件发生率或普遍强方法缺口。

下一步优先检查“决策时知道什么、能改变什么”对结论的影响：在明确声明信息与执行能力的公平协议下，加入受限的强排程／允许中断对照，识别现有规则损失、未知未来造成的限制和不可中断设定的贡献。先做机制对照，再扩模型、增加重复；无需继续堆排列数量。所有功率、周期、容量、模式效果、发布间隔和期限仍是受控设定。
