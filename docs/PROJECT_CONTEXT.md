# 项目上下文

## 项目目标

项目是一个面向智慧家庭的家庭智能中枢，目标包括自然语言理解、设备管控、场景编排、安防和适老看护。当前用户负责或重点关注 Excel 任务清单中的“多 Agent 协同编排”方向。

## 已知系统设计

从项目方案文档提取出的设计要点如下：

- OpenClaw 负责理解、规划和编排；Home Assistant 负责确定性设备执行和状态管理。
- P38：主调度 Agent 识别意图、选择专业 Agent 与 Skill，并形成执行计划。
- P42/P56：云边路由考虑实时性、隐私、算力、网络时延和成本，采用本地优先、云端增强、失败回退、断网可用。
- P58：实时控制、异常告警和原始敏感数据固定本地；复杂分析、报告和深度推理按需上云。
- P69：专业 Agent 有独立职责、工具白名单、记忆视图和风险边界；主调度 Agent 主要负责任务分解与路由。
- P70：优先级为人身安全 > 财产安全 > 舒适度 > 能效 > 娱乐。
- P75/P76：Skill 有接口契约、前置条件、后置条件和可验证执行；支持部分成功、超时、设备离线时的补偿与幂等。
- P104：断网时保留本地设备控制、告警和核心自动化，网络恢复后补传非实时任务。

## Excel 多 Agent 任务

任务 3 的目标包括：

- 建模任务依赖、优先级、资源竞争和互斥关系；
- 建立冲突自动检测与协商机制；
- 使用 ILP/CSP 等数学规划进行多任务混合调度；
- 完成不少于 5 个家庭 Agent 或场景模板；
- 目标是多 Agent 编排成功率达到 95% 以上。

这些目标是项目要求，不是已经完成的科研结果。

## 方案目标与实测结果的区别

PPT 中出现了场景预编排与缓存、简单指令免 LLM 快速路径、本地毫秒级响应、PPO 路由策略模型等内容。当前资料没有证明这些目标已经在真实硬件上达到，因此后续实验必须分别记录：

1. 事件检测或语音结束时间；
2. 首次正确且有用的物理动作时间；
3. 完整任务完成时间；
4. P95/P99 延迟和失败类型。

对于紧急事件，已经预授权且明确的安全动作应走本地确定性控制路径，不能依赖一次无上界的 LLM 调用。陌生或含糊的自然语言请求不能笼统承诺全部在一秒内完成。

## 角色边界

当前材料支持“主调度 Agent＋专业 Agent／Skill＋确定性执行器”的分层架构，但不能据此声称“只有主 Agent 思考，其他 Agent 完全不思考”。论文中应明确区分：LLM 规划器、轻量状态/冲突检测器、专业策略模块、设备执行器和安全运行时。

## 研究与工程边界

论文问题应集中在任务 3 的依赖、冲突和协同执行。云边算力、模型量化和硬件推理优化属于相邻问题，可作为条件或基线，不应把两个任务的贡献混成一个无法解释的“大系统”。
