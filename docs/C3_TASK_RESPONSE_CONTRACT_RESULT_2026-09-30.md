# C3 公平信息与逐任务响应复评结果

已完成 396 次既有模型提案回放：七种同信息策略各 54 次，完美预告诊断 18 次。新增 API 调用为零；396/396 次配对的旧首动作时间、任务服务、截止及最终目标结果完全不变。完成 7,296 个信息快照构建校验，39 项相关测试通过。

本步最有用的结果是：**全场景首动作快，不代表每项任务响应快；全部最终完成，也不代表按时完成。**因此 benchmark 应同时报告逐任务等待、完成、迟延与缺失。

下面均为紧期限、紧急任务晚发布、高压力条件。时间从对应任务自身发布计起，是受控非抢占周期模型下的虚拟调度时间。

四 Agent 案例中，两种策略首动作时间相同，但紧急任务的截止结果不同。预告还延后其他任务；这个对照说明信息和等待分配影响服务质量，不证明免费消除所有等待。五 Agent 的 N5-1 对照两种策略逐任务等待及按时结果相同，是保留的负对照。

## 本次完善了什么

1. 正确动作启动等待、实际完成耗时均从本任务发布计时；完成迟延对照绝对期限。没有动作／完成记为 null 并单独计数，不能把缺失服务记为零时延。实际完成必须有匹配启动提案的完成事件。
2. 接受但尚未启动的预约新增 action_reserved 日志，信息快照区分预约与运行，拒绝／完成时移除。日志不改变调度。
3. 公开信息视图区分已发布任务、提案是否返回、公开成本、预约，以及显式未来预告。投影视图不含隐藏正确动作、评分目标或未来任务清单。
4. 既有删除未来任务对照检查已发布可行性策略在未来任务出现前的动作前缀独立性。快照构建校验不等于控制器读取沙箱，也不构成所有策略无信息泄漏的全面证明。

## 对论文的含义和下一步

本步增强了评测的可信度，支持研究“什么条件下协调值得、等待由谁承担”。它没有新增独立模型证据，也没有证明所有协调一定增加时延，更没有形成新算法贡献。

接下来优先测量强规则实际计算时间并明确如何计入时间线，然后对预先选定的少量代表条件重新调用模型，检验固定提案回放发现是否稳定。应保留同时发布、晚到、低压力和无需额外预告的负对照，不扩大为必须找到规则无解的任务。

限制：服务周期、功率、容量及期限仍为受控设定；分钟级等待不是现实设备实测。1 秒启动阈值只是示例指标，不是物理服务承诺。协调求解的实际计算时间尚未加入虚拟延迟。三个保存的模型批次不足以估计 P95／P99。正确动作匹配只覆盖当前 required_action 声明的设备／操作字段。
