# HomeCoord-Bench：主张—任务—指标—基线核对表

日期：2026-09-30  
状态：作者侧实验设计审计；不是正式数据冻结、独立审核或论文结果。

## 1. 先固定研究问题

第一版 benchmark 要回答：**多个 Agent 在同一家庭状态中异步提出动作时，不同协调方式怎样改变冲突、过程安全、必要任务服务与响应时间；这种取舍何时出现、何时消失？**

不预设复杂协调优于强确定性规则，也不以“发现一个规则无法解决的冲突”作为数据入选条件。C1–C4 是四种机制，不是必须与 2／3／5 Agent 全因子相乘的独立样本。Agent 数量仅在新增真实角色、目标或信息边界时作为规模变量。该 benchmark 与以后可能提出的协调算法分开评价。

三项拟检验的 benchmark 主张：

| 编号 | 可证伪主张 | 需要的证据 | 不能用什么冒充 |
|---|---|---|---|
| B1 冲突有条件地改变结果 | 同一任务的冲突、临界、无冲突配对；同提案回放；过程指标 | 只展示冲突臂，或由 `conflict_rules` 标签直接生成结论 |
| B2 安全、服务和时间不能互相替代 | 所有策略共用启动前安全门控；分报过程违规、每项必要服务、首个安全动作和全部服务完成时间 | 仅报最终家庭目标或一个加权总分 |
| B3 协调价值随条件变化 | 强规则基线、不同提案顺序／任务发布时间／资源压力；真实模型提案与固定提案结果分报 | 给协调器人为加等待后声称测得真实开销，或把确定性重复当独立任务 |

目前 B1、B2 有机制原型证据；B3 在 C3 的受控模板上较清楚，但尚缺独立任务、正式审核和留出验证。三项均**未到论文级验证**。

## 3. 公平基线与两条实验通道

所有策略共用**同一启动前安全门控**、设备能力、状态时间线、任务预算和评分器。公开给某策略的设备容量、权限与任务元数据，必须记录在输入契约里；知道未来任务的理想排程只用于判定题目是否可行，不作为在线算法基线。

| 基线 | 作用 | 必须防止的误读 |
|---|---|---|
| 独立异步执行＋共同安全门控 | 测无提前协调的任务丢失、重叠和首次动作时间 | 被门控拒绝不是物理安全违规；不能把它与无门控独立执行混报 |
| 设备锁 | C1 的强简单基线，C3 的机制消融 | 设备锁不检查共享容量，不是完整 C3 强基线 |
| 安全门控后重试／先到先预约 | 排除“一次拒绝就丢任务”制造的协调收益 | 必须统计按时服务，而不只统计最终服务 |
| 已知容量＋前提条件的确定性约束调度 | C1/C3 的强规则基线 | 规则可读取的信息必须与声明的在线信息契约一致；不得偷偷读取未来任务 |
| 等齐**当前已发布**提案再调度 | 测等待换取排序信息的收益与首动作代价 | 它不知道未发布任务；不能叫作永远知道全部任务的 oracle |
| C4 的直接传感器互锁 | 安全关键路径的强本地对照 | 不能用慢 LLM 占用报告替代即时安全互锁 |
| 单主 Agent＋执行器 | 架构对照，后续真实闭环评测 | 中央可见信息与专业 Agent 不同，需单列而非伪称同信息控制 |

**通道 A：固定提案反事实回放。**每个配对和策略使用同一批已保存动作、返回时间，隔离协调决策；报告每批输入的来源和复用次数。它不估计模型随新状态重新思考后的整体性能。

**通道 B：真实模型闭环。**在任务与工具协议定稿后采样，记录请求、响应、格式失败、实际调用时延和因状态变化产生的新提案；不得把顺序 API 调用回放称为实测并发。两条通道分别报告，不合成一个“真实系统成功率”。

## 4. 最小评分表与解释边界

主指标：过程违规次数和持续时间；每个必要动作的服务状态与完成时间；全部必要服务完成率；首次**安全**设备动作启动时间；全部必要服务完成时间。另列最终环境目标达成与时间，防止外部事件自动满足目标而误计 Agent 服务。C3 的原生期限另报按时服务；其他类型如无可信期限，则用事先声明的响应预算画服务—时间曲线，不事后把预算写入任务。C2 的温度、CO₂ 与能耗，C4 的停止暴露和恢复，仅在各自有效的子集报告。

时延拆为模型生成、等待提案、协调计算、命令接受、设备生效和目标进展；合成值、SimuHome 虚拟 tick 与实测 API 墙钟分开。少量模板、相同输入的确定性重复不计算 P99，也不能估计家庭中冲突发生率。

## 5. 下一轮执行门槛

1. 对上述 C1、两个 C3、C4、C2 候选填逐字段的**配对差异表**：初态、任务目标、可见信息、动作能力、事件、容量、预计结果。标出非实验变量变化、答案泄漏、无解任务和外部事件自动完成目标；发现问题先修任务，再跑模型。
2. 先跑通 C1 与 C3 的共同安全门控和强基线，分别报告简单规则已经足够的条件、等待有收益的条件和等待只增加时延的条件。C4、C2按上述条件单列推进，不因未成熟而从研究范围删除。
3. 保留开发任务与新的独立任务结构之间的边界。作者机器审计后可继续探索，但没有外部审核意见时，所有结果标为 `candidate` 或 `controlled_mechanism`，不宣称冻结金标准。
4. 只有在这些任务上出现可重复、非显然的策略排序或过程级失败，才扩大任务集并做正式模型采样；若强规则始终最好，论文应诚实报告这一发现，不为方法创新人为制造弱基线。
