# HomeCoord-Bench 异步提案顺序敏感性离线试验

日期：2026-09-26  
阶段：保存提案的延迟置换反事实；不是新增模型采样或真实并发测量。

## 试验设计

取 EV 充电／热水器 v2 数据中 5 组固定 DeepSeek 动作提案和各自实测逻辑调用时延。在不改模型动作、任务、截止时间或物理参数的前提下，比较两种时延条件：

- `recorded`：保持各 Agent 原本记录的调用时延；
- `reversed`：只交换 EV Agent 和热水 Agent 的两项调用时延。

在低功率冲突与高功率对照下，分别重放 IndependentMultiAgent、RuleCoordinator、ConstraintCoordinator 和 DeadlineAwareCoordinator。总计 `5 × 2 × 2 × 4 = 80` 次运行，`network_calls=0`。`reversed` 是控制异步返回顺序的反事实条件，不代表任何 Agent 重新实测后会得到该时延。

## 主要结果

| 容量条件 | 提案时延 | Independent | ConstraintCoordinator | DeadlineAware |
|---|---|---|---|---|
| 低容量冲突 | 原记录 | 5/5 超容量；EV 截止 5/5 | 5/5 安全；及时有效 4/5 | 5/5 安全且按时 |
| 低容量冲突 | 交换时延 | 5/5 超容量；EV 截止 5/5 | 5/5 安全；及时有效 3/5 | 5/5 安全且按时 |
| 高容量对照 | 两种时延 | 全策略 5/5 安全且按时 | 全策略 5/5 安全且按时 | 全策略 5/5 安全且按时 |

在原记录条件中，Constraint 的设备启动次序是 EV 先 4/5、热水先 1/5；交换调用时延后，EV 先降为 3/5、热水先增为 2/5。它在“谁先返回就先安排”的规则下保持安全，却让热水先行的样本更可能错过 EV 期限。Independent 不等待冲突动作结束，因此 5/5 都赶上期限，但每次都违反容量约束。

DeadlineAware 在两种时延次序中均先执行 EV，冲突环境均 5/5 安全且按时。它的首次设备启动时延中位数比 Constraint 多约 228 ms（原记录）或 214 ms（交换条件）；高容量对照也承担相同的提案收集等待。这里的时间是按保存时延排布的虚拟时间，不是重新调用模型测得的响应时间。

## 结论边界

这个小型配对试验给出了一个清楚的机制证据：当协调器按提案返回顺序贪心排程时，异步时延排序会改变任务顺序，并可能改变期限是否满足；最早截止时间基线能消除这批任务里的变化，但要等待当前已发布的提案都返回。高容量对照帮助识别这段等待属于策略成本，而不是资源冲突所必需。

这不是“现有方法无法解决”的证据。相反，当前现象可由一个普通截止时间规则处理。它也不是模型端到端实验：两个延迟条件都重用同一组提案，模型调用没有真正并发发出；物理时间、容量仍未设备校准，样本只有 5 组。下一轮若要验证 benchmark 的广泛价值，应扩展到不同任务类型、多个同时截止时间、信息可见性和中途状态变化，再观察普通 EDF／优先级规则在哪些条件下足够、在哪些条件下产生新的服务延迟。
