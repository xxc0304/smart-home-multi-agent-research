# C4：真实提案的状态变化阶段与停止／重试契约

日期：2026-09-28。状态：**真实 DeepSeek 初始提案＋合成机器人生命周期实验**；不是设备性能、正式 benchmark 结果或新协调算法。

## 为什么重新做

旧 C4 用 300/400/600 ms 人工提案延迟探测“启动前过期”和“运行中前提失效”，但没有真实模型响应时延，也没有取消或恢复语义。这次保存 5 组 DeepSeek `deepseek-flash` 清洁 Agent／占用观察 Agent 提案（10 次成功 API 调用），在四种事件条件与四种既有策略中复用相同提案和逻辑到达时间，所有策略都使用相同的启动前安全门控。清洁动作持续 3000 ms、命令延迟 100 ms，均为未校准合成假设。

模型 5/5 次提议清洁；占用观察 Agent 3/5 次提议观察、2/5 次选择不动作。占用变化由外部事件直接更新共享状态，观察 Agent 的提案**并没有驱动事件或向清洁 Agent 传递新信息**。因此本轮首先是动态执行生命周期测试，不能仅凭有两个 Agent 就声称已经验证了多 Agent 信息协调。

## 固定墙钟事件的首轮结果与发现

预先固定无事件、500 ms 居民进入、3000 ms 进入、6000 ms 进入四臂。500 ms 臂在五组中均早于清洁动作启动，所有策略都通过前提重检拒绝旧提案：零安全暴露，也零清洁服务。3000 ms 臂中，4/5 组在途失效，1/5 组因模型响应较慢，事件已经发生在动作开始前，提案被拒。6000 ms 原定为完成后对照，但其中一组模型响应较慢，清洁到 7118 ms 才结束，因此 6000 ms 实际落在其运行中。

这个偏离不能用条件标签掩盖：**环境事件的绝对时刻相同，不保证面对不同模型时延仍属于同一生命周期阶段**。首轮所有结果保留实际阶段标签，不能把 6000 ms 臂硬算为五个“完成后”样本。

## 阶段对齐的反事实诊断

另用相同已保存的五组模型提案，按每组独立执行最早动作启动时刻定义事件：提前 100 ms（提交前）、启动后 1500 ms（在途）、完成后 1000 ms；居民停留 2000 ms。这个设计隔离生命周期阶段，事件时刻依赖已记录的模型延迟，**用于机制诊断，不代表现实事件时间分布**。每组事件时刻在四种策略间保持一致。

| 条件 | 当前独立执行／设备锁／约束协调的表现 | 等齐已发布提案的期限策略 |
|---|---|---|
| 无事件 | 5/5 清洁完成，零安全暴露 | 同样完成；部分样本多等待。 |
| 提交前进入 | 5/5 旧提案被拒，零安全暴露；0/5 清洁完成 | 同样拒绝，不能自动恢复服务。 |
| 清洁运行中进入 | 5/5 在途前提失效；机器人仍继续，安全状态不满足各 1500 ms；最终清洁目标虽达成，过程均无效 | 5/5 仍在途失效；等待当前提案没有预知未来进入事件。 |
| 完成后进入 | 5/5 完成，零安全暴露 | 同样完成。 |

这区分了两个问题：提交前的**安全拒绝但任务丢失**，与在途变化后的**任务最终完成却经历危险暴露**。只报告最终清洁成功，会把在途风险漏掉；只报告冲突计数，也会漏掉被拒但未服务的任务。

## 明示停止／恢复契约的隔离对照

现有通用事件模拟器没有中止或恢复动作。我另建一个单机器人、可核对的执行契约，假设检测到在途前提失效后 200 ms 停止；若选择重试，则在居民离开、命令再等待 100 ms 后**从零重新执行完整 3000 ms 周期**。对“仅安全门控”的启动、完成和暴露时长，该契约与通用事件模拟器逐条一致。停止与重试两个策略目前只在此隔离契约中实现，**不是**已经集成的多 Agent 协调器。

| 阶段 | 仅启动前门控 | 运行中停止但不重试 | 停止并在离开后重试 |
|---|---|---|---|
| 无事件／完成后进入 | 清洁完成，暴露 0 | 相同 | 相同 |
| 提交前进入 | 安全拒绝，清洁未完成 | 相同 | 5/5 最终完成，暴露 0；比无事件多约 2000 ms。 |
| 在途进入 | 5/5 最终完成，但每次危险暴露 1500 ms | 暴露降至 200 ms，0/5 完成清洁 | 暴露 200 ms，5/5 最终完成；比继续运行晚 3600 ms。 |

**200 ms 的暴露仍不满足零暴露安全目标。**这只是展示“反应式停止减少暴露、重试恢复服务却推迟完成”的计算结果，不能说已验证真实机器人能在 200 ms 停下，或说已提出新算法。完整历史、阶段对齐和恢复契约的 80／80／60 条运行分开保存，不混成同一类独立样本。

## 对命题的含义与下一步

C4 在执行层面给出比“动作过期”更清楚的 benchmark 轴：状态变化发生在**提交前、在途、完成后**，对应的合理指标不同；协调收益应同时看安全暴露、任务服务和恢复完成时间。当前机器人与居民事件均未校准；第二 Agent 没有实际传递占用信息，故尚未形成有力的**多 Agent 协调**证据。下一条关键任务应改成第二 Agent 的异步预约／状态报告先于居民进入，使其输出能真正影响清洁 Agent 的停止或让路，并比较本地安全门控、事件驱动停止与恢复。需先写清谁能观测事件、何时收到消息、机器人停止回执和恢复进度，再采样模型提案。若没有可核验停止时间，继续标为合成执行语义子集。
