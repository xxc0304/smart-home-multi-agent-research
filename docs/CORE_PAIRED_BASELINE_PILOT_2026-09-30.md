# C1／C3 核心配对与强基线：首轮复核

日期：2026-09-30  
状态：**作者侧受控机制试验**；任务未独立审核、数据未冻结、没有新模型 API 或真实设备调用。机器结果见 [`core_paired_baselines_20260930.json`](../homecoord_bench/results/core_paired_baselines_20260930.json)，复跑脚本见 [`probe_core_paired_baselines_20260930.py`](../homecoord_bench/probe_core_paired_baselines_20260930.py)。

## 本轮到底比较什么

选两组双 Agent 配对和一组三 Agent 容量梯度：C1 空调命令重叠／不重叠，C3 EV—热水器低／高容量，C3 厨房三 Agent 的 `ρ=0.8/1.2/1.6`。脚本先逐字段验证：C1 只改变第二任务发布时间；两组 C3 只改变容量及其同步规则／元数据。未把 C2、C4 或不同证据等级的结果混入主表。

五种共同安全门控策略为独立异步、设备锁、安全门控后重试、确定性约束调度、等齐当前提案后按期限调度。厨房组另加容量感知期限规则。所有策略共享**相同的启动前安全门控**、提案和时延；没有人为增加协调计算耗时。每个配置另外运行一次**无门控独立执行**，仅用来诊断原始冲突，不把它视为可部署方案。

C1 和 EV—热水器使用固定 300 ms 脚本提案；厨房组复用此前 3 批实际并发 DeepSeek 提案及其返回时间。共 87 个离线回放单元，其中 74 个有共同安全门控，13 个是无门控诊断。厨房的 3 批是**同一个任务模板的三批模型采样**，压力档之间也复用这些提案；87 不是独立任务数。各组设备周期、容量和 C1 的舒适期结束时刻仍为受控假设。C1 仅分析命令、服务与时序，**不把旧 episode 中 6 秒达到 24°C 的最终环境目标计为物理成功**。

## 主要结果

| 条件 | 无门控独立执行 | 共同门控下无提前协调 | 强基线的关键差异 |
|---|---|---|---|
| C1 命令重叠 | 1 次 C1；不重叠对照为 0 | 危险关机被拒，必要任务只服务 1/2；首动作 400 ms | 设备锁、约束调度、门控后重试都服务 2/2；设备锁与约束调度首动作同为 400 ms。等齐提案首动作 600 ms，没有增加服务收益 |
| C1 命令不重叠 | 0 次 C1 | 2/2 服务、无门控拒绝 | 各规则同样服务 2/2，首动作 400 ms；复杂规则无新增收益 |
| C3 EV—热水器低容量 | 1 次 C3；高容量对照为 0 | 第二任务被门控拒绝，只服务 1/2 | 设备锁也只服务 1/2；门控后重试和约束调度服务 2/2，首次动作仍为 400 ms，但全部服务完成约 9.4–9.5 秒，高容量并行对照约 6.4 秒 |
| C3 EV—热水器高容量 | 0 次 C3 | 2/2 服务，首动作 400 ms | 重试与约束调度不额外等待；等齐提案首动作晚 100 ms，且无服务收益 |

厨房三 Agent 使用三批**已保存的真实模型提案**；下表的分母 3 是模型批次，不是独立家庭或任务。`ρ` 为研究者设置的总负载／容量比，不是实测住宅容量。

| 厨房条件 | 无提前协调＋门控 | 门控后重试／确定性约束调度 | 等齐当前提案 | 容量感知期限规则 |
|---|---|---|---|---|
| `ρ=0.8` | 3/3 批全部按时；首动作中位 1063 ms | 3/3；首动作 1063 ms | 3/3；首动作 1807 ms | 3/3；首动作 1063 ms |
| `ρ=1.2` | 0/3 批服务全部任务 | 均 3/3 最终服务，但仅 1/3 全部按时；首动作约 1063 ms | 3/3 全部按时；首动作 1807 ms | 1/3 全部按时；首动作中位 1072 ms |
| `ρ=1.6` | 0/3 批服务全部任务 | 均 3/3 最终服务，但 0/3 全部按时；首动作约 1063 ms | 3/3 全部按时；首动作 1807 ms | 3/3 全部按时；首动作中位 1118 ms |

所有有门控的运行在已声明的规则下都没有执行 C1／C3 冲突动作。因此“冲突数都是 0”不能说明策略一样好；差别出现在**被拒后是否重试、任务是否按时、首次动作是否等待**。无门控诊断则只在冲突条件触发 C1 或 C3，在各无冲突对照为 0，说明条件切换确实改变了机制。全部服务完成时间、逐任务状态和门控拒绝理由保存在 JSON；不能只看最终家庭目标。

## 对 benchmark 命题的判断

这轮提供了**比“有冲突，协调器能消除”更有用的机制证据**：

1. C1 是负控制。普通设备锁已经足够；复杂协调没有值得宣称的新收益。它适合检验评测器是否公平，而不是方法创新场景。
2. C3 体现两个不同取舍：门控后重试可以恢复**最终服务**，但可能赶不上期限；等齐提案有时改善按时率，却在容量宽松时延迟首次动作。这个区别在三 Agent 厨房任务及真实模型返回顺序上仍可观察。
3. 尚不能说“已经发现新算法缺口”。厨房只有一个基础任务结构、3 批模型提案，功率上界与设备周期未校准；已有容量感知规则在 `ρ=1.6` 已同时取得 3/3 按时和较短首次响应。方法研究必须先在更多独立任务与同信息强规则下复核。

## 接下来的门槛

**先修任务，再扩实验。**C1 要明确“节能关机”何时是必要任务，并把房间温度目标从本机制评分中正式隔离；SimuHome 只承担命令和设备状态交叉核对。EV—热水器与厨房任务须确认可控设备、周期／容量语义及可行调度；若无现实来源，仍可保留为明确标注的抽象资源压力任务。随后增加至少一种与现有厨房设备和期限结构不同、未用于基线调试的 C3 基础任务，重新采样模型提案；在固定提案回放之外，再用真实闭环检验策略改变后续状态和模型选择的影响。独立审核暂缺时保留审核状态为空，不把探索结果写成正式 benchmark 主表。

这轮没有测规则计算墙钟、SimuHome 虚拟 tick 与真实设备生效时延，也不能从 3 批提案估计 P95/P99 或现实家庭冲突发生率。
