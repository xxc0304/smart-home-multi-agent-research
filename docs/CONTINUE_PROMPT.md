## 研究问题

当前首篇论文暂定为 HomeCoord-Bench，核心问题是：多个专业 Agent 异步作用于动态共享家庭环境时，协调机制减少动作冲突需要付出多少响应时延和任务效用？方法方向仍在研究中；选择性修复、模型路由和预测执行均是候选，不要写成已确定的算法贡献。

## 当前可复现状态（2026-09-27）

HomeCoord-Bench 离散事件原型把任务发布、异步提案返回、环境事件、动作启动和完成反馈置于一条虚拟时间线上。离线主套件通过 107 项测试，执行 674 次本地仿真／回放，未调用模型 API。它验证协调时间线和评测逻辑，不代表真实网络并发或真实家庭物理性能。

固定版本 SimuHome 的 HVAC 适配试点共 21 条轨迹，21/21 通过结构审计，7/7 个重复组一致；没有模型 API 或真实设备。HomeCoord 固定提案与 SimuHome 的两批回放各有 12 条轨迹，结构审计均 12/12 有效，只有 1/4 个重复组逐状态完全一致。HomeCoord 的即时温度目标效果与 SimuHome 的渐进温度变化语义不同；两边成功率不可合并，SimuHome 也尚未接入 HomeCoord 的异步多 Agent 调度。

C4 边界试验对 HC-M16–M20 做了 180 次合成时序运行，60/60 个重复组一致。它区分动作开始前过期拒绝、在途前置条件失效和在途安全状态转坏；300 ms 条件下普通三种策略各有 15/15 次在途失效，DeadlineAware 为 3/15。400／600 ms 条件下各策略均拒绝 15/15 个启动时已过期的主动作，但必要任务服务会下降。外部目标审计还发现 34 条 episode 中 HC-M17–M20 的最终目标可在没有 Agent 动作时由外部事件满足，因此必须分开报告环境目标成功和 Agent 任务服务。

依据首轮任务复核，已为 HC-M01、HC-M11、HC-M16 生成 9 条隔离的配对／时序修订草稿。冲突臂与安全控制在本地确定性试跑中可区分，但动作持续时间、功率和时序仍是合成值；HC-M16 草稿没有实现动作取消或补偿。这些草稿不在正式候选数据目录，也未通过领域双审。

9 条草稿已完成五策略 × 三重复的基线矩阵（135 次 DryRun），45/45 配置重复一致。C1 冲突臂中 Constraint 将能源动作完成推迟 5.8 秒，安全配对无额外等待；C3 低容量臂消除冲突增加 0.9 秒，高容量对照无串行等待；C4 在途臂 Constraint 有 2.9 秒合成安全违规，DeadlineAware 避免违规但未服务清洁任务。报告和原始结果分别位于 docs/REPRESENTATIVE_REVISION_BASELINE_MATRIX_2026-09-27.md 与 homecoord_bench/results/representative_revision_baseline_matrix_20260927.json。它们是机制检查，不是现实设备或算法证据。

事件模拟器已明确同一虚拟时刻的排序阶段，并新增环境更新、动作完成、新任务读取状态的顺序回归测试。在途前提失效检测现覆盖其他 Agent 动作的开始／完成效果，并区分首次触发来源。C1 制冷／关机隔离探针共 60 次 DryRun：冲突臂 Independent 在两个效果阶段各有 1 次跨 Agent 失效，Constraint 与安全配对均为 0；这只验证指标，简单规则已解决该例。见 docs/AGENT_CAUSED_INFLIGHT_PROBE_2026-09-27.md。剩余边界见 docs/EVENT_SIMULATOR_SEMANTICS_AUDIT_2026-09-27.md，尤其是同步 API 决策回放和未编码物理依赖。
