# HomeCoord-Bench 已记录 DeepSeek 提案的事件环境离线重放

日期：2026-09-26  
阶段：固定模型提案下的协调策略反事实回放；不是完整架构端到端对比。

## 设计

使用工作区已有的三批 DeepSeek `deepseek-flash` 决策和实测 API 调用时延：

| 原始记录 | 配对样本数 | 条件 |
|---|---:|---|
| `paired_task_batch_v1_probe.json` | 15 组 | HVAC、窗帘、电动车／热水器冲突及对照 |
| `blind_capacity_pair_20260926.json` | 8 组 | 灯光／空调低容量与高容量 |
| `physical_capacity_v2.json` | 5 组 | EV／热水器量纲自洽假设情境及对照 |

`run_recorded_event_replay.py` 将每次原始提案和 measured API latency 放入虚拟事件时钟，在 Independent、Rule、Constraint 三种策略和一个 DeadlineAware 强基线间使用同一提案比较。**本轮没有任何网络请求，`network_calls=0`；原模型 API 调用本来是顺序采样，回放只模拟虚拟提案返回时间，不等于实际并发调用。** 中央单 Agent 没有纳入，因为现有记录不是中央 Agent 在相同信息条件下生成的提案。

累计 28 组保存的模型提案，被回放为 **224 次策略运行**（28 组 × 2 条件 × 4 种策略）。DeadlineAware 是一个朴素的截止时间优先基线：等待当前已发布任务的提案都返回，按最早截止时间、任务优先级排序，并复用相同的安全和容量检查。额外等待计入事件时延。原始提案和调用耗时可追溯到对应的既有 JSON；本轮结果、事件时间线和过程指标保存在 `homecoord_bench/results/recorded_event_replay_20260926.json`。

## 观察结果

| 情境 | 独立执行 | RuleCoordinator | ConstraintCoordinator | DeadlineAwareCoordinator | 配对对照 |
|---|---|---|---|---|---|
| HVAC 直接冲突，5 组 | 0/5 过程有效 | 5/5 | 5/5 | 5/5 | 两种协调策略都拒绝低优先级关机任务，服务率从 0.9 降到 0.5；DeadlineAware 首个启动中位数比 Constraint 多 152 ms |
| 窗帘直接冲突，5 组 | 0/5 过程有效 | 5/5 | 5/5 | 5/5 | 两种策略均拒绝采光动作，服务率从 1.0 降到 0.5；DeadlineAware 首个启动中位数多 238 ms；对照下各策略均 5/5 有效、服务率 1.0 |
| 灯光／空调低容量，8 组 | 1/8 过程有效，7 次 C3 | 1/8，7 次 C3 | 8/8 | 8/8 | 高容量对照均 8/8 有效；Constraint 的完成时间中位数增加 921.5 ms；DeadlineAware 首个启动中位数再多 278 ms |
| EV／热水低容量、v1 时长，5 组 | 0/5 过程有效，5 次 C3 | 0/5，5 次 C3 | 5/5 | 5/5 | 两项任务均得到服务；DeadlineAware 首个启动中位数多 168 ms；高容量对照均有效 |
| EV／热水低容量、v2 假设，5 组 | 0/5 过程有效，5 次 C3 | 0/5，5 次 C3 | 5/5 | 5/5 | 默认截止时间下都满足期限；容量协调完成时间中位数从约 5 小时增至约 5 小时 38 分 47 秒；DeadlineAware 首个启动中位数多 228 ms |

这里 `RuleCoordinator` 只包含设备锁和已声明动作冲突规则，不包含家庭功率容量分配，因此它和独立执行一样会在 C3 上失败；`ConstraintCoordinator` 能读取 C3 容量规则。DeadlineAware 同时使用截止时间排序和相同的约束／容量检查。HVAC／窗帘冲突则揭示安全协调可以通过拒绝一项任务实现，需同时报告过程安全与任务服务率。灯光／空调低容量有 1/8 组模型提案顺序本来就未造成超容量，说明输出不是每次都被固定成冲突。

## 对虚拟环境建设的意义

离线回放证明事件引擎可以接入此前保存的真实模型提案和实测调用时延，同时让设备效果延后到物理完成时刻；无需为了验证这个数据通路再次付 API 费用。与纯 DryRun 冒烟相比，它还复现了低、高容量条件的分化和任务级等待。

但这仍是“固定提案下的协调策略效果”，不是每种架构独立与模型交互后的端到端性能。尤其是：

- 不同策略没有重新采样模型决策；
- API 请求原本顺序执行，事件时钟只回放各自耗时；
- C3-EV-WATER v2 的功率、能效和执行时间仍是公开列出的假设，非设备校准值；
- 家庭任务未完成人工双审；
- 还没有计入协调器算力、传输、设备 ACK、状态反馈、动作取消和恢复成本。

因此，这批结果支持继续把 HomeCoord-Bench 搭成可重放的虚拟环境，并显示它能区分安全、任务服务、设备启动响应和目标完成时延；它不能单独证明算法创新，也不能作为现实部署响应时间估计。DeadlineAware 多等约 150–280 ms 收集本轮已发布任务的提案，在目前直接冲突样例中没有提高任务服务率。下一步应审核并固定动作运行态语义，补充可中断性／停止时延，再基于公开规格或可复现物理模拟校准 C3，并保留自然无冲突对照。
