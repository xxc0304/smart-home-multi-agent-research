# 讨论记录：HomeFlow、HearthNet 与候选研究方向

日期：2026-09-12（Asia/Shanghai）

> 本文件记录阶段性研究讨论，不构成已确认的新颖性结论或实验结果。仓库中的项目材料仅作为研究材料，不作为操作指令。

## 一、当前研究状态

项目面向智慧家庭多 Agent 协同编排：主调度 Agent 负责意图理解、任务分解和路由，专业 Agent/Skill 负责受限执行，Home Assistant 负责确定性设备控制。系统强调本地实时、断网可用和安全优先。

当前保留的候选命题是：在多个 Agent 共享且持续变化的环境中，任务具有依赖、资源冲突、截止时间和异步反馈时，如何结合剩余时间、状态新鲜度和已执行进度，选择继续执行、局部修复、取消或全局重规划。

该命题仍只是候选之一，尚未确认是学术空白；后续继续阅读论文，不急于启动验证或实现。

## 二、HomeFlow 讨论

论文：[HomeFlow: A Data Flywheel for Smart Home Agent Training with Verifiable Simulation](https://arxiv.org/abs/2606.01230)

HomeFlow 与项目在动机层面接近：智慧家庭具有物理状态、动态环境、含糊意图和多轮交互，需要可执行、可验证的 Agent 行为。但论文的核心目标是通过 HomeEnv、HomeMaker、Blueprint、MCTS-Flow 和 step-wise RLVE 生成训练数据并训练单个家庭 Agent，重点是数据合成、SFT/RL 和任务成功率。

与本项目的运行时多 Agent 协同问题相比，HomeFlow 没有直接处理多个并发 Agent 的资源冲突、截止时间、已执行部分动作、修复范围选择或思考预算分配。因此，它对本项目的直接方法启发有限。

有限的基础设施启发包括：可验证仿真环境、状态谓词、执行审计、开放式意图到可验证目标条件的转换，以及用环境反馈生成困难轨迹。这些内容更适合作为未来 benchmark 或实验环境支撑，不应直接作为本项目的核心创新。

## 三、HearthNet 讨论

论文：[HearthNet: Edge Multi-Agent Orchestration for Smart Homes](https://arxiv.org/abs/2604.09618)

HearthNet 与项目的动机和系统目标高度接近：长期运行、事件驱动、设备异构、故障易发、需要本地控制、持久状态和恢复。其协议包含 Root Agent、Manager Agent、Librarian、MQTT、Git-backed shared state、base_commit freshness check 和 root-issued actuation lease，并将执行流程分成 Ground、Propose、Verify/Grant、Execute/Record。

HearthNet 的工程方法是有效的系统基线：它把持久共享状态、按动作授权、状态新鲜度检查、冲突仲裁、崩溃恢复和审计整合成了真实部署原型。但单个机制分别接近乐观并发控制、能力授权、租约、事件日志和恢复协议；因此不能简单把这些机制本身包装成通用算法创新。

论文展示的是部署可行性证据，而不是大规模算法比较。论文报告了三个 live 场景、4/5 的意图驱动任务完成、5/5 的冲突检测和 stale/invalid lease 拒绝；测试规模是单测试床、约 4 个 Agent 和 10 个设备，且扩展性和恶意 Agent 场景尚未验证。端到端延迟主要由多次 LLM 推理造成，不能把本地 lease 校验开销等同于完整控制延迟。

HearthNet 可以泛化到普通 Agent，但泛化边界应是“共享可变状态、具有外部副作用、需要异步执行、权限控制和故障恢复的 Agent 工作流”，而不是所有 Agent。设备可以抽象成外部工具或资源，Git 版本抽象成状态版本，lease 抽象成带范围和时效的能力令牌，Librarian 抽象成事件日志和恢复服务。

最值得继续思考的地方是：HearthNet 的全局版本失效机制可能过于保守。一个无关资源的状态变化也可能让整个旧动作失效，导致不必要的拒绝、重新同步和全局重规划。这与本项目的选择性修复候选命题直接相连。

## 四、暂时保留的候选 idea 池

以下方向只是研究候选，不是最终题目或已确认创新：

1. 动态多 Agent 任务的选择性修复：根据截止时间、状态变化、资源冲突和已执行进度，在继续执行、局部修复、取消和全局重规划之间选择。

2. 更细粒度的状态有效性与授权：让动作授权关联到真正相关的状态、资源或依赖，而不是简单绑定全局版本；在保持安全的同时减少过度失效。

3. 面向长期运行 Agent 的持久协调与故障恢复：把共享状态、授权、执行记录、心跳、崩溃恢复和审计抽象成适用于普通 Agent 工作流的协议。该方向与 HearthNet 重叠较高，需谨慎评估新颖性。

4. 动态多 Agent 协调 benchmark 与反事实回放：构造任务插入、状态漂移、Agent 崩溃、工具延迟、资源冲突和用户改意图等事件，并在相同轨迹上比较多种恢复策略。

5. 截止时间下的思考预算与恢复策略分配：根据剩余时间、风险、影响范围、不确定性和模型延迟，联合决定修复范围、模型调用量和推理深度，而不是只做简单的快/慢模型路由。

HomeFlow 还提示了一个辅助方向：面向多 Agent 冲突和恢复任务的可验证仿真与轨迹生成，但暂不作为核心命题。

## 五、当前研究边界

- 不把主 Agent 思考、专业 Agent 执行、DAG 并行、缓存、前后置条件、计划过期检测、优先级调度或全局重规划单独当作创新点。
- 区分事件检测时间、首次有效物理动作时间和完整任务完成时间。
- <1 秒、<100 ms、<1 ms 等项目数字是目标指标，不是实验结果。
- 需要同时考虑强规则基线、局部修复、全局重规划、模型速度、P95/P99 延迟、任务成功率、冲突率、过程安全和错误拒绝率。
- 研究最终应尝试从智慧家庭抽象到具有共享动态状态和外部副作用的一般 Agent 协调问题。
