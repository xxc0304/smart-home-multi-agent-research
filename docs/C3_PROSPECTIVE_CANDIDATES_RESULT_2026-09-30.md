# C3 前瞻候选批次结果：协调价值是否随容量变化

日期：2026-09-30。定位：作者生成的受控候选与真实模型提案试验，**不是正式冻结 benchmark、独立家庭样本或真实设备实验**。运行前设计见 [`C3_PROSPECTIVE_CANDIDATES_PREREG_2026-09-30.md`](C3_PROSPECTIVE_CANDIDATES_PREREG_2026-09-30.md)。12 份输入及哈希见 [`manifest.json`](../homecoord_bench/revision_drafts/20260930_c3_prospective_candidates/manifest.json)。

## 完成情况

四组三 Agent 任务全部保留。对每组的三档容量，理想排程检查均判为可行；专业 Agent 请求的信息边界检查也全部通过。运行了计划中的 **288 个离线配对单元**，即四组任务 × 三档容量 × 六种提案返回顺序 × 四策略。六种顺序只是同一任务上的干预；实际结构只有四组，且来自共用设备池。

在**离线有效提案**条件下，下表为每档容量所有任务按时的返回顺序数／24 个模板—顺序配对单元。数字不可解释为 24 户家庭的成功率。

| 负载／容量比 | 独立执行＋共同安全门控 | 约束协调 | 等齐当前提案后期限调度 | 容量感知期限调度 |
|---:|---:|---:|---:|---:|
| 0.8 | 24/24 | 24/24 | 24/24 | 24/24 |
| 1.2 | 0/24 | 16/24 | 24/24 | 16/24 |
| 1.6 | 0/24 | 7/24 | 24/24 | 24/24 |

在 `ρ=0.8`，四策略都服务全部任务且全部按时；等齐策略的首个安全动作中位数为 **1300 ms**，其余三策略为 **900 ms**。这是预定的负控制：宽松资源下等待带来 400 ms 开销，却没有在这批任务中改善成功。`ρ=1.2/1.6` 下独立执行受共同安全门控拦截，全部任务服务数均为 0/24；这表示安全门控阻止了超容量启动，同时丢失服务，不表示系统实际执行了危险操作。约束协调在 `ρ=1.2/1.6` 都最终服务全部任务，但按时结果对返回顺序敏感。等齐与容量感知规则在最紧档均 24/24 按时，说明这批候选**没有证明强规则无法解决问题**。

## 预先指定的真实模型提案

只对事先选定的 P1、P2 各做两批三 Agent 并发 DeepSeek 调用，共 **12 次成功模型请求**，记录 **12,774 输入 token、1,780 输出 token**。四批均返回三个动作提案，没有协议失败；配对重放至三档容量、四策略，共 **48 个回放单元**。最初在本地沙箱尝试的 12 次请求因网络权限错误未送达 API，失败日志保留；随后在获准的网络环境下执行相同的预定批次，没有按结果重选模板。

| 模板、容量 | 独立执行 | 约束协调 | 等齐期限调度 | 容量感知期限调度 |
|---|---:|---:|---:|---:|
| P1，0.8 | 2/2 | 2/2 | 2/2 | 2/2 |
| P1，1.2 | 0/2 | 2/2 | 2/2 | 2/2 |
| P1，1.6 | 0/2 | 0/2 | 2/2 | 2/2 |
| P2，0.8 | 2/2 | 2/2 | 2/2 | 2/2 |
| P2，1.2 | 0/2 | 2/2 | 2/2 | 2/2 |
| P2，1.6 | 0/2 | 1/2 | 2/2 | 2/2 |

表内为“全部任务按时”的**批次数**。P1 两批的并发返回顺序相同；P2 两批不同。在 `ρ=1.2`，模型实际返回顺序恰好让约束协调 4/4 按时，而脚本穷举只有 8/12；不能只取模型四批便称约束协调普遍等价于等齐策略。宽松档中，P1 等齐策略的首动作中位数为 **1498.5 ms**，即时策略为 **1388.5 ms**；P2 对应为 **1947.5 ms** 和 **1199 ms**。真实 API 返回时延的差异使等待代价依批次而变，不能用固定 400 ms 代替。

## 能支持与不能支持的判断

本批给出一条较完整的**机制证据链**：题目可行、输入边界检查通过、负控制无协调收益、紧张资源下安全门控与任务服务存在取舍，且协调规则对同一组异步提案有不同的按时结果。真实模型提案复现了“宽松时等待有代价、紧张时调度选择影响服务”的方向。

同时，四模板都由研究者设定，每个专业 Agent 只有一个可用动作，目标与工具对应直接。因此 **12/12 有效提案不构成复杂自然语言理解能力的证据**；离线 288 次也不能增加独立任务结构数量。模型只见本地任务，而中心规则读取声明的容量和负载上界，比较的是规定信息契约下的系统策略，不是所有方法获得完全相同信息的纯算法胜负。所有功率、周期和截止时间都是受控设定，尚无设备物理校准或第三方任务审核。当前证据支持继续建设“冲突—时延 benchmark”，但不足以宣称新算法缺口或顶会级泛化结论。

## 下一步的实验设计决策

接下来优先扩充**结构差异**，而不是继续排列同一模板的返回顺序：增加有多个合理动作的专业 Agent 请求、不同截止宽紧及发布时刻、两 Agent 与四／五 Agent、无冲突负控制，并在采样前固定生成规则和留出集。对每个候选都先做理想可行性、信息边界、强规则和共同门控审计，再采样模型；失败任务也进入结果。这样才能检验本批所见取舍是否越过“一动作、三 Agent、单容量资源”的狭窄构造。
