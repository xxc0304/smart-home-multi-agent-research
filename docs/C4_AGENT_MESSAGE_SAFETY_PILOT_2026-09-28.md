# C4：占用报告 Agent 的真实消息时延与安全停机

日期：2026-09-28。定位：**5 组探索性模型采样＋合成机器人时序回放**，不代表真实设备性能、正式 benchmark 统计或新算法验证。

## 实验要回答什么

上轮 C4 虽调用了两个 Agent，但占用观察 Agent 的输出未影响清洁执行。本轮让第二个 Agent 在居民进入／离开时根据可见的实际占用与上次发布状态，提出 `report_occupied`／`report_clear` 消息。消息经过实测 DeepSeek 响应时间与假设的 100 ms 传输时间到达协调端。清洁任务的启动使用上一轮保存的同一组 DeepSeek 提案和响应时延；各策略共享同一提案、事件时刻与机器人契约。

每组有冲突（清洁开始后 1500 ms 居民进入、停留 2000 ms）和无事件对照。清洁周期假定 3000 ms；停止回执假定 200 ms；重试命令 100 ms，并从零重新清洁。比较不协调、Agent 消息停机、Agent 消息停机并恢复，以及直接传感器停机并恢复。模型看见的是**事件发生时**的局部占用，未看见未来进入；离开时已发布状态只由此前实际送达的进入消息决定。模型调用为串行采样，其实测耗时作为逻辑异步消息延迟回放，不是真正并发 API／设备实验。

## 结果

15 次新 DeepSeek `deepseek-flash` 调用：5 次进入报告均正确，5 次离开报告均正确；无事件对照只有 2 次选择 `noop`，2 次 `defer` 且未发动作，1 次多余地发布了 `report_clear`。进入报告模型耗时分别为 1483、1397、1223、1164、1260 ms，中位数 1260 ms；加传输和停机回执后，在事件发生后约 1464–1783 ms 才能完成停机。机器人原本在事件后 1500 ms 完成。

| 冲突条件策略 | 5 组中实际在清洁完成前停机 | 危险重叠时长 | 清洁服务 |
|---|---:|---|---|
| 无协调 | 0/5 | 每组 1500 ms | 5/5 完成，但过程不安全 |
| Agent 消息停机 | 1/5 | 4 组 1500 ms；1 组 1464 ms | 停机的 1 组未完成 |
| Agent 消息停机＋离开后重试 | 1/5 | 同上 | 5/5 最终完成；停机组比继续运行晚 5077 ms |
| 直接传感器停机＋离开后重试 | 5/5 | 每组 200 ms（假设值） | 5/5 最终完成，较无协调晚 3600 ms |

这里的直接传感器基线不是实测硬件。其 200 ms 暴露仍非零风险；若任务要求零暴露，停机回执也不够，必须在设备端设置更严格的安全互锁或预先避免启动。无事件时所有策略均完成清洁；那次多余 `report_clear` 在当前状态下没有改变执行，但揭示模型消息准确率不能假定为 100%。

## 机制解释与研究判断

因为事件发生时清洁只剩 1500 ms，消息传输和停止共需 300 ms，报告模型必须在 **1200 ms 内**返回才可能改变这次执行；5 组中只有一次达到。若要把事件后的暴露控制在 1000 ms 内，模型调用还需不超过 700 ms，本次均未达到。事件发生后才让 LLM 报告再决定**紧急安全停机**，与简单传感器互锁相比没有优势，不能把这一方案包装成协调算法贡献。

本结果也不否定 C4 或整体 benchmark。它把问题分层：设备端快速安全互锁处理紧急停机；Agent 协调可研究**进入前的预约／预警如何改变任务安排**，以及停机后何时、由谁、用什么信息恢复服务。下一轮应把“提前通知的可用时间”作为配对变量，加入同等可见信息的确定性预约规则，判断 Agent 是否提供超出规则的收益。若没有收益，C4 的价值仍可作为揭示自然语言 Agent 不宜处于实时安全关键路径的评测证据，而非硬造一个新方法缺口。

## 边界与复现

所有机器人时长、消息传输与居民停留均是人工设定；没有真实占用传感器、机器人中断回执或家庭事件频率分布。事件时刻按每组清洁启动时间对齐，只用于机制诊断，不能估计现实中冲突概率。五组重复采样同一任务模板，也不是五种独立家庭场景。由于清洁 Agent 与占用报告 Agent 的调用耗时来自分别采样的 API 请求，本实验是可审计的**逻辑异步回放**，不能声称测量了真实并发通信。本文只比较已列策略，不证明一般多 Agent 协调无效。
