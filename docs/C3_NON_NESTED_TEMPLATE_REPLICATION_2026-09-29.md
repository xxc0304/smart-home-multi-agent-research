# C3非嵌套任务结构复现

日期：2026-09-29。状态：受控合成机制实验；不属于冻结benchmark数据；无模型API调用。

后续物理解释复核：7项功率规格均是额定／连接功率，作为全周期保守预约上界；不能由此推断恒定实际功率。敏感性实验与审核门槛见 `docs/C3_RATED_POWER_REVIEW_GATE_2026-09-29.md`。

## 为什么做

此前2、3、5 Agent结果来自同一任务池的嵌套扩展，只能说明规模变化，不能说明结论跨任务结构成立。本轮新增两个设备集合和期限结构不同的模板，检验“资源宽松时立即执行、资源紧张时等待协调更有价值”能否复现。

## 两个模板

1. **厨房回路**：烧水、烤制正餐和洗碗三个Agent，分别具有短、中、长期限；
2. **早晨出发**：吹头发、洗浴热水、洗衣和EV充电四个Agent，其中两项是紧迫的人服务任务，两项可延后。

两个模板的设备集合互不重合。每个模板分别设置资源压力ρ=0.8、1.0、1.2、1.6，并穷举全部提案返回顺序：厨房6种、早晨出发24种。四种基线合计480次回放。

动作提案由确定性脚本按episode中的必要动作生成，返回间隔固定为200 ms。该设计只测试异步调度和协调，不测试LLM理解。

资源宽松时，始终等齐没有成功率收益，却把厨房模板的首动作中位数从900 ms增加到1300 ms，把早晨模板增加到1500 ms。

资源紧张时，始终等齐期限排序在全部顺序中成功，证明条件可行。容量感知期限规则仍受提案顺序影响。例如早晨出发ρ=1.6时，如果热水和洗衣先占用容量，10分钟的吹头发任务可能到约70分钟才完成；这是明显的排序失误，不是毫秒级截止边界。

## 参数来源复核

本轮另建立逐任务参数来源矩阵，并与可执行模板做机器核对。7个任务的功率值均已匹配到具体公开产品规格：小米电水壶1.8 kW、博世烤箱3.0 kW、博世洗碗机2.4 kW、戴森吹风机1.6 kW、阿里斯顿热水器3.0 kW、博世洗衣机2.0 kW和Bolt.Earth充电设备3.3 kW。阿里斯顿热水器60分钟升温时间也与模板一致。

规格复核前的探索稿曾使用2.0 kW水壶、1.2 kW洗碗机和35分钟热水周期；现已分别改为1.8 kW、2.4 kW和60分钟，热水期限设为75分钟并重新运行全部480次，表中策略计数没有变化。除热水器外的设备周期仍属于E4受控工作量，不能称为实测周期分布。

## 当前结论

两个新结构都复现了核心取舍：

- 低压力下等待全部提案浪费响应时间；
- 高压力下立即接受当前可行动作会使结果依赖提案顺序；
- 局部容量感知规则无法在所有组合上同时保持低时延和按时完成；
- 全局等待可以稳定完成，但等待成本随Agent数和最慢提案增加。

这增强了HomeCoord-Bench研究“何时协调最值得”的依据。不过两个模板仍由研究者构造，不能据此声称现实家庭中的冲突发生率，也不能替代设备参数来源、模型提案和人工审核。

## 下一步

1. 为其余设备周期补充匹配程序，或继续明确标为E4受控工作量；
2. 将ρ解释为受控管理预算，继续避免冒充典型家庭总容量；
3. 选择能够区分策略的关键条件，调用或重放真实LLM提案；
4. 加入无冲突、边界、冲突配对并进行双人盲审；
5. 只有通过审核的基础模板才进入第一批冻结数据。
