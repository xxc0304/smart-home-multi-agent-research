# HomeCoord-Bench 下一阶段的研究取舍

日期：2026-09-27。此页用于防止实验工具的扩充偏离原命题；不是新论文结论。

## 当前得到的、尚未得到的

已有离散事件实验台、固定提案与时延回放、C1/C3/C4 的代表性冲突／安全对照及强规则基线；C2 另有真实模型提案回放和独立连续换气／制热仿真，但两者使用不同环境语义。它们支持“多 Agent 异步协调会影响过程安全、任务服务、完成时间和环境成本”这一研究动机，但许多原型被简单规则解决，尚不能证明新算法必要。SimuHome 固定版本的 HVAC 试点证明了后端状态／时钟能接入；它还没有给 HomeCoord 提供通用多 Agent 物理环境。

HC-M06 的连续换气／制热探针进一步发现合成的完成时间—用电取舍，参数估计错误会让简单预测规则超时或多耗电。新建的轨迹入口能审计来源、采样、配对和过程指标；目前导入的 8 条样例全部是同一人工环境生成的契约测试。**这些结果不能升级为“现实中简单规则失效”或“已有新算法空间”**。现有 SimuHome 制冷轨迹缺少 HC-M06 的关键观测，单凭增加合成格点不会提高证据等级。

## 研究优先级

1. **主线先做覆盖 C1–C4 的可信 benchmark。** 对 C1 同设备冲突、C2 共同环境状态影响、C3 容量、C4 状态过期任务均给出机制清楚的代表场景和匹配控制；核查提案权限、状态可见性、动作生命周期、物理可行性和计分口径。C2 在完成参数／方程审核前作为明确标记的合成环境子集，不与事件运行时格点合并。请独立领域审核者复核，记录分歧，而非自评替代双审。
2. **物理接地只推进可验证的一小族。** C1 HVAC 可沿既有 SimuHome 适配扩展，但必须分开设备终态与热目标；HC-M06 保持探索分支，直到取得窗户、CO₂、温度和功率的联合轨迹。SimuHome 原生加湿／除湿可作为另一候选，却不能直接沿用语义有缺陷的 HC-M08。
3. **固定强基线后再判断方法空间。** 在同一批冻结任务上比较独立执行、设备锁、状态再验证、约束协调、期限优先、简单预测与有限信息反馈，并记录首个物理动作、目标进展、完成、能源及查询开销。若在线强规则仍基本饱和，就把论文贡献放在 benchmark 揭示的普遍 Agent 局限；若有跨任务、跨工况稳定的剩余缺口，再围绕这一缺口设计协调方法。
4. **模型调用后置于数据冻结。** 先固定任务、工具协议、观察边界、评测器与成本预算，再以相同模型和调用预算测试中央单 Agent 与专业多 Agent。既有确定性回放只隔离协调变量，不能替代真实模型提案质量与调用时延结果。

短期成功标准是：C1–C4 每类机制都有明确的操作定义、代表任务、匹配控制和独立复核结论；强基线不会因数据标签／目标泄漏而被冤枉；论文能清楚说明每类结论来自真实后端、外部模拟器还是合成事件台。某类暂时没有可信物理参数时，明确留在合成子集或降级为探索性任务，不为追求覆盖率而虚构现实性。这个里程碑比继续制造一个“规则必败”样例更能支撑 benchmark 可信度。

## 2026-09-27 审计进度

9 条代表性事件草稿已做字段级配对审计；此前把“未配置硬截止时间”记为失败，是把评测范围误当成缺陷；现在明确 C1／C3／C4 这批草稿评测冲突与经过时间，不主张硬截止调度。C2 的截止时间网格仍是单独标注的合成压力实验，不混入事件矩阵。C1 只改变能源请求释放时刻；C3 只改变容量阈值；C4 提交前与在途臂统一为 300 ms 提案延迟，只改变事件时刻。草稿现在有 `strict-v1` 可执行工具契约，越权目标、参数越界和遗漏安全前置条件会在设备动作前被拒绝。五种策略、135 次固定提案回放已重跑；将 C2 明确列为独立审核场景、修正截止时间范围后，代表性设计审计 104/104 项通过，测试套件 125 项通过。该结果是作者侧结构与实现检查，不是独立领域审核。C2 连续环境场景稿已纳入代表性审核包，并重新运行其两个既有仿真：18 个冲突／18 个安全对照中，3 个慢换气／240 秒期限配置由乐观下界证明不可行；其余 15 个冲突配置里，StateGate 节能但按时率低于 Independent。另导出冲突／匹配对照下五策略的 10 条 C2 轨迹，内部状态趋势、时钟和能耗积分核对全部通过。108 格模型误差冲突格点出现 13 个相对完美模型参考的可避免超时，对照 0 个。C2 方程和参数仍未校准，不能视为现实证据。详细审计见 `docs/C2_SHORT_TERM_INTEGRATION_AUDIT_2026-09-27.md`、机器审计 JSON、C2 轨迹包与独立审核包。

冻结前仍需解决：由领域审核者判断 C2 是否是有效的间接环境冲突，并评审其动力学；找出 C1／C3 参数来源及 C4 动作中断语义的来源，或将这些任务限制为合成诊断；若论文要主张硬截止调度，另设计有可行性下界的配对，不随意给现有任务填数字；在独立双审后，再以真实模型检查工具调用与提案质量。两名领域审核者仍未填写，现有草稿继续保持 `proposed_revision_not_scored`。

“何时值得协调”的实验定义及 C1/C3 第一轮合成激活成本探针见 `docs/WHEN_COORDINATION_WORTH_IT_EXPERIMENT_V0.1.md`。它把提案返回后的协调耗时独立于模型提案耗时，但冲突占比仅为配对轨迹的假设加权。正式实验必须给所有策略相同的最低安全门控，并比较强确定性规则；当前探针不说明需要新算法。

## 2026-09-28：优先完成跨模板真实提案统一回放

已将 C1-HVAC、C1-BLINDS 和物理工作量版本 C3-EV-WATER 的历史 DeepSeek 提案放入同一个事件运行器，并给五种策略相同的安全门控，得到 150 条探索性策略结果，新增 API 调用为 0。C1 两种冲突主要由安全约束拒绝不兼容服务，未显示复杂协调器的额外收益。C3 低容量下容量协调保住双任务服务，但一次按提案就绪先后排序导致 EV 假设期限未达；期限排序修复这一例，却会在高容量无冲突时徒增等待。公开功率上界的容量感知规则已在该模板的 5 组样本全部按时，因此不能据此宣称新算法缺口。完整数据、条件和后续跨机制任务决策见 `docs/CROSS_TASK_RECORDED_PROPOSAL_REPLAY_2026-09-28.md`。接下来优先核定 C2 的连续状态与物理参数并取得真实提案；C4 先补齐取消/恢复契约。独立审核是冻结任务前的质量关口，不替代机制验证。

## 2026-09-28：C2 真实提案与连续环境接合

已在冻结的高／低 CO₂ 配对任务上调用 DeepSeek 15 次，得到五组空气质量和制热 Agent 的初始提案；其中高 CO₂ 开窗、低 CO₂ 不动作、低温制热均为 5/5。提案与调用耗时接入独立连续房间模型，两个固定换气假设下立即制热均按时，等关窗再制热均超时但总用电较低；对照无差异。改变合成升温速率后，出现两策略都超时、只有立即制热按时、以及两者均按时但等关窗更省电三种局面。该敏感性支持“协调收益依赖共同环境动力学和期限”的**合成机制问题**，同时表明不能用一组人工参数断言现实效果。准确参数下简单规则即可选择；物理参数与设备行为尚无联合轨迹校准。详见 `docs/C2_RECORDED_MODEL_PHYSICS_PILOT_2026-09-28.md`。下一证据门槛是外部模拟器或设备的窗／CO₂／温度／功率联合轨迹，而非继续增加同一方程的参数格点。

## 2026-09-28：C3 三任务结构扩展

新增做饭、烘衣、洗碗三个共享容量任务（与 EV／热水器结构不同），在 3.5/5.8 kW 配对条件下，用 15 次 DeepSeek 初始动作提案和逻辑返回时延回放五种策略。低容量时，共同门控下独立执行无法完整服务；先到先排可恢复三任务服务，但仅 1/5 组全部按时；等候期限排序与容量感知期限规则均为 5/5 全部按时。高容量时各策略全部按时，始终等候的首动作额外等待配对中位 312 ms，容量感知规则避免这一等待。三任务干跑还发现并修复了强基线漏看“已返回但待分派的早期限任务”的实现漏洞；不能把该漏洞当论文方法缺口。结果支持 C3 内不同任务结构的条件取舍，却仍基于未校准固定负载和人工期限；设备功率轨迹与共享电源来源成为下一数据任务。详见 `docs/C3_THREE_LOAD_REAL_PROPOSAL_PILOT_2026-09-28.md`。

## 2026-09-28：C4 模型时延、状态阶段与恢复契约

取得五组 DeepSeek 清洁／占用观察提案，重放无事件、提交前、在途和完成后条件。固定墙钟事件发现一条模型慢响应会让原本标作“完成后”的事件实际落到运行中，因此另作随每组提案启动时刻对齐的反事实机制诊断。提交前安全门控 5/5 拒绝过期动作但丢失清洁服务；在途变化 5/5 造成 1500 ms 危险暴露而旧运行器仍完成清洁。独立停止／重试契约假设 200 ms 停止：仅停机减少暴露但不完成任务；停机后从零重做可恢复服务，却比继续运行晚 3600 ms，且仍有 200 ms 暴露。这是合成执行契约，不是可部署算法或实际机器人性能。占用观察 Agent 的输出尚未传给清洁 Agent，第二 Agent 并未真正参与协调；下一道 C4 任务应让其异步预约／报告成为可见状态，并明确停止回执与恢复进度。详见 `docs/C4_REAL_PROPOSAL_LIFECYCLE_AND_REPAIR_2026-09-28.md`。

### 补充：占用消息真正参与执行后的边界

另采样 5 组进入、离开、无事件占用报告 Agent（15 次 DeepSeek 调用），用实际模型耗时决定消息抵达时刻，并将其用于机器人停机／重试。进入和离开报告动作均为 5/5 正确，但事件发生时清洁只剩 1500 ms，模型响应＋假设的 100 ms 传输＋200 ms 停机回执使 5 组中仅 1 组赶得及停机，危险暴露只从 1500 缩至 1464 ms；直接传感器停机基线在同一假设下 5/5 达到 200 ms。研究判断是：**紧急安全停机不应依赖 LLM 报告链**；下一步把 C4 的多 Agent 问题放在进入前预约／预警和停机后恢复，并用同信息确定性规则作强基线。这仍是合成执行时序，既不能代表实机，也不证明必须提出新算法。详见 `docs/C4_AGENT_MESSAGE_SAFETY_PILOT_2026-09-28.md`。

## 2026-09-27：C3 协调价值边界补充

在同一 EV／热水器合成任务模板中，将功率上界误差、共享容量（6.0/7.0/7.2 kW）和三种期限紧迫度纳入控制参数扫描。结果显示，低容量和紧迫期限下，等待尚未返回的高优先任务提案可改善按时完成；期限宽松时，容量先到先排已达到同等服务，额外等待增加首动作延迟；容量允许并行时，容量感知规则可直接放行，而始终等待没有增加按时率。公开上界低报会丧失等待排序的期限收益。

这些结果精细化了“何时协调值得”的**实验问题**，不是对真实家庭频率的估计，也不是算法创新证据：基础任务、设备参数和期限都未校准；历史模型调用仅形成逻辑提案到达时间；规则计算耗时未实测；模拟策略可查询实际负载与持续时间；参数扫描不是独立任务样本。下一道独立里程碑仍是双人任务审核；通过后扩展到结构不同的任务模板，分段测量规则／模型／网络／设备耗时，再评估强规则是否在跨模板条件下留下稳定缺口。

详细结果见 `docs/C3_EV_WATER_INFORMATION_BOUNDARY_2026-09-27.md`、`docs/C3_EV_WATER_DEADLINE_BOUNDARY_2026-09-27.md`；期限扫描输出 `homecoord_bench/results/ev_water_deadline_boundary_20260927.json`（315 单元）。

另测了本机模拟器处理耗时：每种配置 300 次预热、2,000 次计时，完整两任务事件模拟中位数约 1 ms；历史 DeepSeek 提案时延中位数约 1.5 s。该量级对比提示模型调用可能主导等待，但本机模拟器计时不等同生产协调器，生产网络及设备延迟仍未测。细节见 `docs/LOCAL_EVENT_RUNTIME_TIMING_2026-09-27.md` 和 `homecoord_bench/results/local_rule_runtime_benchmark_20260927.json`。
