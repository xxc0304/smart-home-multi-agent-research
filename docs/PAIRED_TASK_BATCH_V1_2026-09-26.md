# HomeCoord-Bench 多任务配对探索：首批结果

2026-09-26。**这批试验已在三种新任务上重复观察到条件性的冲突与协调代价，但尚不能证明正式 benchmark 的普遍性或新算法的必要性。**

## 设计与证据边界

构造四组冲突／无冲突对照、共八条合成 episode：舒适制冷与节能关机（C1-HVAC）、卧室隐私与采光（C1-BLINDS）、照明与空调容量（C3-LIGHT-HVAC）、电动车充电与热水容量（C3-EV-WATER）。前两组切换一个条件状态，并据此导出条件性家庭目标；后两组切换家庭电力容量。每组的本地专业 Agent 输入在两个条件中一致。任务 JSON 已存于 `homecoord_bench/data/pilot_pairs_v1/`。

确定性功能筛查覆盖四组八条 episode，全部通过结构校验与预定冲突／对照关系；它只检查实验实现。真实模型探索使用 DeepSeek `deepseek-flash`，对三组新任务各做五次采样，共 15 组配对、40 次成功模型调用；先前 C3-LIGHT-HVAC 已完成独立的八组盲测，见 `docs/BLIND_CAPACITY_PAIR_PILOT_2026-09-26.md`。本批模型输入 44,066 tokens、输出 4,852 tokens，成功请求耗时中位数约 1,323 ms。最初在沙箱内的六次连接失败没有进入这 15 组结果。

专业 Agent 只看到自己的任务、可观察状态和两种公开设备动作，看不到 `required_action`、`action_template` 或其他 Agent 的未来提案。模型输出与实测调用耗时在独立执行和在线强规则架构间回放。C1 的条件 Agent 分别采样，而本地 Agent 提案在冲突／对照间复用；C3-EV-WATER 则在容量两条件间复用同一组提案。因此本实验估计的是**给定相同提案时改变环境条件和执行策略的结果**，不是各架构重新交互后完整策略的性能。调用在真实墙钟上顺序进行，再按耗时放入逻辑异步时间线。

## 真实模型结果

| 任务对 | 冲突条件：独立执行 | 冲突条件：在线强规则 | 无冲突对照 |
| --- | --- | --- | --- |
| C1-HVAC（5 组） | 5/5 出现 C1；0/5 过程有效；两项任务都曾获服务 4/5，另 1/5 制冷因前提条件失败未执行 | 5/5 过程有效；5/5 拒绝节能关机任务，制冷任务获服务 | 两架构 5/5 过程有效、节能任务获服务；规则无额外目标等待 |
| C1-BLINDS（5 组） | 5/5 出现 C1；0/5 过程有效；两项任务都曾获服务 | 5/5 过程有效；5/5 拒绝采光开帘任务，隐私任务获服务 | 两架构 5/5 过程有效、采光任务获服务；规则无额外目标等待 |
| C3-EV-WATER（5 组） | 5/5 超容量 C3；0/5 过程有效；两个动作都执行 | 5/5 过程有效且两个任务都执行；目标首次满足时间增加 2,311–5,951 ms，中位数 2,940 ms | 两架构 5/5 过程有效、两任务均获服务；规则无额外目标等待 |

先前 C3-LIGHT-HVAC 八组盲测中，低容量 7/8 出现 C3，强规则在这七组增加 510–2,859 ms；一组本来没有冲突，高容量八组也没有冲突，两者规则增量均为零。它提供了一个不同设备组合与天然无冲突的例子，但和本批数据来自同一套未校准的合成执行器，不能当作独立真实场景验证。

## 目前能说明什么

1. **冲突不是评分器凭空造出来的。**相同本地提案在条件切换后，冲突条件触发 C1 或 C3，无冲突对照不触发；所有成功调用的动作都能落地到公开目录。先前照明／空调组还有 1/8 次低容量提案天然安全，说明结果并非每次被固定为冲突。
2. **“安全”有不同代价。**C1 两组是不可同时满足的目标竞争，强规则通过放弃低优先任务消除冲突，不能宣称同时完成两项任务。C3 组是资源容量竞争，强规则保留两项任务，但通过串行等待换取安全；这两类取舍需要分别评估。
3. **尚未看到超越简单规则的缺口。**这些任务的安全处理都可由已有约束与优先级规则完成。C1 的损失是任务服务，不是本批观测到的时延增长；C3 的增长主要是合成设备占用时间，并未测量协调计算、网络同步或设备反馈开销。现有证据支持继续做更严谨的 benchmark，不能直接支持“必须提出复杂新协调算法”的结论。

## 下一轮设计应先补的证据

首要工作是人工双审这些任务的目标、优先级、动作效果和对照公平性，并用设备规格或可复现仿真校准功率与执行时长。随后补上有明确截止时间、动作执行中状态变化和真实反馈延迟的配对场景，与规则、单管理 Agent 和其他协调基线比较。重点观察是否存在**同样保证安全，却在任务完成率或端到端时延上产生可重复差异**的情境；若没有，应诚实将论文定位为评测框架和规律分析，而非方法论文。

本批模型轨迹与回放指标在 `homecoord_bench/results/paired_task_batch_v1_probe.json`，调用事件在 `homecoord_bench/runs/paired_task_batch_v1_probe/model_events.jsonl`。设计筛查在 `homecoord_bench/results/paired_task_batch_v1_audit.json`。`goal_first_satisfied_ms` 是模拟状态首次满足时间；执行器在动作开始时写入效果，**不是物理设备完成任务的时间**。全部四组仅做单人设计审查，未经设备校准与人工双审，不能据此估计真实家庭冲突率、部署响应时间或论文中稿概率。
