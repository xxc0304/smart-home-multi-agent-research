# C3 强基线与信息差：结果及研究结论修正

日期：2026-09-30。运行前方案见 [`C3_INFORMATION_BASELINES_PREREG_2026-09-30.md`](C3_INFORMATION_BASELINES_PREREG_2026-09-30.md)。继续使用前批 108 个锁定条件、六个设备集合和同一批模型提案。完成 12,264 个新增离线单元、126 个真实提案反事实回放、9 个事后逐任务时延检查；**没有新增模型调用或 API 费用**。

## 关键结果

**同时发布时，强可行性规则可以明显削弱此前的等待取舍。**只使用已发布任务与公开服务成本的精确可行性检查，在六个结构的紧期限、压力 1.6 条件中都全部按时；4/5 Agent 的首次安全动作均为 900 ms，而前批等齐规则分别为 1500/1700 ms。这些固定成本场景中，不必等齐所有提案才能成功。因此不能继续把“协调必然使响应变慢”当作普遍结论。该规则是已有精确可行性准入加现有派发，不是本项目的新算法，也不等于全局最优调度器。

**紧急请求晚到时，未来信息仍改变结果。**只见已发布任务的可行性规则在五个结构中失去全体按时机会，N5-1 仍成功。明确额外公开未来请求身份、周期、负载、期限和发布时间的预留规则，在这批晚到条件中全部按时。这个预告来自受控未来事件，具有信息优势；不能与普通在线规则按“相同信息方法胜负”解释，也不能充作现实预测模型。

**严格维持可行性会放弃已经超期的服务。**严格版在部分晚到条件中无法恢复全体按时，因此停止接纳剩余任务；新增的服务回退版本在已发布任务已经不可全部按时时通过相同安全门控继续提供服务。回退版在全部条件最终服务了全部任务，超期仍如实报告。历史版本默认不启用回退，本轮通过隔离输入开关运行。

## 全量基线结果

两已发布信息版本各覆盖所有 5,256 个响应排名与条件配对；完美预告版只覆盖单个紧急任务晚到的 1,752 个单元。低压力或宽松期限条件均全部按时。每行下面的分母来自同一个作者结构的响应排名，不是独立家庭样本。

表格限定紧期限、压力 1.6；“已发布规则”指服务回退版，它与严格版在按时结果上相同，服务结果不同。

| 结构 | 同时发布：已发布规则按时 | 同时发布：已发布规则／等齐首动作 | 紧急晚到：已发布规则按时 | 紧急晚到：完美预告按时 |
|---|---:|---:|---:|---:|
| N2-1 | 2/2 | 平均1000／1100 ms | 0/2 | 2/2 |
| N2-2 | 2/2 | 平均1000／1100 ms | 0/2 | 2/2 |
| N4-1 | 24/24 | 900／1500 ms | 0/24 | 24/24 |
| N4-2 | 24/24 | 900／1500 ms | 0/24 | 24/24 |
| N5-1 | 120/120 | 900／1700 ms | 120/120 | 120/120 |
| N5-2 | 120/120 | 900／1700 ms | 0/120 | 120/120 |

已发布信息规则可以根据声明的周期、容量与期限保护当前任务的排程可行性，即使其他已发布专业 Agent 的提案还未返回。这依赖本批固定、公开、两个模式成本相同的接口合同；不代表现实环境中的动作持续时间、负载或模型选项都已准确可知。搜索允许用理想的当前任务可行性作检查，实际异步提案仍按记录返回，因此本规则不是全局最优性的保证。

## 同一组实际模型提案的回放

从前批 N2-1、N4-1、N5-1 的 11 次模型调用重放，无新增采样。三个集合的同时发布、最紧条件中，可行性规则全部按时，首动作分别为 1616、1442、1508 ms；等齐分别为 1654、1846、2404 ms。

晚到、紧期限、最紧条件中，服务回退版在 N2-1/N4-1 超期但最终服务全部任务，N5-1 全部按时。完美预告版三组全部按时。N2-1 的完美预告把首动作从 1654 ms 推至 61,616 ms；N4-1/N5-1 的首动作仍为 1442/1508 ms，说明预留未来容量并不必然推迟所有设备的首次动作。

### 逐任务时延诊断：首动作指标可能掩盖等待转移

另做 9 个事后逐任务检查，固定前批三组模型提案、晚到、紧期限、压力 1.6。每项时延按**本任务发布时刻**计算，未服务记为空，不能当成零延迟。

- N2-1：普通服务回退下，热水器请求发布后等约 89 分钟才启动；完美预告下仅等 1.616 秒。相应代价是洗碗机从发布后 1.654 秒启动，变为约 46 分钟后启动。
- N4-1：水壶从发布后约 44 分钟才启动，变为发布后 1.846 秒启动；灶台则从 1.443 秒启动推迟到约 6 分钟。全场景“首个动作”都为 1442 ms，看这一项无法发现等待在任务间转移。
- N5-1：两个版本的任务启动时延相同，完美预告没有在这组任务上改善按时率或时延。

因此后续正式评测应同时报告：全场景首次安全动作、每个任务发布后的启动等待、期限满足和必要服务。不能仅凭全场景首动作快就宣称紧急请求反应快，也不能仅凭未来预告在两个案例成功就声称协调总要等待。

## 实现与信息审查

本批成本从 Agent 可见的工具说明解析，并与公开负载上界检查一致；两服务模式成本相同，隐藏正确操作不用于选择搜索周期。测试在篡改隐藏成本后验证适配后的成本仍来自公开工具。代表性删除未发布任务对照验证两个已发布版的发布前动作不变；完美预告则明确添加额外未来合同。

服务回退只在当前已发布任务已不可全部按时时启用，继续使用容量与前置条件门控，未允许打断、取消或修改已启动动作。相关 11 项新旧回归检查通过。源候选与模型记录哈希未改变。

本机每个模拟单元的墙钟中位数：严格可行性 5.679 ms，服务回退 6.213 ms，完美预告 6.050 ms；数据偏重五 Agent 排列，包含事件处理、搜索与计分。这不是纯调度器性能测试，也没有加入虚拟首动作时延。端到端比较仍需实测并计入调度开销。

## 对论文的影响和下一步

本轮让证据更可信，同时缩小了原有主张：**简单、同时发布、准确已知固定成本的取舍，可以被更强规则明显改善。**此前规则或等齐的不足不能直接当作普遍方法缺口。值得继续评测的是：在什么信息和执行条件下，协调能保持正确服务与期限，又把等待分配给哪些任务。规模、发布与期限仍是同一研究问题的评测条件，无需改成多个新命题。

下一步优先把“公开任务合同／当前已返回提案／未来预告”写成清楚的信息协议，并固定逐任务响应指标；再检查所有比较方法在同一公开合同下的公平性。随后少量测实际调度开销与重复模型提案。无需为了证明规则失败继续堆更多人为冲突；若要加入中断恢复，应先定义可验证的服务进度语义和适用设备，不能直接假设所有周期都可任意中断。
