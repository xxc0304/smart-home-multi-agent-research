# HomeCoord-Bench 数据构造协议 v0.1

日期：2026-09-28  
状态：正式数据冻结前的执行规范。本文规定数据从哪里来、哪些变量可以由研究者控制，以及每类证据可以支持什么结论。

## 1. 基本单位

正式数据的基本单位不是一条孤立指令，而是一个可回放的 `episode`。每个 episode 由五层组成：

1. **家庭配置层**：设备、房间、共享资源和初始状态；
2. **任务层**：用户目标、Agent 角色、可见信息、工具和异步发布时间；
3. **执行层**：动作启动、完成、反馈、外部事件和共享状态版本；
4. **对照层**：只改变一个预先声明的冲突因素，形成冲突、边界和无冲突条件；
5. **来源层**：逐项记录实测轨迹、设备规格、模拟器、模型日志、人工设计或审核意见。

不同住宅的数据不拼成一个虚构家庭。公开轨迹用于初态、状态范围和事件背景；研究者设计的任务和冲突条件单独标注；动作产生的反事实后果由可复现环境计算。

## 2. 来源等级

| 等级 | 来源 | 可支持的内容 | 不能直接支持的内容 |
|---|---|---|---|
| E1 | 实测传感器或设备日志 | 某配置下真实出现的状态、功率、事件和时间范围 | Agent 目标、冲突因果、协调策略收益 |
| E2 | 具体设备规格、协议或控制接口 | 动作能力、额定功率、参数范围和离散状态转换 | 某个家庭中的使用频率和实际响应分布 |
| E3 | 经轨迹或实验校验的模拟器 | 给定动作下的可复现反事实状态变化 | 超出校验范围的部署结论 |
| E4 | 受控研究设定 | Agent 数量、任务到达间隔、容量压力、事件发生阶段 | 现实发生率和真实家庭统计分布 |
| E5 | 实际模型调用日志 | 提案内容、格式错误、推理耗时和调用失败 | 设备自身的物理执行耗时 |
| E6 | 独立人工审核 | 任务自然性、目标和约束一致性、标签分歧 | 物理参数的测量替代品 |

允许混合来源，但每个字段只能继承其实际来源的证据强度。例如，“真实轨迹初态 + 合成任务 + 模拟器后果”仍属于半合成 episode，不能称为完整真实家庭轨迹。

## 3. C1–C4 主张—证据矩阵

| 冲突族 | 论文可检验的核心主张 | 正式最低证据 | 当前已有 | 当前缺口 | 当前可用状态 |
|---|---|---|---|---|---|
| C1 直接设备冲突 | 异步 Agent 会对同一设备提出不兼容命令，协调可减少覆盖或振荡，但增加等待 | 设备命令语义 E2/E3；冲突/对照配对 E4；模型提案 E5 | SimuHome 命令状态交叉检查；配对回放 | 具体设备的命令确认与反馈时间；多 Agent 复杂组合 | **机制实验可用**；不报告室温达标或真实毫秒响应 |
| C2 间接环境冲突 | 不同设备的动作通过共享环境相互抵消，协调价值随环境状态和重叠时间变化 | 实测背景 E1；动作效果模型 E3；成对任务 E4；模型提案 E5 | 两个独立宿舍单元的门窗、温度、CO2、天气和供暖功率实测窗口 | 可校验的通风—供暖反事实模型；更广的留出配置 | **背景已跨单元复核，物理效果未就绪** |
| C3 共享资源冲突 | 单动作可行而并发动作超过共享容量；排序或等待在安全、服务率和完成时间之间产生取舍 | 具体负载能力 E2；明确容量实施点 E2/E3；容量比配对 E4；模型提案 E5 | EV 与热水器功率数量级来源；可执行容量边界试点 | 可核查的家庭/回路容量；匹配设备档位；更多负载组合 | **机制实验可用**；容量压力仍是合成变量 |
| C4 状态过期 | 状态变化发生在提案、提交或执行不同阶段时，旧动作可能失效，重新验证和修复带来时延 | 状态事件或轨迹 E1/E4；动作生命周期 E2/E3；恢复语义 E2/E3；模型提案 E5 | 事件阶段回放；提交前拒绝和运行中前提失效指标 | 停止响应、可中断性、部分进度和恢复成本 | **检测实验可用，恢复效果未就绪** |

正式论文必须分别报告“机制成立”“物理结果可信”“现实发生率”三个层级。当前项目可以验证前两者中的一部分，没有数据支撑冲突在普通家庭中的发生率。

## 4. 第一批正式候选如何设置

先冻结 4 个基础模板，每类一个。每个模板生成配对和边界条件，而不是把每个参数组合当成独立现实家庭。

| 模板 | 固定部分 | 只允许改变的实验变量 | 第一批条件 |
|---|---|---|---|
| C1 HVAC 命令 | 同一设备、任务目标、Agent 权限和提案 | 第二任务到达时刻、Agent 数量 | 不重叠、刚好边界、明显重叠；2/3/5 Agent |
| C2 通风—供暖 | 同一实测背景窗口、目标、设备能力 | 动作重叠时长、室内外温差、模型参数区间 | 无重叠、短重叠、长重叠；物理模型校验前只作探索 |
| C3 EV—热水—第三负载 | 同一负载工作量、截止时间和提案 | 总负载/容量比、Agent 数量、任务到达时差 | 容量比 0.8、1.0、1.2；2/3/5 Agent；松/紧到达间隔 |
| C4 清洁或安防动作 | 同一初态、任务和外部事件内容 | 事件相对动作生命周期的位置、设备可中断性 | 无事件、提案前、提交前、执行中、完成后 |

其中 0.8、1.0、1.2 是受控压力条件，不是现实家庭分布。Agent 数量扩展时必须增加真实角色、目标或权限边界，不能复制同一个 Agent 的名称凑数量。

## 5. 一条候选进入正式集的门槛

每条候选必须同时满足：

1. 单个任务本身可执行，联合任务至少存在一种安全可行的处理方式；
2. 冲突条件和对照条件除预先声明的变量外保持一致；
3. 初态、设备参数、容量、时间和事件各自带来源类型与引用；
4. 外部事件不会替 Agent 自动完成全部任务；
5. 设备开始、完成、反馈和中止语义明确；
6. 至少两名审核者在不看策略结果时独立判断任务自然性与标签；
7. 实际模型提案及耗时原样保存，离线回放不冒充真实并行调用；
8. 数据冻结后才运行主实验，任何影响解释的修订都产生新版本并重跑全部基线。

## 6. 第一阶段规模和结果组织

第一阶段不追求一次生成数百条表面不同的任务。先完成 4 个基础模板，每个模板包含冲突、边界、对照三类条件，并覆盖 2/3/5 Agent，预计形成约 36 个可审查配置。模型随机性可在冻结配置上重复采样，但重复调用不增加基础任务数量。

结果分三张表报告：

- **机制表**：冲突率、硬约束违反、任务服务率、协调拒绝及等待；
- **时延表**：首个动作启动、首次目标进展、任务完成的中位数、P95 和 P99；
- **来源表**：每个模板的 E1–E6 覆盖、缺失项和允许的结论范围。

不同证据等级的数据不合并成一个“总体真实成功率”。半合成任务、模拟器任务和未来实机任务分别报告，并检查结论方向是否一致。

## 7. 紧接着执行的工作

1. 用机器审计矩阵固定 C1–C4 当前证据状态；
2. 为 C2 选择并校验可产生反事实后果的通风—供暖模型；第二个独立宿舍单元已经按相同规则完成背景复核；
3. 为 C3 确定一个明确的容量实施点和匹配负载配置；
4. 为 C4 增加可中断、不可中断和有停止延迟三种设备契约；
5. 修改 4 个正式候选模板并进行盲审，通过后冻结第一批数据。

当前仓库中的 20 条候选仍是题材池。它们不会因为数量足够而自动升级为正式 benchmark 数据。
