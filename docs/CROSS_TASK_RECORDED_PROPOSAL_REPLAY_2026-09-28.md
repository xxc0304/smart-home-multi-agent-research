# “何时协调值得”：跨任务真实提案统一回放

日期：2026-09-28。**结论限于探索性证据**；不作为独立家庭样本或论文主结果。

## 这次实际做了什么

将已保存的 DeepSeek `deepseek-flash` 专业 Agent 动作提案及实测调用耗时，按原任务顺序重放到同一个离散事件模拟器。每种策略接收同一组提案、同一逻辑到达时刻、同一最低安全门控。比较独立执行、设备锁、约束协调、始终等候已释放提案的期限排序，以及具有公开功率上界的容量感知期限排序。**本轮没有调用模型 API，没有接入实体设备。**

覆盖 C1-HVAC、C1-BLINDS、C3-EV-WATER-PHYSICAL 三种模板；每种有冲突/对照两个条件和 5 组历史模型提案，共 30 个配对条件、150 个策略运行。5 组是同一模板上的模型采样，不是 5 套独立住宅。C3 设备功率、工作量和截止时间虽量纲自洽，仍是未实测的假设。

运行器：`homecoord_bench/replay_cross_task_recorded_proposals.py`。原始结果：`homecoord_bench/results/cross_task_recorded_proposal_replay_20260928.json`，含来源文件哈希、各任务服务、截止时间、首动作时刻和拒绝原因。

## 主要发现

| 模板和条件 | 共同安全门控下的观察 | 对“何时协调值得”的含义 |
|---|---|---|
| C1 窗帘冲突 | 5/5 次隐私关闭成功，采光开启 0/5；五种策略的最终目标与过程有效性均为 5/5。独立执行的冲突动作由共同门控或完成态约束拒绝。 | 这里展示了目标优先级与不可同时满足的服务；未展示更复杂协调器的独立收益。 |
| C1 空调冲突 | 5/5 次舒适动作成功，节能关机 0/5；五种策略的最终目标与过程有效性均为 5/5。 | 主要是安全约束下的服务取舍。旧草稿把空调设定动作近乎直接映射到室温目标，物理语义尚需修订。 |
| C1 两个对照 | 目标服务均为 5/5，各策略最终目标一致；期限指标不适用。 | 无冲突时没有协调收益；仅“始终等候”在部分冲突样本增大首动作等待。 |
| C3 EV/热水器，6 kW | 独立执行和设备锁在 5/5 次都因共同安全门控拒绝一项，未完成双任务。约束协调在 5/5 次完成双任务，但仅 4/5 同时按时。两种期限排序在 5/5 次双任务按时。 | 容量调度的服务收益明确；在一组热水提案先就绪的样本中，先后次序又影响 EV 截止时间。此处有非平凡排序取舍。 |
| C3 EV/热水器，7.2 kW | 独立执行、设备锁、约束协调、容量感知期限排序均 5/5 双任务按时；始终等候的期限排序也按时，但在所有 5 次都推迟首动作。 | 容量允许并行时，等待没有服务收益。容量感知的确定性规则已处理这个边界。 |

C3 低容量的第 1 组历史提案中，热水 Agent 比 EV Agent 的提案先就绪。约束协调按就绪先后排，EV 于 20,326,900 ms 完成，超过 19,200,000 ms 的**假设**截止时间；期限排序等到 EV 提案后先排 EV，18,001,524 ms 完成，代价是首动作从 1,344 ms 推迟到 1,524 ms。高容量下不需要这 180 ms 等待；容量感知规则能放行。这是清楚的机制示例，不是显著性结论。

共同门控让所有策略在这些回放中都避免了被测的并行容量/动作冲突。因此这里比较的是**安全基础之上的任务完成与等待代价**，不能说独立执行造成了实体设备危险，也不能把“门控拒绝”误报为某协调策略独有的安全增益。C1 的 `all_deadlines_met=False` 是未配置截止时间时的评测字段，不应当解释为超时；本报告只对 C3 统计按时率。

## 研究判断与紧接着的实验

这次结果支持一个较窄但有价值的 benchmark 问题：**相同的协调动作，在什么任务条件下改善必要服务或期限，什么时候只增加等待？** 它尚不能支持“需要新协调算法”。C3 的容量感知期限规则已在这些条件上达到 5/5 双任务按时；C1 的服务冲突主要由共同门控和目标优先级决定。若现在为这一组结果设计复杂算法，容易只拟合单一模板。

下一条证据应来自**机制不同的任务**，而非继续扫描 EV 容量和期限。优先推进 C2 的通风—制热共同环境任务：先核定状态方程、边界条件、时间常数与能耗积分，并让真实模型在冻结的冲突/对照输入上提出动作，再用同一批动作比较共同安全底线下的服务、完成时间和能耗。C4 需要先明确取消、恢复和在途动作的契约，才适合进入同一主表。两者目前分别使用连续环境探针与未完善的事件语义，**不与上述 150 次运行合并计算“跨四类成立”**。

正式数据集仍需独立任务语义审核、设备参数来源或明确的合成标签、预先冻结的评价规则、更多结构独立的任务及多模型/多次采样。审核是冻结数据质量的后续关口，不应取代现在的机制验证。
