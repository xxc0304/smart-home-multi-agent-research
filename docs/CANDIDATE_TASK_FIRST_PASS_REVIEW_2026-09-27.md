# HomeCoord-Bench 候选任务逐条语义复核（首轮）

日期：2026-09-27  
状态：研究助理首轮桌面复核；不是两名独立领域审核者的双审，不批准任何候选进入金标准数据集。所有 M01–M20 继续保持 `candidate_dry_run`，原 episode JSON 未改动。

## 复核范围

逐项对照每条候选的初始状态、Agent 可见状态、任务目标／前提、外部事件、硬约束、冲突规则和动作效果。需区分两个执行路径：旧版 `run_closed_loop_episode` 通过 `materialize_action` 直接读取 `effects`；当前用于长动作／候选任务的 `run_event_simulation` 会把显式 `start_effects` 与 `completion_effects` 分开，在开始和完成时分别应用。若 grounding 只给一个 `effects` 快照，事件模拟器会在动作完成时一次写入该快照，仍不会模拟连续变化；声明的 `environment_effects` 在这两条路径中都未作为环境动力学执行。此次 C1-HVAC 到 SimuHome 的回放使用旧闭环路径，不是候选任务事件路径。

机器证据就绪审计的总体结果仍有效：20/20 未双审，20/20 动作时间和功率为合成值，20/20 没有任务完成截止字段，20/20 缺少完整可调用动作签名；M06–M10 的环境效应未进入执行器，M17–M20 的目标可由外部事件单独满足。下表把这些总括问题具体落到任务级。

## 对候选集的处理建议

1. 暂时不把 M01–M20 中任何一条称为“已审核任务”。现阶段最适合保留的是**问题结构**，不是当前动作时长、物理结论或论文数据标签。
2. 若要先做小而可解释的下轮试验，优先修订一条直接设备冲突（M03）、一条容量冲突（M11）和一条状态过期任务（M17 或 M18），各自配一条只改变关键条件的无冲突对照。C2（M06–M10）先不进主要证据，直到环境作用进入运行时并有依据。
3. M13 可作为期限压力样例的候选，但只有在完成时间字段、物理负载可行性和强在线规则对照后才运行模型。M12 必须先补洗涤依赖，否则不是可信的洗烘顺序任务。
4. 全部任务还需定义可调用动作的名称、参数、前置条件、预期返回和权限；仅列 `tools` 名称不足以公平测试模型。
5. 下一位审阅者应独立检查上述判断，并可否决或改写。双方没有完成独立审查与分歧记录前，审核人 A/B 列保持未填写，候选状态保持不变。

针对 M16–M20 的首轮机制复核已另做 180 次状态事件／动作开始边界试验，结果见 `docs/C4_TIMING_BOUNDARY_PILOT_2026-09-27.md`。它确认状态变化发生在提交前与动作执行中是两类不同现象；当前 C4 计数两者均为 0，且 M17–M20 的目标可由事件本身满足。该试验补充了本表的诊断，不改变任何候选状态或双审结论。

复核依据还包括 `docs/CAUSAL_EVIDENCE_AUDIT_2026-09-26.md`、`docs/CANDIDATE_TRADEOFF_AUDIT_2026-09-24.md` 和 `homecoord_bench/results/evidence_readiness_audit_20260926.json`。此首轮判断没有新增模型 API 调用、没有修改候选 episode JSON，也没有使用真实设备数据。

## C2 连续环境路径补充（2026-09-27）

HC-M06–M10 的原始 `environment_effects` 仍没有进入统一事件运行时，因此上述候选表的判断继续成立。另建立了独立 HC-M06 开窗换气／制热连续房间探针，显式计算 CO₂ 变化、室温热损失和加热耗电，并加入 CO₂ 已达标的配对控制。该工作让 C2 有了可复核的合成环境路径，但方程与参数未校准，也没有真实模型提案；它在领域审查前只作为 C2 候选场景，不可将原 M06 JSON 的标注直接视为通过审核。

## C4 指标补充

对 M16–M20 的边界回放现已在运行时明确区分：外部状态已变化、动作启动前安全拒绝；动作启动后，外部更新令原本成立的任务前提转为不成立；以及在动作仍在执行时安全约束转为违反。新增计数及其适用边界见 `docs/C4_TIMING_BOUNDARY_PILOT_2026-09-27.md` 和数据规范第 4 节。指标细化没有修补候选任务的目标泄漏、动作可取消性或物理校准缺口，因此 M16–M20 仍只是待修订候选，而非双审金标准。
