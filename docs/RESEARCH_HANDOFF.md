## 已形成的判断

HomeBench 和 SimuHome 的重要性不在于提出了非常复杂的新神经网络，而在于它们用智慧家庭这个具体载体，把一般 Agent 的问题做成了可复现的任务和评测：

- HomeBench：有效／无效指令、单设备／多设备、完整执行和错误识别。
- SimuHome：设备操作依赖、连续环境变化、工作流调度、可行／不可行请求和时间加速。

因此，垂直场景可以支撑顶会论文，但前提是场景约束揭示了更一般的问题，且 benchmark 或方法具有可复用价值。不能把两篇论文的录用原因简单归结为“智慧家庭这个题材新颖”。

## 当前暂定主线

第一篇论文暂定为 **HomeCoord-Bench：异步多 Agent 智慧家庭中的冲突—时延权衡评测**。

核心问题保持简洁：

> 多个专业 Agent 异步作用于动态共享家庭环境时，协调机制减少动作冲突需要付出多少响应时延和任务效用？

首轮只把多 Agent、共享状态、异步返回和动作冲突作为核心变量。选择性计划修复、模型路由、预测执行和快慢模型属于后续方法方向，不直接塞入 benchmark 主命题。

当前已实现 4 条种子 episode、20 条参数化变体、确定性评测器、四种架构闭环和 DeepSeek API 适配。`deepseek-flash` 与 `deepseek-v4-pro` 已在最终原生标量协议下对 C1–C4 的 8 个关键配置各重复 20 次。共享策略提示不能稳定消除冲突；低优先级 Agent 先返回会破坏简单优先级规则；显式协调可消除 C1–C4，但不同冲突的代价不同：C1 主要牺牲低优先级任务服务率，C2/C3 主要增加完整完成时间，C4 可能等待状态恢复。相同提案与时延的反事实回放表明，C2/C3 协调只在冲突样本增加完成时间，安全样本的增量为 0。

## 保留的后续方法命题

原选择性修复表述：

> 在共享动态环境中，多个 Agent 的任务具有依赖、资源竞争、截止时间和异步反馈。推理和通信期间环境继续变化，局部正确的动作可能组成全局冲突。系统应根据剩余时间、状态新鲜度和已完成进度，在继续执行、局部修复、取消和全局重规划之间做选择。

更窄的候选题目：

> Deadline- and state-validity-aware selective repair for asynchronous multi-agent home automation.

中文可称“面向异步家庭自动化的截止时间与状态有效性感知选择性计划修复”。

### 保留命题：预测式协同执行

基于 [Speculative Actions](https://arxiv.org/abs/2510.04371)，新增并保留以下候选方向：

> 在共享状态持续变化、设备动作具有物理风险且任务存在严格截止时间的多 Agent 家庭环境中，如何安全地预测和准备未来动作，并在预测失配后只修复受影响的计划子图，从而降低端到端延迟？

暂定英文题目：**HomeSpec: Risk- and Deadline-Aware Speculative Coordination for Multi-Agent Home Automation**。

这个命题目前是研究池中的正式候选方向，不等于已经确认的首创学术空白。它与“选择性计划修复”共享状态版本、资源冲突和局部修复机制，与“低延迟 Agent 执行”共享预测、预取和快慢路径机制。直接把 Speculative Actions 移植到 Home Assistant 的物理动作上创新性和安全性都不足；需要研究风险分级、状态有效性验证、资源租约、截止时间感知的分支选择，以及预测失配后的局部修复。

建议采用三层架构：本地预授权策略保证紧急事件的首个安全动作，快速 Speculator 并行预取和准备低风险后续步骤，慢速主 Agent 负责权威计划与最终提交。高风险或不可逆物理动作只能提前准备、模拟或预约，不能因为预测置信度高就直接执行。

## 新颖性结论

本轮已将讨论过的论文补齐为 19 篇，新增纳入 HomeFlow、When Do LLM Agents Help? 和 Agentic Fast-Slow Planning。它们分别强化了可验证训练数据、LLM 控制层的适用边界以及快慢规划分层的先例，因此“数据飞轮”“固定快慢分工”或“平稳负载下增加 LLM”都不能单独作为核心创新。

不能把“共享动态环境中的多 Agent 按时、无冲突执行”直接称为全新命题。已有工作已覆盖其中的大部分组成部分：

- SyncPlan：一次联合规划、异步动作链、等待原语、死锁检测和计划过期后重规划；2026 年 8 月 arXiv 预印本。
- VeraRAN：异步动作生命周期、前置认证、事件因果同步修复、版本和截止时间检查；2026 年 8 月 arXiv 预印本。
- Agent JIT：可执行计划、工具前后置条件、延迟分布和串行／并行／hedging 调度；ICML 2026，作者实验室页面和会议页面均有记录。
- LLMCompiler：并行函数调用编排；ICML 2024。
- Win Fast or Lose Slow：动态环境中的延迟—质量权衡；NeurIPS 2025 主会。
- Multi-Agent Path Finding with Deadlines：共享空间中的多 Agent 截止时间与无碰撞规划；IJCAI 2018。
- MultiAgentBench：协作与竞争的多 Agent benchmark；ACL 2025。
- HearthNet：OpenClaw＋Home Assistant 的家庭多 Agent 控制、状态新鲜度和恢复；CAIS 2026 Demo Track。

因此，以下内容单独作为贡献都不够：快慢 Agent 分工、缓存、预编排、DAG 并行、前后置条件、过期计划拒绝、优先级调度。

## 值得验证的增量

最有希望的差异是：已有方案多在计划失效后进行全局重规划；本项目研究在截止时间有限、部分动作已经执行且多个 Agent 互相干扰时，如何联合决定修复范围和思考预算。

可检验假设：

> 在持续到达的任务流中，固定周期重规划或失效后的全局重规划会造成不必要的延迟和重复动作；根据任务截止时间、计划受影响范围、状态版本和修复成功概率选择复用／局部修复／全局重规划，可以提高按时正确成功率并减少 LLM 调用。

这是待验证假设，不是已确认学术空白。

## 不应过度声称的内容

- SimuHome 的 episode 完成时间不是首次物理动作延迟；其 GPT-5.1 的最难任务超过 100 秒，但不能直接当作家庭设备响应时间。
- HomeBench 的某些 0% 是“一条请求中全部操作正确”的严格成功率；其 ICL 结果明显高于 0%。
- 项目文档中的 `<1 秒`、`<100 ms`、`<1 ms` 是目标或设计值，不是实测结果。
- LLM 的自报置信度不能直接当作校准成功概率。
- 不能仅凭论文题目或场景断言一定能中顶会。
