# 公开住宅传感器轨迹试点：门窗—供暖共现

日期：2026-09-28。状态：单住宅单分片的数据来源与轨迹抽取试点；未进入正式 benchmark，不是 Agent 协调实验，也没有证明任何策略的因果效果。

## 这轮的结果

找到并完整扫描了一份公开的、实测的宿舍单元数据文件。它记录门窗接触传感器、室内空气质量和温度、室外天气以及电路功率。这个来源适合给 HomeCoord-Bench 的 C2（通风—供暖）场景提供**真实观测状态和背景轨迹**，比纯手工设数更有物理上下文；但没有住户任务、Agent 提案、设备控制命令或命令回执，因此不能直接作为多 Agent 冲突 episode 或动作效果的真值。

## 来源与可复核性

- Pandey, P. R., Liu, Y., Wilson, N. et al. “Dataset on occupant behavior, indoor environment, and energy use before and after dormitory retrofit.” *Scientific Data* 12, 798 (2025), published 15 May 2025. [论文](https://doi.org/10.1038/s41597-025-05166-7)
- 数据集：“A Two-Year Comprehensive Dataset on Occupant Behavior, Indoor Environmental Quality, and Energy Use Before and After Dormitory Retrofits.” [Figshare 条目](https://doi.org/10.6084/m9.figshare.27155988)，数据许可 CC BY 4.0（再分发需署名）。论文说明共 16 个宿舍单元，改造前、后各有单独文件；本轮只取改造前目录的一个匿名单元分片。
- 文件：`All_Files_Combined_341_1.csv`，Figshare file ID `49643052`，原文件 148,106,757 字节；SHA-256：`99b3f9496e9f37582a8d244bca34de1f4748d83a9e144432313e10055f0d056e`。
- 全量扫描 455,397 个可解析分钟记录，时间从 2021-08-02 14:17 到 2022-06-14 21:13；其中 455,395 个相邻间隔为 60 秒，另有一个 3,660 秒间隔（约 61 分钟），不应把它误当成连续分钟序列。
- 公开表中 `Window_1_1` 有 264 次可观测状态转变，另外两扇窗分别有 20、16 次。按“任一有观测的窗状态为开，且客厅电暖器功率超过 0.1 kW”筛查到 1,127 个分钟 bin；这是一个匿名单元、改造前的一份长时序，不是 1,127 个独立事件或家庭样本。0.1 kW 只是本次排除近零功率读数的分析阈值，不是设备安全阈值。窗状态缺失的分钟不会被当成“关闭”。

论文给出的原始采样语义很重要：门窗传感器底层事件有秒级时间，但共享 CSV 将它规整到分钟，并把“一分钟内任何时刻曾开窗”记为该分钟开窗；室内 CO₂、温度、湿度等原始为 5 分钟采样，再线性插值到分钟；电路功率原本为分钟采样。因此，本试点能支撑分钟级真实背景轨迹，不能用于验证 1 秒响应，也不能把相邻插值后的 CO₂/温度行当成独立测量。

## 抽出的代表性观测窗口

用预先写入提取脚本的筛选条件，找到 4 个候选开窗窗口；筛选要求：目标窗前 15 个有效分钟 bin 均关闭、随后从 0 变为 1；前 5 分钟至少 4 个功率读数高于 0.1 kW，开窗 bin 本身也高于 0.1 kW；室外温度低于室内温度；主入口门关闭；30 分钟上下文中没有其他**可观测到的**门窗状态转变。按开窗前 CO₂ 均值由高到低选出最多 3 条，数据与筛选规则保存在派生 JSON 中。

第一条代表性窗口在文件时间 `2022-02-14 06:32`：

| 观测项 | 开窗分钟 bin 附近的记录 |
|---|---:|
| `Window_1_1` | 06:31 为关；06:32、06:33、06:34 为开；06:35 起为关 |
| 主入口门 `Door_1_1` | 关闭 |
| 室外温度 | −12.49°C |
| 室内温度 | 约 21.76°C（5 分钟原始传感器读数经插值） |
| 室内 CO₂ | 约 1,619 ppm（同为插值分钟值） |
| 客厅电暖器功率 | 2.305 kW（约一分钟采样） |

这说明在这个真实记录窗口里，开窗与电暖器运行、较高 CO₂ 和寒冷室外环境共现，足以作为 C2 场景的真实状态背景。它**没有**证明开窗导致了 CO₂ 或温度变化，也没有说明住户意图、目标截止时间，或 Agent 应该关闭电暖器。比如，开窗前 5 分钟 CO₂ 均值为 1,626.674 ppm，随后 5 分钟为 1,614.174 ppm；传感器插值、占用变化、门窗其他状态和未观测因素都可能影响这一差异，不能把它解释为开窗的因果效应。

## 数据质量与适用边界

在该分片中，客厅电暖器功率约 7.39% 缺失，室外温度约 4.72% 缺失；三个窗状态各约 14.27% 缺失，主入口和另外两扇门状态约 4.47% 缺失。`Door_2_2` 约 74.41% 缺失。因而“上下文里没有其他状态变化”仅指其他有读数的传感器，不能保证所有门窗均未变化。数据来自美国大学宿舍的改造前建筑，论文称改造前采用电踢脚线供暖、没有制冷系统；它不能代表中国普通家庭的设备品牌、控制接口、房屋结构或使用频率。

建议将数据来源明确分成三层：

1. **测量层**：保留本数据中的实测状态、环境、天气及功率窗口，记录来源文件 ID、版本、许可、缺失率和采样语义。
2. **任务层**：可以围绕真实状态生成用户目标和异步 Agent 提案，但这些任务、冲突标签、截止时间与动作必须标为研究者设计或合成，不能声称是原数据中的住户请求。
3. **结果层**：如果策略动作会改变温度、CO₂ 或能耗，必须由经过验证的模拟器或真实设备实验给出反事实结果；不能直接拿该条被动观测轨迹当作“若协调/不协调执行会怎样”的标签。

因此，本轮使 C2 有了一个可信的**实测背景样例**，但不足以单独证明协调能改善舒适度、空气质量或能耗，更不能证明冲突频率。下一步可按同一筛选协议抽查第二个匿名单元，验证这种状态共现不是单个房间偶例；在做物理效果比较前，仍需明确使用的模拟器/模型能否复现该数据中的温度和功率轨迹，并把测量数据与合成动作后果分开保存。
