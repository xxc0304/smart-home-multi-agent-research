## 2026-09-27 HomeCoord-Bench 虚拟环境与试点状态

离散事件原型将任务发布、异步提案返回、外部状态变化、设备动作启动和完成反馈放在同一虚拟时间线上。离线主套件通过 107 项测试，运行 674 次仿真／离线回放，未调用模型 API。它覆盖协调逻辑和评测流程，不代表真实网络并发或真实设备性能。

SimuHome HVAC 适配试点共 21 条轨迹，结构审计 21/21 有效，7/7 个重复组一致；没有模型 API 和真实设备。HomeCoord 固定提案的两批 SimuHome 回放各含 12 条轨迹，均通过结构审计，但只有 1/4 个重复组逐状态完全一致。温度目标在 HomeCoord 中即时写入，在 SimuHome 中随时间演化；不可合并两边的成功率，SimuHome 也未接入异步多 Agent 调度。详情见 docs/SIMUHOME_HVAC_RUNTIME_PILOT_2026-09-27.md 与 docs/HOMECOORD_HVAC_PAIR_SIMUHOME_REPLAY_2026-09-27.md。

C4 边界试验覆盖 HC-M16–M20、四种策略、300／400／600 ms 三档合成提案延迟和三次重复，共 180 次运行；60/60 个重复组确定性一致。它分别报告启动前过期拒绝、在途前置条件失效和在途安全状态转坏。300 ms 下普通三种策略各有 15/15 次在途前置条件失效和安全状态转坏，DeadlineAware 为 3/15；400／600 ms 下各策略均在启动前拒绝 15/15 个过期主动作，但任务服务率下降。当前 C4 冲突数仍只计实际执行的 stale action。报告见 docs/C4_TIMING_BOUNDARY_PILOT_2026-09-27.md。

外部目标审计显示，当前 34 条 episode 中有 4 条（HC-M17–M20）会在没有 Agent 动作时由外部事件满足全部目标。后续结果必须区分最终环境目标、必要动作服务和过程安全。依据首轮语义复核，为 HC-M01、HC-M11、HC-M16 生成了 9 条隔离修订草稿；本地确定性试跑可区分冲突臂与匹配控制，但物理参数未校准，HC-M16 未实现取消／补偿，也未通过领域双审。草稿报告见 docs/REPRESENTATIVE_TASK_REVISION_SPEC_2026-09-27.md。

## 研究假设

H1：环境变化和 Agent 间干扰会使“最终状态正确率”高估真实可部署性；加入按时和过程安全指标后，方法排序会发生变化。

H2：固定周期全局重规划在低干扰任务上浪费推理，在高干扰任务上又可能来不及完成；事件触发的选择性修复可以在相同模型预算下提高按时成功率。

H3：只检查同一设备的冲突会漏掉通过共享环境变量产生的间接冲突，例如加湿／除湿同时作用于湿度；使用语义资源 footprint 后，错误并发会减少。

H4：把慢 LLM 从首次物理动作的关键路径移出，配合预授权本地策略，可以改善 P95/P99 首次有效动作延迟；它不能保证任意陌生自然语言请求都在 1 秒内正确完成。

H5：在满足风险硬约束的前提下，基于预测命中概率、剩余截止时间、状态新鲜度和修复成本动态选择 speculation 分支数，可以减少端到端等待；预测失配后的局部修复比全局重规划具有更高的按时成功率和更低的重复动作开销。

## 形式化对象

每个任务 (i) 至少记录：释放时间 (r_i)、截止时间 (d_i)、优先级、目标、前置条件、后置条件、资源读写集合、可取消／可补偿属性、预计执行和验证时间。

每个正在执行的计划还记录：产生时的状态版本、依赖的设备和环境变量、已完成动作、在途动作、租约或权限版本、可接受的状态漂移范围。

每个 speculative 结果还应记录：预测动作和参数、预期状态变化、命中置信度、风险等级、可逆／可补偿属性、资源集合和过期时间。可以使用以下收益判据选择是否预测：

\[
U(a)=p_{hit}\Delta L-(1-p_{hit})(C_{spec}+C_{repair})-\lambda R(a)-\mu X(a)
\]

只有收益为正、风险门控通过且动作仍在有效时间内时才允许提交预测结果。高风险不可逆动作可以预取参数、查询状态或进行干运行，但不能提前产生真实物理副作用。

运行时在复用、局部修复和全局重规划之间选择。选择目标可以写为：

\[
m^*=\arg\max_m P(\text{在 }d_i\text{ 前正确达成目标}\mid s_t,\text{在途动作},\text{剩余时间},m)
\]

候选动作必须先通过权限、安全不变量、资源冲突和状态版本检查。概率估计应由带真实耗时标签的历史轨迹校准，不能直接使用 LLM 自报置信度。

## 环境与任务

第一阶段基于 SimuHome 或等价 Home Assistant 测试床，增加：

- 连续任务到达和不同优先级；

每条轨迹在模型思考时继续推进环境，不能冻结世界等待 LLM 返回。

## 必须比较的基线

1. Home Assistant 规则＋确定性 Skill＋优先级／最早截止时间调度。
2. 单主 Agent＋确定性执行器。
3. 固定快／慢模型路由＋相同缓存和安全检查。
4. 事件触发全局重规划。
5. LLMCompiler／Agent JIT 风格的计划并行执行适配。
6. 选择性修复方法的消融：去掉状态版本、去掉局部修复、去掉截止时间、改为固定阈值。
7. HomeSpec 消融：无 speculation、固定分支数、置信度感知分支数、风险感知 speculation、风险感知 speculation＋局部修复。

所有方法应使用相同模型、设备信息、工具权限和总预算，避免把额外的安全检查误算成算法增益。

## 指标

- 首次有效物理动作延迟：中位数、P95、P99；
- 按时任务成功率；
- 最终任务成功率；
- 资源／互斥冲突率、过程安全违反率；
- 计划过期率和状态版本拒绝率；
- 重规划次数、局部修复范围、LLM 调用次数和成本；
- 不可行请求的正确拒绝率；
- 低优先级任务的饥饿时间。
- 预测命中率、状态过期提交率、预测分支浪费率；
- 预测失配后的局部修复范围、全局重规划比例和补偿动作次数。

紧急事件应单独报告“事件检测时间”和“预授权动作时间”，不得与普通复杂请求混为一个平均延迟。

## 近期四周验证门槛

第一周：建立单主 Agent、确定性执行器和分段延迟日志。

第二周：实现强规则基线，测量其在现有项目场景中的覆盖率和失败边界。

第三周：加入任务插入、状态漂移、资源互斥和跨 Agent 干扰，比较全局重规划、固定周期重规划和局部修复。

第四周：加入剩余时间选择器，在不同模型、负载和家庭配置上做重复实验，报告置信区间和失败案例。

如果强规则基线已解决所有 MVP 场景，应把研究集中到它解决不了的动态组合任务，而不是仅增加更多家电名称。
