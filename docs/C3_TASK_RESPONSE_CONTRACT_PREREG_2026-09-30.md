# C3 公平信息与逐任务响应：运行前方案

本步不增加任务或模型提案；固定既有三组 DeepSeek 提案，在 54 个条件中复评七种发布信息策略（378 次），另外对晚到任务条件复评完美预告诊断（18 次），共 396 次。输入哈希写入机器清单后执行。属于已见过现象后的指标完善，不是新的独立验证样本。

相同信息组可以使用已发布任务元数据、工具公开的服务时长／功率、已返回提案和当前预约／执行状态。精确未来预告单列，不参加同信息优劣排名。审计快照只核查信息投影；它不是隔离控制器读取的沙箱。现有删除未来任务测试用于检查已发布可行性策略的前缀行为是否改变，不能保证所有策略完全没有未来读取。

新增指标均从任务自身发布时间计时：首个正确动作启动等待、实际完成耗时、超过绝对截止时间的完成迟延，以及未启动／未完成数。缺失值为 null，不能作为零等待；1 秒内启动仅作示例阈值，不是实际物理服务承诺。正确动作按 required_action 已声明字段匹配；当前 C3 只声明设备与操作，不泛称覆盖所有参数语义。

每次复评核对旧的首动作时间、任务服务、期限及最终目标指标；任何变化均中止。记录已接受的未来预约和运行中的动作，保留同一虚拟时刻的原事件顺序。仅保存预先选定紧期限／晚发布／高压力的九组完整快照。汇总等待和缺失，不从三个结构估计 P95／P99。

不新增 API 调用；固定提案反事实回放不等同于模型在每个条件重新思考。功率、时长、期限、服务语义仍是合成条件。实际协调计算成本尚未计入虚拟响应时间。
