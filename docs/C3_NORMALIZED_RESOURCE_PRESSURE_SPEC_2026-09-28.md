# C3 归一化资源压力数据规范

日期：2026-09-28。状态：第一批正式候选的配对设计；仍是合成机制子集，尚未完成独立审核。

## 解决的问题

此前 C3 直接写“家庭容量为3.5、5.8、6.0或7.2 kW”，容易让人误以为这些值来自某个真实家庭、断路器或供电合同。现有资料不能支持这种解释，而且不同国家、住房和能源管理系统的容量也难以统一。

新版将容量定义为实验环境中的**共享可管理功率预算**，并使用无量纲压力指标：

`资源压力 ρ = 同时请求的名义总功率 / 共享功率预算`

这个定义直接回答调度问题：ρ<1 时所有任务可同时执行；ρ=1 是边界；ρ>1 时至少需要等待、排序或拒绝。它可以泛化到家庭功率、算力、带宽或设备并发槽位，不依赖某一种住宅供电标准。

## 冻结的第一批条件

三个任务及其名义总负载固定为5.7 kW，任务文字、Agent、工具、周期、期限和提案保持相同，只改变共享预算。

| 条件 | ρ | 共享预算 | 用途 |
|---|---:|---:|---|
| 明显有余量 | 0.8 | 7.125 kW | 检查协调器是否无谓等待 |
| 精确边界 | 1.0 | 5.7 kW | 检查浮点边界和保守策略 |
| 中度超载 | 1.2 | 4.75 kW | 检查排序、部分并行和期限取舍 |
| 严重超载 | 约1.63 | 3.5 kW | 保留此前三负载压力场景，作为更强诊断条件 |

每个单任务功率都低于所有条件的共享预算，所以 C3 来自并发组合，而不是某台设备本身不可执行。

## 可以支持的结论

该批次可以比较资源压力变化对冲突、安全门控、必要任务服务、期限成功率和首动作时延的影响。因为只有容量因素变化，它也适合检验“何时协调最值得”：ρ明显低于1时应快速放行，ρ超过1时才需要付出协调开销。

该批次不能估计普通家庭容量、设备使用频率或现实冲突概率。当前设备功率、固定周期和期限仍是公开的合成任务假设；它们需要设备轨迹或独立审核才能进入物理部署结论。

## 对现有试验的处理

旧3.5/5.8 kW结果继续作为历史探索记录，不重新解释为真实家庭容量。新批次加入0.8、1.0和1.2三个预先声明的压力层级，后续所有基线在相同提案上配对回放。若使用真实设备配置，可把其功率和容量换算为ρ并作为单独的外部验证集，而不与合成压力条件混算现实发生率。

## 首轮保存提案回放

复用已有5组 DeepSeek 三Agent提案与调用耗时，在4个压力条件和5种策略上完成100次离线回放，没有新增API调用。

- ρ=0.8和1.0时，所有策略均5/5完成服务并按时；始终等齐提案的期限策略首动作中位数为1437 ms，其余主要策略为1153 ms，出现约284 ms无收益等待。
- ρ=1.2时，独立执行和设备锁因共同安全门控拒绝任务，均为0/5全部服务；先到先安排的容量规则与容量感知期限规则均只有3/5全部按时；始终等齐提案后按期限排序为5/5。
- ρ约1.63时，容量感知期限规则和始终等待期限规则均为5/5全部按时，但前者首动作中位数1309 ms，低于后者1437 ms。

ρ=1.2的两次容量感知规则失败都发生在模型提案到达顺序为烘衣、洗碗、做饭时。规则先启动2.5 kW烘衣和1.2 kW洗碗，两者合计3.7 kW，虽然没有超过4.75 kW预算，却只剩1.05 kW，导致随后到达、30分钟截止的2.0 kW做饭任务等待到85分钟左右才完成。规则知道任务功率与期限，仍没有正确保留未来容量。

这表明评测问题已经超出“能否用规则消除容量冲突”：真正问题是提案异步到达且压力状态变化时，协调器应何时等待未来信息、何时立即放行。当前结果来自一个合成任务模板，不能直接证明需要新算法；但它已经形成可供后续跨模板验证的清晰机制假设。
