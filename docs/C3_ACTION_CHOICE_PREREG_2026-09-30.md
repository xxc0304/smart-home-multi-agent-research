# C3 多动作需求配对试验：运行前方案

日期：2026-09-30。本文件在本批可行性检查、离线回放、模型采样前写入。定位为受控语义选择试验。继承前瞻候选 P1/P2 两个既有三 Agent 排程结构，每个结构构造 A/B 两组相反需求，合计四个需求配置；这些配置不是四个新家庭或四个独立排程结构。

## 本次要验证的内容

上批每个 Agent 只有一个可用动作，模型提案正确性几乎没有选择难度。本批每位 Agent 看到两个服务预设和关闭动作，根据自然语言需求选择。A/B 保持同一工具目录、工具顺序、负载、周期、期限和发布时间，仅改变所请求服务及相应的隐藏评估目标。例如洗碗 Agent 分别收到普通清洗和卫生处理请求，工具固定提供两项服务。工具操作名为 `preset_1/2`，用户需求不会直接指定操作名。

两个服务预设的资源成本刻意设为相同，以隔离“语义选错”与“资源成本变了”。40/60 度供水、升温/降温、清洗/卫生处理、烘焙/烧烤均为**模拟接口声明的分类服务结果**；本轮没有对应温度动力学或杀菌模型，不能推断真实物理效果。动作效果固定依操作改变服务状态，不能依据当前评分答案动态判定效果。

增加 `GateRetryRule`：提案到达即尝试，被共同安全门控拒绝后，在资源释放时重试相同提案。另四策略为独立执行、约束协调、等齐期限调度、容量感知期限调度。该规则用于检查“安全门控后没有重试”是否解释了前批服务损失，防止夸大复杂协调的收益。

## 固定实验单元

- 四需求配置 × 三容量档（0.8/1.2/1.6）× 六提案返回顺序 × 五策略：360 个正确提案离线单元。
- 每配置在宽松容量下，逐个任务注入一次错误预设或关闭动作，其余任务仍正确，每种策略都运行：120 个语义负控制。预期错误动作可以是合法、安全的工具动作，但不能算作对应需求得到服务。
- 模型采样子集预先固定为全部四需求配置，各一批三 Agent 并发 DeepSeek 调用：计划 12 个专业 Agent 请求。实际提案及并发完成时延共享回放到三档、五策略：若完整采样则有 60 个配对回放单元。每配置一批只能作试点，不作稳定概率估计。

输入由 [`probe_c3_action_choice_20260930.py`](../homecoord_bench/probe_c3_action_choice_20260930.py) 生成，在 `revision_drafts/20260930_c3_action_choice/manifest.json` 记录哈希。先生成并锁定文件，再审计全部请求：禁止泄漏容量压力、其他任务、全局目标或 `required_action/action_template`；不同容量档的模型请求须完全相同。再检查理想排程可行性，不可行档完整报告，不按策略结果调期限。

## 分析口径

先报告工具合法率、语义选择正确率，再报告全部任务服务、全部期限满足、最终服务目标满足及首次安全动作时延。错误动作虽安全，也不能据此称任务成功或系统更快。正确提案回放只检验排程，不检验自然语言理解。语义负控制用于验证评分能识别“安全但做错事”；其失败不能称为模型自身观察到的局限。每个配置只有三位 Agent 和简单工具目录，即使模型 12/12 正确，也仅表明接口和需求配对试点可运行。

所有负控制、规则基线胜出、模型失败及不符合预期的结果均保留；不按结果换模型任务。本批继续本地保存。
