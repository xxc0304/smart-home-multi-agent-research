# HomeCoord-Bench 证据链地基复核

2026-09-26。此文档记录修正执行语义后的**小规模、未双审、合成设备**结果，不是论文实验结论。保留旧结果文件，不覆盖历史统计。

## 本轮完成的修正

1. 所有架构在动作落地前检查 `requires`，不再仅在状态版本变旧时检查；独立 Agent 可以被设备前提挡住，但不会自动获得协调器的事件唤醒与重试。
2. 协调器不再读取尚未到达的模型提案。它依据已接受动作与当前政策约束做在线决策；若先前动作已经落地，不能事后凭更高优先级撤销。
3. 评测器将已执行动作的未满足前提单独计数，并判为过程无效，即使动作基于当前状态版本。
4. 补充对应的因果信息边界与执行前提测试。
5. 后续输入审计又发现模型请求曾包含 `required_action` 与 `action_template`，即评测答案／脚本动作模板。现已从真实模型请求中移除，仅确定性脚本可显式读取模板；局部信息条件也不再泄漏全局家庭目标。修正后全套 **55 项测试通过**。

这使 `IndependentMultiAgent`、`RuleCoordinator`、`ConstraintCoordinator` 的含义更接近可部署执行。**旧结果与新结果不能直接混报**。

## 复核结果

| 材料 | 修正后观察 | 含义 |
| --- | --- | --- |
| 20 条合成候选任务，确定性提案 | 强规则 20/20 过程有效；独立 Agent 4/20 过程有效（旧统计 0/20） | 旧执行器高估部分失败；强规则仍表现强，但这是按已定义规则的功能检查 |
| 10 条匹配无冲突对照，确定性提案 | 独立 Agent 10/10 有效；强规则没有模拟额外时延或服务损失 | 现有模拟时钟仍未测得“无冲突也被过度协调”的证据 |
| 保存的 DeepSeek 提案，5 条可回放原任务 | 4 条独立执行有 C2/C3 冲突，在线强规则均消除；目标首次满足分别推迟 762、1831、3703、5932 ms（中位 2767 ms），首个有效动作时间均不变 | 支持合成任务中的“避免重叠需要等待”；不等于实测设备或协调计算时延 |
| 保存的 DeepSeek 提案，6 条无冲突对照 | 5/6 双方有效且强规则增量为零；HC-M12 对照双方均失败 | 原先的 6/6 有效结论不成立。HC-M12 模型要求“衣服已洗好”才烘干，但其烘干提案到达时前提不成立 |

原任务 HC-M06 的模型动作仍无法由该任务的能力表落地，未计入五条可回放原任务。HC-M08 仅得到一个动作，不产生双 Agent 冲突。这些不能写成规则收益。

**模型输入限制：**上述保存的 DeepSeek 提案来自修正前的通用请求，模型当时可见评测用 `required_action`／`action_template`。同提案重放仍可检查“给定这些提案时，执行与协调会怎样”，却不能当作模型在盲测任务上的提案质量或冲突发生率。前一轮单独设计的“信息边界”试验主动去掉了这些字段，因此不受此项答案泄漏影响。

## 数据就绪度

自动检查 20 条候选任务：20/20 未双审；20/20 时长与功率仍是合成范围；20/20 没有任务截止时间，因此当前不能论证紧急任务及时性；20/20 未提供完整的可调用动作签名；5/5 跨设备环境冲突任务声明了 `environment_effects`，但现有执行器未把它们应用于环境状态；4 条任务（HC-M17–M20）仅靠外部事件就能满足家庭目标，且强规则没有首个有效动作，不能作为 Agent 协调成功的证据。自动检查是问题筛查，不代替领域专家审核。

其中，环境冲突的 C2 标签目前只由显式重叠规则决定；“开窗如何影响温度、制冷如何抵消开窗”等因果效应尚未被模拟。若将其作为智慧家庭物理冲突主证据，必须先补环境动力学或用设备／仿真数据校准。容量 C3 的功率与执行时长同样需要校准。HC-M12 还揭示任务依赖与动作到达时序需要单独设计，不能把提高容量当作必然可执行的无冲突对照。

## 研究判断与下一批实验

**目前已经可以提出可信的试验假设，但还没有完整论文证据链。** 信息边界试验表明，事实、约束与动作前提会改变真正可执行的冲突；这次复核表明，强规则在合成 C2/C3 情况下消除冲突时产生必要等待。这两环尚未在足够多、经审核、设备语义可信的任务上连起来，更没有测协调计算、状态同步或物理反馈的开销。

下一批任务先保持范围小：共享设备 C1 与容量 C3 各建立经审核的冲突／无冲突配对，逐条写明任务目标、可见信息、动作前提、设备效果、到达顺序和完成判据。C2 暂缓进入主统计，待环境效应进入模拟后再纳入。每条任务先验证“独立执行为何失败、规则怎样恢复、是否发生等待或任务放弃”；只有出现跨任务稳定取舍，再扩展模型和规模。任务截止时间可作为后续预注册的压力条件，不应为制造结果随意添加。

### 2026-09-27 后续补充

此报告撰写后，HC-M06 已有独立的连续换气／制热合成探针，显式模拟 C2 对室温、CO₂ 与耗电的共同影响。它解决了“环境效应没有执行”的建模缺口，但还未接入通用 episode runtime、未做物理校准、未通过双审。因此 C2 现在纳入 C1–C4 的代表性审核范围，仍不能并入已校准主统计；场景、可行性下界与限制见 `docs/C2_SHORT_TERM_INTEGRATION_AUDIT_2026-09-27.md`。

数据设计还需公开可调用工具的动作签名，并给每个 Agent 多于一种合理选择；现有部分任务的 `tools` 名称与标准动作 `operation` 名称并不一致。如果不修正，模型无法公平地知道如何调用设备；若只给一个标准动作，又会把任务规划简化为照抄动作。这两点应在下一批配对任务中一并处理。
