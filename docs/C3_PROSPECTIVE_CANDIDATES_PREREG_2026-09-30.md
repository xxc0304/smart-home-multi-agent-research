## 样本与受控设定

以种子 `20260930` 从固定八设备池依次抽取四组三 Agent 任务，抽取结果全部纳入，不按策略结果挑选：P1 为热泵、洗碗机、热水器；P2 为洗碗机、热水器、烤箱；P3 为电动车充电桩、热泵、水壶；P4 为水壶、洗衣机、热水器。每项服务处理的是相互独立的请求；没有洗后烘干等隐含前置关系。同种设备可跨模板重现，所以不能视为四户独立采样家庭。

每组固定三档总额定负载／共享容量比 `ρ=0.8/1.2/1.6`。各设备的额定功率、固定不可中断周期、截止时间和优先级都列在 manifest，是研究者的受控因子，不是设备实测值。只改变容量，不在不同档位改动作目标和期限。无真实设备接入；不推断家用线路的实际功率或事件发生频率。

## 检查和运行顺序

1. 对全部 12 个候选先用 `ideal_schedule` 标注是否存在**知道全部任务**的理想可行排程。该排程仅作题目诊断，不能用作在线基线。不可行档仍完整报告，不据结果改参数。
2. 审计专业 Agent 所见请求，确保没有 `ρ`、容量标签、其他任务、全局目标、标准答案字段。中心策略可读取声明的容量和负载上界；这是事先规定的信息差。
3. 用确定性有效提案，对每组的六种返回顺序（800／1000／1200 ms）、三档容量和四种策略做完整的 `4×6×3×4=288` 次配对离线回放。四策略为独立执行、约束协调、等齐当前提案的期限调度、容量感知期限调度；所有策略共用安全门控。
4. **在看离线结果前指定** P1、P2 各重复两批并发 DeepSeek 专业 Agent 提案，共计划 12 个模型请求。真实提案与并发完成时延原样记录，并配对回放至三档容量与四策略。模型请求的 episode ID 使用公开别名，不带压力档。

## 预定分析口径

主要报告每个**模板×容量档×策略**下六种顺序的全部任务服务数、全部截止满足数、首次安全动作时延中位数；另列单任务结果和门控拒绝数。模型部分以两批为重复单位，报告有效动作率、并发返回次序和配对结果；协议失败、超时及缺失也计入尝试次数。六种顺序与三档容量是同一模板的受控干预，不是新增的 72 户独立家庭。资源宽松档是负控制：若各策略都成功，等待策略的时延开销仍需报告。若强规则全部解决，保留该结果。若有题目不可行档，不能把任一策略的误期解释为方法缺陷。

本批是作者生成的内部候选，不是现实事件抽样、第三方独立留出集或正式冻结 benchmark。固定有效提案回放检验调度机制；DeepSeek 采样增加真实语言提案证据，但不等于现实设备验证。结论以四个模板为上限，不能凭 288 次回放声称统计泛化。
