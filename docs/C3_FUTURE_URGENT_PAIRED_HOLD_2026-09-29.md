# C3未来紧急任务有无插入：等待收益与代价的配对试验

日期：2026-09-29。状态：探索性反事实回放；没有新增模型API调用，不作为冻结benchmark结果。

## 设计

在厨房与早晨两个模板中，保持共享功率预算及全部非紧急任务完全相同，只改变最紧任务是否在第1分钟插入。没有插入时移除该任务及对应目标、Agent、工具、动作映射；其余任务仍在0分钟发布。每模板3批保存的并发DeepSeek提案、ρ=0.8/1.2/1.6和五种方法形成180次配对回放。设计中的ρ指**包含未来任务时**的名义压力；无插入分支的实际请求负载较低，结果文件另记录了其实际压力。

方法包括先到先预约、门控后重试、等齐当前已发布提案，以及固定等待至第2分钟。固定等待在“未来有／无紧急任务”两边使用同一个时间窗，模拟**未知未来**下必须支付的等待代价。另设“已公告条件等待”的信息上界：已知未来有任务时等至第2分钟，已知无任务时不设固定等待。这个上界通过外部提供未来是否存在的信息配置，不是一个能预测未来的算法，不能拿来与未知未来方法公平排名。

## 配对结果

两个模板各三批提案合计，表中为全部任务按时次数及首动作中位时延。未插入和插入分支的任务数不同，比较重点是同一方法在两种未来下的收益与代价。

| 名义ρ | 未来紧急任务 | 等齐当前提案 | 固定等到第2分钟 | 已公告条件等待 |
|---:|---|---|---|---|
| 0.8 | 无 | 6/6；1.19秒 | 6/6；120.10秒 | 6/6；1.19秒 |
| 0.8 | 有 | 6/6；1.19秒 | 6/6；120.10秒 | 6/6；120.10秒 |
| 1.2 | 无 | 6/6；1.19秒 | 6/6；120.10秒 | 6/6；1.19秒 |
| 1.2 | 有 | 3/6；1.19秒 | 6/6；120.10秒 | 6/6；120.10秒 |
| 1.6 | 无 | 6/6；1.19秒 | 6/6；120.10秒 | 6/6；1.19秒 |
| 1.6 | 有 | 0/6；1.19秒 | 6/6；120.10秒 | 6/6；120.10秒 |

在此固定任务集里，盲目等2分钟有助于处理晚到任务，但没有插入时比等齐当前提案多耗约119秒首动作时延。已公告上界可以避免无插入时的固定等待，说明**未来任务信息**本身会改变可达到的取舍，而不证明任何当前方法具有预测能力。

## 固定窗口敏感性

为避免仅靠“2分钟”这个人为选择，再将相同固定等待窗口扫过0、15、30、59、60、61、120秒，得到252次补充回放。资源紧张且未来任务在第60秒发布时：

| 名义ρ，未来有插入 | 等到59秒 | 等到60秒 | 等到120秒 |
|---|---:|---:|---:|
| 1.2，全部按时 | 3/6 | 6/6 | 6/6 |
| 1.6，全部按时 | 0/6 | 6/6 | 6/6 |
| 1.6，无插入时首动作中位时延 | 59.10秒 | 60.10秒 | 120.10秒 |

第60秒的跳变来自实验设定和事件队列语义：紧急任务恰在第60秒发布，任务发布先于同一时刻的等待到期事件处理，协调器因此继续等其提案。**这不是从现实数据推断出的最佳等待阈值。**在当前受控设置中，等120秒与等60秒按时率相同却更慢，说明固定窗口参数必须报告敏感性，不能只展示有利值。

## 研究含义与下一步数据设计

这个配对试验比单纯增加冲突例子更接近“何时协调值得”：在可能有未来紧急任务时，提前等待可能换取按时成功；没有插入时，同样等待是纯时延成本。但本实验把插入时间固定为第1分钟，固定等到那一刻就可轻易解题，尚不能支持提出新算法。下一批数据应在**无插入与多个插入时间**之间变化，并在训练/开发/测试划分中隔离插入时间与任务模板；同时明确预约是否提前可见。未知未来时应报告不同插入概率或风险权重下的成功率—首动作时延曲线，避免只用单一加权总分掩盖取舍。

无插入与多个插入时间的受控网格现已完成，见 `docs/C3_UNCERTAIN_ARRIVAL_GRID_2026-09-29.md`。它初步描出固定等待的成功率—时延前沿，但留出的只有到达时间，任务模板和模型提案仍共享。

所有回放沿用同时调用时保存的模型决定与完成偏移。改变发布时间后，模型没有重新观察新状态或重新计时；设备周期、期限、额定上界预约和可控性也仍有前述限制。
