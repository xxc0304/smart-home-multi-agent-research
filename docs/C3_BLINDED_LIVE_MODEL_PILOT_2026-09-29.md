# C3 动态任务盲化后的真实模型小样本

日期：2026-09-29。状态：探索性验证；每模板仅一批，不是论文主实验或独立测试集。

## 为什么补这一轮

上一轮在线信息边界审计复用了任务共同发布时的旧提案。为了检查结论是否完全依赖旧提案，本轮对“紧急任务在第 60 秒到达”的两个模板重新调用 `deepseek-flash`。两个模板的专业 Agent 原本就不接收全局 `goals`；本轮重点修正请求中带有未来到达条件的 episode / request 标识，并启用未发布目标过滤作为面向其他 Agent 架构的保护。脚本逐项断言：有插入与无插入两种情形中，同一初始任务的模型请求完全一致。紧急任务的请求仅在其发布时构造。

每个模板的初始任务同时请求，紧急任务单独请求。厨房和早晨模板分别得到 3、4 个有效提案；7/7 均提出与任务要求匹配的设备动作。实际日志有 10 次请求尝试：最初的受限网络环境造成 2 次未发出的连接失败；早晨 EV 任务有 1 次返回字段不合协议，随后重试成功。记录的有效响应加上这次格式错误响应共约 8541 输入 token、1077 输出 token。不能把“7 个有效提案”误写成“只尝试了 7 次请求”。

## 配对回放

7 个新提案在三档名义资源压力、有／无第 60 秒紧急任务和三种策略上离线复用，共 36 次回放。下表为**单次条件结果**，不是成功率估计。各策略都使用同一设备容量与安全门控；`ObservedTaskFeasibilityCoordinator` 只检查已发布任务，`RobustReserveCoordinator` 额外获知精确的可能紧急任务参数及可能到达时刻。

| 模板 | 名义压力 | 是否插入 | 只看已发布任务的排程 | 精确未来先验参考 | 安全门控重试 |
|---|---:|---|---|---|---|
| 厨房 | 0.8 | 否／是 | 均按时 | 均按时 | 均按时 |
| 厨房 | 1.2 | 否／是 | 无插入按时；插入失败 | 均按时 | 无插入按时；插入失败 |
| 厨房 | 1.6 | 否／是 | 无插入按时；插入失败 | 均按时 | 两种情形均未全部按时 |
| 早晨出发 | 0.8 | 否／是 | 均按时 | 均按时 | 均按时 |
| 早晨出发 | 1.2 | 否／是 | 均按时 | 均按时 | 两种情形均未全部按时 |
| 早晨出发 | 1.6 | 否／是 | 无插入按时；插入失败 | 均按时 | 两种情形均未全部按时 |

厨房 ρ=1.6 且无插入时，只看已发布任务的排程器首动作约 2.568 秒；精确未来先验参考规则等到约 120.100 秒。插入时，前者未完成所有任务，后者全部按时。这个方向与复用旧提案的审计一致，但**不能从两个模板各一次提案推断稳定统计规律**。

## 测量和解释边界

1. 最初的 Agent 请求已在目标和标识层面盲化，但模板、设备目录和静态家庭状态仍是研究者设计的；执行时长、功率、期限仍是受控参数。
2. 第 60 秒紧急任务的提案单独调用；这一调用并非真的等待 60 秒后观察已执行设备的反馈。专业 Agent 只观察其设备，因此当前动作选择不受其他设备状态影响，但这仍非完整在线闭环。
3. 早晨 EV 初始调用发生协议格式错误。有效的洗衣与热水提案来自原并发批次；EV 提案来自单独重试，其回放时延是单次调用耗时的近似，**不能据此分析早晨模板的真实并发返回顺序或 P95 时延**。厨房初始提案来自同一并发批次。
4. 旧提案与本轮提案均给出正确目标动作。当前差异主要测试动作的准入和排序，不足以揭示自然语言理解能力差异，也不能证明必须采用 LLM 协调算法。
5. 强先验参考获得了任务的精确未来候选类；它是信息上界，不是现实可得的普通基线。即使当前 36 次回放全部按时，也不能据此推断实际家庭部署表现。

下一步应优先冻结 Agent 可见信息、任务参数来源及更多独立任务模板，再对同信息基线做正式评估。若要研究方法创新，尤其应比较**不准确或仅粗略可得的未来先验**，但先验误差分布不能随意编造成有利于某策略的难例。
